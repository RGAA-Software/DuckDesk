# Panel 授权验证旧实现

`st_network.cpp` 为移除强制 Relay 验证前的完整源码快照，不参与构建。

旧行为：Console HTTPS 验证成功后，继续访问授权信息中的旧 Relay HTTP 端口；Relay 未部署时返回 `RELAY-0`，误判节点授权不可用。

当前行为：“验证”检查 Console 连通性；“保存”通过受安装授权码保护的设备查询 / 注册接口确认节点接入，不要求管理员浏览器会话，不将旧 Relay 健康状态作为节点授权前置条件。

后续修复：旧“保存”调用 `/api/v1/auth/control/get/authorization`，该接口已经限定管理员会话，节点只持有安装授权码会被拒绝。该调用已退出节点保存流程，管理员接口权限不变。设备查询仅在明确 `DeviceNotFound` 时允许注册；授权错误、网络故障和其他业务错误立即返回并显示具体错误。

2026-09-10 真实接口检查：`/ping` 有效和无效授权码都返回 200，仅能证明连通性；受保护的设备查询，有效授权码返回 200，无效授权码返回 HTTP 401 / 业务码 604。以上未创建新设备或修改服务器权限。

本轮通过 Panel 增量构建、C++ 所有权检查和 build-tree / dist SHA-256 校验。自动重新启动 Panel 的命令被执行审查拒绝，新界面点击验收未执行；不能记作 UI 验收通过。
