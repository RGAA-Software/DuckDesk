# Pixels 软件定价方案及其思考

> 状态：商业化讨论草案，不是已批准价目表或合同条款。
> 最近更新：2026-09-20。
> 适用范围：客户自行准备并运营基础设施，Pixels 作为软件供应商提供
> 私有部署软件授权、升级、支持与可选定制服务。
> 本文价格默认未含税；正式发布前必须结合成交反馈、交付成本和法务意见复核。

## 1. 结论摘要

Pixels 首阶段不自营算力、带宽、Relay、GPU 或云主机，也不以 SaaS 账号、设备数、
客户端安装量作为主要收费单位。商业模型应保持简单：

1. 远程桌面、云游戏、云渲染办公是三个独立产品，分别购买、分别扩容。
2. 每个产品只按最大同时在线工作的 Stream 数授权。
3. 注册用户、纳管设备、客户端安装、Render/Cloud Node 和普通服务实例数量不计费。
4. 标准私有部署不另设持续性的“平台基础费”，通过每产品至少 5 Streams 的起购量
   建立最低合同金额。
5. 年度订阅包含版本升级和标准维护；永久授权首年包含维护，次年起按 20%/年续购。
6. 实施、深度集成、品牌定制和对外运营权是独立商品，不应隐含在 Stream 单价中。
7. 内部自用授权不允许客户以自己的品牌对外转售服务；对外经营必须购买
   Service Provider/OEM 商业分发权。

这一结构的核心优势不是绝对低价，而是计费口径与客户实际承载的工作负载一致：
客户可以自由增加员工、客户、终端和计算节点，只在真正增加同时运行的业务容量时
增加授权。

## 2. 业务前提与边界

### 2.1 当前商业前提

- Pixels 销售软件授权副本和交付服务，不先承担客户的云资源运营责任。
- 软件部署在客户控制的服务器、网络、存储和 GPU 环境中。
- 客户承担云主机、IDC、GPU、操作系统、数据库、带宽、公网 IP、证书及第三方软件费用。
- Pixels 提供控制面、授权服务、节点软件、客户端及相应的部署资料。
- 标准产品支持私有部署，但私有部署不自然等同于源代码交付、OEM 转售或无限定制。

### 2.2 产品拆分

| 产品 | 典型使用场景 | 定价定位 |
| --- | --- | --- |
| 远程桌面 Remote | 远程支持、远程办公、个人/团队工作站访问 | 经济型 |
| 云游戏 Cloud Gaming | 游戏上云、云电竞、互动内容运营 | 企业级高性能 |
| 云渲染办公 Cloud Rendering Workspace | 设计、剪辑、专业图形工作站、企业云桌面 | 企业级高性能 |

三个产品不应默认捆绑。远程桌面的用户往往不需要游戏调度或专业图形工作流；强制捆绑
会抬高入门价格，也会让价值表达失真。

### 2.3 Stream 的商业定义

一个正在传输交互画面并占用产品运行能力的活动工作会话，计为一个 Stream。

- 只检查同一时刻的峰值，不累计连接次数、在线时长或月流量。
- 一个用户可以在不同时间使用多个设备，不因此增加固定授权。
- 一个设备可以被多个用户在不同时间访问，不因此增加固定授权。
- 同一时间两个独立活动画面会话原则上计为两个 Stream。
- 每个产品拥有自己的 Stream 池，默认不能跨产品混用。
- 监控、管理 API、节点心跳和未承载画面的控制连接不应被误计为 Stream。

本文只确定价格口径，不设计许可证的绑定、验证、在线检查或技术管控方式。

公开事实示例：

- RustDesk 明确其公开价格适用于自托管而非 SaaS。基础版为 $23.88/月；定制版在

- AnyDesk Standard 以一个并发连接为起点，新增连接公开价为 $29.90/月；Standard
  已包含品牌客户端，真正支持云端或本地部署的 Ultimate 采用询价。
- TeamViewer 公开说明采用年度订阅；并发连接也称为 channel。企业 Tensor 使用完全

- Splashtop Remote Access 按用户收费，SOS 则按并发技术人员收费，企业版采用定制报价。
- Parsec Teams 为 $30/用户/月，Enterprise 为 $45/用户/月，包含不同等级的管理、

- ToDesk 团队专业版、游戏/设计版和性能版公开年价分别为 ¥799、¥999 和 ¥1,899，

- 向日葵行业版公开价为 ¥2,880/通道/年，页面说明包含 Windows、Android 客户端的
  功能与 VI 定制；更完整的企业+、SDK/API 和私有化方案需商务询价。

### 3.2 “基础软件费”在市场中的真实形态

厂商未必在报价单中使用“基础软件费”这个名称，但通常通过以下方式建立最低收入：

1. 必须先购买 Business、Standard、Enterprise 等套餐。
2. 套餐先包含一部分用户、设备或并发，再按增量收费。
3. 私有部署和企业版不公开价格，由商务报价设置最低合同额。
4. OEM、SDK、SSO、集成和高级支持只在高档套餐或附加包中提供。

因此，“其他厂商没有单独写基础费”不等于没有最低软件费用。多数厂商只是把它包装
成最低套餐、基础连接、企业版准入或年度最低消费。

### 3.3 竞品价格不能机械照搬的原因

- ToDesk、向日葵等公开零售价格可能包含共享平台和网络节点，规模经济不同。
- Parsec 按命名用户收费，一名用户通常对应较高的持续使用概率；Pixels 按并发池收费，
  客户可以让更多用户轮换使用同一容量。
- AnyDesk、TeamViewer 同时限制用户、设备和并发；Pixels 放开前两项，单个 Stream 的
  价值不能只与竞品的单账号价格比较。
- 云游戏和云渲染涉及 GPU 调度、高帧率、外设、图形质量和企业集成，其价值高于普通
  远程协助，不应套用低价远控会员价格。
- 自建基础设施减少了 Pixels 的云成本，却增加了部署差异、兼容性和技术支持成本。

## 4. 基础软件费用的选择

### 4.1 建议：标准产品不另收持续性平台费

标准内部使用授权采用“Stream 单价 × 授权数量”，服务端组件随授权提供。通过每产品
至少 5 Streams 起购，代替一项难以解释的年度平台费。

理由：

- 官网可以清晰承诺“只按最大并发 Stream 授权”。
- 销售不需要同时解释平台费、账号费、设备费和节点费。
- 客户扩容设备和节点时没有被重复收费的感受。
- 最低 5 Streams 已经形成最低订单金额，可覆盖基本商务和授权管理成本。

### 4.2 独立生产部署分别计费

- 一套独立生产部署是一个单独的报价单元。
- 同一部署内的高可用、容灾和计算节点数量不增加软件价格。
- 第二套及更多独立生产部署分别选择产品和 Stream 数量，并分别计算软件价格。
- 多套部署可以由销售根据总项目规模给予项目折扣，但官网不公开或自动计算该折扣。
- 本文不讨论上述商业边界如何通过许可证技术实现。

### 4.3 交付实施不是基础软件费

客户自行部署时提供标准文档和安装包，不收实施费。需要 Pixels 人员参与时建议：

| 服务 | 建议价格 | 边界 |
| --- | ---: | --- |
| 标准远程实施 | ¥9,800 起/套环境 | 安装、基础配置、一次验收，不含系统改造 |
| 现场实施 | 单独报价 | 差旅、驻场和安全流程另计 |
| 环境评估/容量测试 | 按人日 | 不保证客户硬件自然达到未验证指标 |
| 迁移、目录或业务系统集成 | 项目报价 | 不属于标准安装 |

## 6. 维护与技术支持

### 6.1 为什么订阅制通常不单列维护费

年度订阅本身就是持续获得软件使用权、更新和一定支持的费用。TeamViewer 官方说明，
有效订阅包含主要更新、新功能、增强和补丁；RustDesk 也说明所有付费计划包含客户支持。
因此订阅客户再次看到“年度维护费”容易认为被重复收费。

### 6.2 年度订阅的维护规则

年度订阅价格包含：

- 授权期内的主版本和次版本升级；
- 安全修复和产品缺陷修复；
- 授权续期和标准许可证管理；
- 部署、升级和故障排查文档；
- 工作日 5×8 的邮件/工单标准支持。

报价单可列为“标准软件维护：已包含”，而不是另外增加金额。

不包含：

- 客户服务器、GPU、网络、存储、操作系统和数据库的代运维；
- 客户业务软件、驱动、第三方 SDK 或安全产品故障；
- 未经验证的特殊硬件、系统版本和定制内核适配；
- 现场服务、驻场、7×24 值守和约定恢复时间的 SLA；
- 新功能、业务流程变化和新的第三方系统集成。

### 6.3 永久授权的维护规则

建议合同口径：

1. 首次购买包含 12 个月标准维护。
2. 第二年起，年度维护费为相同 Stream 规模当前永久授权目录价的 20%。
3. 每客户每年最低维护费为 ¥9,800。
4. 维护仅针对已购买产品和功能，不自动包含新增产品。
5. 停止维护后，已取得的永久版本可继续运行，但不再提供升级和标准技术支持。
6. 恢复维护时收取当年维护费和恢复费用，历史补缴最多追溯两年；具体公式在合同模板
   中固定，不能由销售临时口头决定。

选择“当前目录价 × 20%”而不是永远按照首单折后价计算，可以避免早期促销折扣永久
压低后续维护收入。若实际招投标要求按原合同净额计算，则应同时约定每年价格调整机制。

### 6.4 支持等级

初期只承诺能够稳定履行的服务：

| 等级 | 建议范围 | 收费方式 |
| --- | --- | --- |
| 标准支持 | 工作日 5×8，工单/邮件，合理首次响应 | 订阅或维护费包含 |
| 优先支持 | 更短首次响应、远程会议、指定联系人 | 单独年度报价 |
| 关键业务 SLA | 7×24、分级响应、升级路径、服务信用 | 团队和监控能力成熟后再销售 |

不能把“尽力协助”写成没有人员和监控体系支撑的 7×24 恢复承诺。

## 7. OEM 与企业定制

“换 Logo”“企业系统集成”“拿 Pixels 对外卖服务”不是同一种 OEM，必须分别报价和授权。

### 7.1 品牌定制（White Label）

品牌定制不改变核心功能和产品所有权，通常包括：

- 软件名称、Logo、图标、颜色和启动画面；
- 默认服务地址、客户域名和关于页面；
- 安装包名称、发行信息和可配置功能显示；
- Web 门户的品牌外观；
- 客户自行提供的代码签名证书和应用商店账号。

建议：

| 品牌包 | 一次性价格 | 范围 |
| --- | ---: | --- |
| 基础品牌包 | ¥29,800 起 | Windows + Web，标准可配置项，两轮确认 |
| 全平台品牌包 | ¥69,800 起 | Windows、Linux、macOS、Android、iOS、Web |
| 额外独立发行/特殊平台 | ¥8,000–15,000/项 | 另一个品牌、渠道或特殊安装包 |

品牌定制应尽量实现为配置、主题、资源包和构建参数，而不是复制长期分叉代码。客户证书、
Apple/Google 等商店账户、上架审核和第三方 SDK 商业许可由客户承担。

### 7.2 企业集成与功能定制

典型范围包括 LDAP/AD/OIDC/SSO、客户用户和计费系统、API/Webhook、审计平台、审批流程、
专用部署脚本、特殊硬件或业务流程。

建议：

- 项目最低金额 ¥98,000 起；
- 标准研发服务 ¥4,000/人日；
- 海外项目可按 $600–900/人日估算；
- 需求、设计、开发、测试、文档、交付和项目管理都计入工作量；
- 超过 30 人日的项目先做付费需求分析，再承诺范围和总价；
- 需求变更通过变更单处理，不以“维护”名义无限追加。

### 7.3 对外运营和商业分发权

客户如果将 Pixels 包装为自己的云桌面、云游戏、云渲染或远程支持服务，并向第三方收费，
属于 Service Provider/OEM，而不是普通企业内部使用。

建议商业结构：

| 项目 | 建议价格/规则 |
| --- | --- |
| OEM 准入与首次交付费 | ¥198,000 起，一次性 |
| Stream 授权单价 | 标准企业目录价的 1.5 倍 |
| 年度最低授权消费 | ¥100,000；与实际 Stream 授权金额取较高者 |
| 二级转授权 | 默认禁止，另行签署渠道或主 OEM 协议 |
| 源代码 | 默认不包含 |

准入费覆盖专属发行、品牌构建、测试、交付和版本管理；Stream 费对应客户持续对外经营的
商业容量。只收一次性改名费却允许无限对外销售，会让 Pixels 无法分享持续价值，也难以
承担后续维护责任。

### 7.4 OEM 维护

| 类型 | 首年 | 后续年度维护建议 |
| --- | --- | --- |
| 品牌配置包 | 包含 | 定制费的 15%，最低 ¥8,000/年 |
| 涉及专属代码的定制 | 包含 | 定制开发费的 20%/年 |
| 核心产品年度订阅 | 已含核心维护 | 不重复收核心维护费 |
| 核心产品永久授权 | 首年包含 | 仍按核心授权 20%/年计算 |

OEM 维护覆盖已有定制在受支持新版本上的迁移、构建和回归。新增页面、新流程、新接口、
第三方系统变化以及客户品牌再次重做，仍应按项目或人日收费。

### 7.5 源代码与排他权

- 默认只交付安装包、部署包、配置和约定的接口资料，不交付核心源代码。
- 源代码审阅、托管（escrow）和完整源代码许可是不同权利，应分别签约。
- 如确有源代码许可需求，建议从 ¥300,000 的受限审阅/托管方案开始评估。
- 完整商业源代码许可或买断原则上不主动提供；如必须报价，不应低于 ¥1,000,000，
  并应限制产品、区域、期限、再许可和衍生作品权利。
- 排他权会阻止 Pixels 服务其他客户，不能按普通开发人日定价，应至少覆盖预计 3–5 年
  被放弃的毛利和战略机会。

## 8. 推荐报价结构

一份标准报价应分行展示，避免客户把所有服务误解为永久免费：

1. **软件授权**：产品、模式（年度/永久）、Stream 数量、部署身份和授权期限。
2. **标准实施**：自行部署则为 0；需要协助则单列。
3. **软件维护**：年度订阅显示“已包含”；永久授权显示首年包含及次年费率。
4. **品牌/OEM**：说明是内部品牌使用还是对外商业分发。
5. **定制开发**：固定范围、交付物、验收标准和变更机制。
6. **第三方和基础设施**：明确由客户采购或按实报销。
7. **税费与付款计划**：按地区、合同主体和发票类型明确。

示例：20 路远程桌面年度内部使用授权，按 10–49 路的 90% 系数：

```text
软件授权：20 × ¥1,280 × 90% = ¥23,040/年
标准维护：包含
自行部署：¥0
可选远程实施：¥9,800
客户基础设施：不包含
```

示例：10 路云渲染办公永久授权：

```text
软件授权：10 × ¥6,980 × 90% = ¥62,820
首年标准维护：包含
第二年维护：按届时相同容量永久授权目录价的 20%，且不低于 ¥9,800/年
```

## 9. 应避免的定价错误

1. 一边宣传“只按 Stream”，一边在合同中追加设备、用户、节点和安装数量限制。
2. 把客户服务器故障、GPU 驱动、网络质量和第三方应用问题全部承诺为免费维护。
3. 用普通内部使用许可允许客户贴牌后无限转售。
4. 把一次性 OEM 开发费当成永久商业分发费。
5. 为赢得首单承诺不可履行的 7×24 SLA、无限定制或永久免费升级。
6. 为每位 OEM 客户复制一套长期代码分支，导致主版本无法演进。
7. 永久授权价格过低，使客户两三年内回本，而 Pixels 长期承担兼容和安全成本。
8. 用云厂商资源成本直接推导软件价格；软件价值还包含研发、调度、协议、管理、安全、
   多端兼容和持续维护。
9. 公开尚未经过成交验证的永久低价，导致后续难以上调。

## 10. 验证与调整计划

建议先用 5–10 个真实商机验证，而不是立即把全部数字写死在官网：

- 记录客户产品组合、预计 Stream、是否永久授权、部署复杂度和决策周期。
- 分别记录客户对“用户设备不限”“只按并发”“私有部署”的价值排序。
- 记录每个项目售前、实施、缺陷支持和环境排查的人时。
- 观察远程桌面 5 路起价是否过低以至无法覆盖销售支持成本。
- 观察云游戏与云渲染的价格阻力来自软件价格还是客户 GPU/带宽预算。
- 对 OEM 单独记录专属构建和回归成本，判断 15%–20% 维护是否足够。
- 每季度复核目录价和折扣，不因单个客户的特殊条件永久修改公共模型。

需要通过真实数据回答的未决问题：

1. 三个产品的最低起购量是否都保持 5 Streams。
2. 云游戏是否应高于云渲染办公，还是按实际功能成熟度调整顺序。
3. 永久授权是否公开销售，还是仅在客户明确要求时提供。
4. 优先支持的首次响应目标、价格和人员排班。
5. OEM 年度最低消费能否覆盖渠道支持、专属版本和法务成本。

## 13. 官网价格计算器设计

价格计算器只负责按照公开目录价计算预算，不负责许可证的绑定、验证、在线检查或其他
技术管控。它只计算一套生产部署，需要表达使用方式、产品、授权模式、Stream、一次性
费用和持续费用，并把内部使用与 OEM 对外经营区分开。第二套及更多生产部署直接引导
客户联系销售，不进入公开计算器。

### 13.1 计算器目标

1. 用户不联系销售也能得到标准配置的透明目录价预算。
2. 逐步解释 Stream，而不是一次展示一张复杂价目表。
3. 同时给出首年支出、后续年度支出和客户自备成本边界。
4. 只按公开目录价计算，不展示数量折扣、项目折扣或销售底价。
5. 对可以标准化的项目给出确定公式；其他项目显示起价或待评估。
6. 生成可复制、打印或随咨询表单提交的结构化配置。
7. 中英文、人民币/美元、亮色/暗色使用同一计算逻辑。

### 13.2 推荐步骤

采用 6 步向导。桌面端左侧操作、右侧固定显示实时摘要；移动端摘要折叠在步骤标题下。

#### 第一步：使用方式

- **企业内部使用**：服务本企业及被授权的员工、设备和客户支持对象。
- **服务商/OEM 对外运营**：以客户品牌向第三方销售相关服务。

OEM 首版只提供年度授权，自动加入 OEM 准入与首次交付费，并使用服务商年度最低消费。

#### 第二步：授权方式

内部使用客户选择年度订阅或永久授权，OEM 固定为年度授权。页面明确说明本次估算只
适用于一套生产部署；第二套及更多生产部署需要联系销售单独报价。

#### 第三步：选择产品和 Stream

用户可以选择远程桌面、云游戏和云渲染办公中的一个或多个产品。

- 至少选择一个产品；
- 已选产品最低为 5 Streams，未选产品为 0；
- 页面说明“50 名员工轮换使用、峰值同时 8 路，应填写 8 Streams”；
- 无论数量多少都按照目录单价计算，不显示折扣档位或折后价；
- 数量较大时仅提示“联系销售获取项目价格”。

永久授权同时显示“首年维护包含”和“第二年预计维护”。

#### 第四步：部署与交付

用户选择：

- 自行部署：¥0；
- 标准远程实施：¥9,800 起；
- 现场实施或复杂迁移：待评估。

计算器只计算交付价格，不讨论服务器拓扑或授权管控。

#### 第五步：品牌与集成

内部使用客户可以选择：

- 使用 Pixels 品牌：¥0；
- Windows + Web 基础品牌包：¥29,800 起；
- 全平台品牌包：¥69,800 起；
- 企业系统集成/功能定制：¥98,000 起，待评估。

OEM 客户显示：

- OEM 准入与首次交付：¥198,000 起；
- 计划使用的平台和品牌范围；
- 年度最低授权消费与 1.5 倍 Stream 价格规则；
- SSO、API、计费、审计及其他开发需求为待评估项。

#### 第六步：预算结果

结果页显示：

1. 使用方式、授权方式和一套生产部署的配置摘要；
2. 软件目录价小计；
3. 首年/首次费用；
4. 后续年度订阅或维护费用；
5. 品牌、OEM 和待评估项目；
6. 不包含的服务器、GPU、网络、存储、税费和第三方软件。

提供复制摘要、打印/PDF、修改配置和“联系销售获取项目价格”操作。结果注明价目表版本、
生效日期、未含税、有效期、“仅适用于一套生产部署”以及“在线测算不是正式合同报价”。

### 13.3 自动计算范围

| 项目 | 第一版处理方式 |
| --- | --- |
| 标准内部年度/永久授权 | 按目录价精确计算 |
| Stream 数量或项目折扣 | 不展示、不计算，联系销售 |
| 永久授权次年维护估算 | 精确计算并单列 |
| 自行部署/标准远程实施 | 精确计算 |
| 第二套及更多独立部署 | 不进入计算器，联系销售 |
| 基础/全平台品牌包 | 显示标准起价 |
| OEM 准入、Stream 和最低消费 | 按公开规则计算最低预算 |
| 深度集成、驻场、特殊系统 | 显示起价或待评估，不作为确定报价 |
| 客户基础设施 | 明确不包含 |

### 13.4 计算公式

设产品为 `p`，产品数量为 `q[p]`，年度单价为 `annual[p]`，永久单价为
`perpetual[p]`。计算器只计算一套生产部署，不使用折扣系数。

内部年度授权：

```text
annual_license = sum(p, annual[p] * q[p])
year_1 = annual_license + delivery + confirmed_branding
year_2 = annual_license + branding_maintenance
```

内部永久授权：

```text
perpetual_license = sum(p, perpetual[p] * q[p])
maintenance = max(perpetual_license * 20%, ¥9,800)
year_1 = perpetual_license + delivery + confirmed_branding
year_2 = maintenance + branding_maintenance
```

维护结果只能称为“按当前目录价估算的第二年维护”。

服务商/OEM 年度授权：

```text
oem_stream_value = sum(p, annual[p] * q[p]) * 1.5
oem_annual_license = max(oem_stream_value, ¥100,000)
year_1 = ¥198,000 + oem_annual_license + delivery
         + confirmed_customization
year_2 = oem_annual_license + customization_maintenance
```

人民币和美元使用独立的版本化价目表，不按实时汇率换算。金额使用最小货币单位整数。

### 13.5 结果展示原则

一次性费用和年度费用必须分开：

```text
一套生产部署软件授权       ¥xx,xxx/年
一次性交付/OEM            ¥xx,xxx
第二年预计持续费用        ¥xx,xxx/年
项目价格                  联系销售
客户自备                  服务器、GPU、网络、存储
```

页面不显示“已优惠”“折扣率”“最低可售价格”等内容。无论数量多少，自动结果都是目录价；
销售折扣只在正式报价阶段处理。结果旁固定说明：额外生产部署不在本次估算中，请联系销售。

### 13.6 前端实现结构

计算器进入当前 `/pricing` 页面或独立 `/pricing/calculator` 子页面。旧 `/price` 页面不是
新体系的实现基础，后续确认无入口依赖后再清理或重定向。

```text
src/pricing/types.ts              领域类型和结果类型
src/pricing/catalog.ts            版本化人民币/美元价目表
src/pricing/calculate.ts          无 UI、无翻译依赖的纯计算函数
src/components/pricing/
    PricingCalculator.vue
    CalculatorStepUsage.vue
    CalculatorStepLicense.vue
    CalculatorStepProducts.vue
    CalculatorStepDelivery.vue
    CalculatorStepCustomization.vue
    PricingEstimateSummary.vue
```

实施要求：

- 单价和公式只存在于 `catalog.ts` 和 `calculate.ts`；
- 中英文只翻译标签和说明，不复制数值规则；
- 价目表带 `version`、`effectiveFrom`、货币和税务说明；
- 结果返回 `lineItems`、一次性小计、年度小计、待评估项和提示；
- URL 可以保存配置，但不包含姓名、电话、邮箱等个人信息；
- 咨询表单提交配置与价目表版本，网页结果只作为非约束性预算；
- 亮色、暗色和移动布局沿用官网设计系统；
- 所有步骤支持键盘操作和清晰的错误提示。

### 13.7 测试门禁

计算内核至少覆盖：

- 0、4、5 及大数量 Streams 的输入边界；
- 三个产品分别计算；
- 年度与永久授权；
- 永久授权维护最低 ¥9,800 和超过最低值两种情况；
- OEM 的 1.5 倍和 ¥100,000 最低消费；
- 页面始终说明只计算一套生产部署，且没有添加第二套的入口；
- 一次性与持续费用不混算；
- 计算结果始终不自动应用折扣；
- 人民币和美元价目表隔离；
- 待评估项目不被计为确定价格；
- URL 恢复、中英文、主题和移动端流程。

### 13.8 推荐实施顺序

1. 冻结公开目录价和 OEM 起价。
2. 编写纯 TypeScript 计算内核和边界测试。
3. 完成 6 步交互和一套生产部署的实时目录价摘要。
4. 接入中英文、主题、URL 分享和打印样式。
5. 将配置带入现有咨询表单，不提供在线支付和自动折扣。
6. 根据真实询价数据再调整目录价和销售折扣政策。

第一版最重要的是计算可信、边界清晰和结果可解释。
