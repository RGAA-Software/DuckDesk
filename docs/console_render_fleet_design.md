当前保留既有非WebRTC数据链与Relay能力，WebRTC只允许Direct Host模式，不再存在标准模式/Coturn转发fallback。
本文批量模板、多地址等内容是总体设计；本轮先完成单一明确节点访问入口及显式端口映射，不把复杂自动探测作为前置条件。

## 1. 使用场景与最高优先级约束

产品目标是 **一台 Console 统一管理大量被控机器，每台被控机器运行自己的 Service 和按需启动的 Render**。
Console 与被控端可以分开安装；大量 Render 不意味着在一台 Console 主机上启动大量 Render。
旧固定局域网的 Console / Service / Render 同机调试环境已经退役，不能决定产品架构。

- Console 管理设备、应用、访问授权和调度；不拥有所有机器上的本地端口分配器。
- 每台机器的 Service 负责本机实例、端口资源、进程启动 / 停止和状态回报。
- Render负责对应会话的采集、编码、传输和输入；不在Render或Console部署ZLMediaKit/Coturn。
- 各机器可以使用相同的内部端口。只有共用同一公网地址 / NAT 出口时，对外端口映射需要协调避让。
- 不共用一份必须包含所有组件字段的 `network_ports.json`。共享协议中的端点类型可以统一，运行配置所有权必须分离。
- 不将任何测试节点的端口范围、应用池容量或公网 IP 写死为全产品限制。
- Native现有UDP/FEC、WebSocket、Relay等业务通道保持；Windows/Web保留Direct Host WebRTC，适用Android流程按平台实现验收。
  本设计不引入中央WebRTC signaling、STUN/TURN或隐藏回退，也不展开iOS/macOS适配。

## 2. 控制连接与会话数据连接分开

```text
                          CN：px_auth
                               ▲ 授权接入
                               │
客户端 ──登录 / 应用请求──> 单台 px_console
                               ▲
                    主动建立的受认证 WSS 控制连接
                 ┌─────────────┼─────────────┐
              Service A     Service B     Service N
                 │             │             │
             Render A1…    Render B1…    Render N1…
                 ▲             ▲             ▲
                 └────客户端按资源会话描述符连接对应 Render────┘
```

- Service 主动连接 Console，注册、心跳、接收命令并返回结果；Console 不直接调用公网暴露的 Service 本机管理口。
- Console 下达“在哪个节点启动什么实例”，目标 Service 决定本机如何启动并确认实际端点。
- 客户端凭Console返回的当前资源会话、role、lease和frontend authorization连接对应Render；不新增短期连接ticket。
- Direct Host WebRTC在Render直接端点协商并传输；Relay不交换RTC信令，产品不部署Coturn/TURN。
- ZLMediaKit媒体预览/推流退出活动产品；录像和文件传输继续使用各自受授权链路。
- 被控端能连上 Console 不代表客户端能连上 Render：控制通路和客户端数据通路分别验证。

## 3. 配置按角色独立归属

以下是配置语义，不预先冻结文件名、序列化格式或协议字段编号。

| 配置归属 | 必需内容 | 不应包含 / 不应假设 |
| --- | --- | --- |
| Console | 自身监听/对外URL、TLS、Auth地址、持久化、设备接入与调度策略、资源会话和节点实际端点 | 不使用一套全局应用端口池代替所有节点；不假设Render在127.0.0.1；不引用ZLM/Coturn |
| 被控节点 Service | Console地址、独立节点凭据、节点身份、本机管理口、桌面端口、应用端口池、实际地址/NAT映射配置 | 不要求Console监听端口、PostgreSQL、Relay或任何媒体sidecar在本机存在 |
| 单个 Render | Service 注入的实例身份、实际监听端口、本机 IPC 凭据、允许的媒体范围和会话策略 | 不独立猜 Console 全局端口，不自行声明他人设备身份，不读取 Console 数据库配置 |

批量配置可由 Console 管理模板并下发给指定节点，但模板是“期望配置”，不是立即生效的实际状态。
节点先校验、应用并回执版本；Console 同时记录期望版本、已应用版本及失败原因。
本机配置和中心模板需定义唯一优先级，不允许两个来源无版本地相互覆盖。
启动阶段加载失败必须报告错误；不能静默换用未映射端口。

### 身份与秘密

- 批量安装包只带公共程序和配置模板，不克隆已注册节点的设备身份、授权缓存或长期凭据。
- 每个节点通过受控接入流程获得独立身份 / 凭据，并绑定 Console 中的设备记录；重装与替换节点需有明确身份处理。
- 安装参数可提供 Console URL 和受限的引导凭据；不得把管理员密码作为全体节点永久连接密码。
- CN 授权签名私钥只留在 Auth。被控端不因加入同一部署而获得 Auth 私钥、Console 管理员凭据或数据库密码。
- 端点上报只接受该认证 Service 所属节点；拒绝替其他设备上报、过期会话回执或客户端直接指定任意目标。

## 4. 节点端口分配与实例生命周期

**应用端口由节点 Service 分配并确认，Console 根据回执维护实例，不预占一个全局固定端口。**

1. Console 选择已授权、可用且符合应用部署条件的节点，发送带唯一请求 ID / 实例 ID 的启动请求。
2. Service 校验身份、应用部署、当前配置和本机资源，在本机应用池内自动选择端口并进行实例预留。
3. 递增选择、跳过占用、必要时回绕复用已释放项；同时检查所需 TCP / UDP 绑定条件。
   单次端口探测不是永久保证，仍以实际 Render 成功绑定为准；绑定失败要回滚预留并有界重试。
4. Service 启动所属 Render，传入本机端口与实例凭据；确认就绪及本实例的实际端点后回执。
5. Console更新实际状态和端点版本，再向已授权客户端提供该实例的类型化资源会话描述符。
6. 停止 / 失败时按该实例归属清理；确认资源释放后回收端口。迟到回执不能覆盖更新一代实例。

约束：

- 请求重试幂等，同一个启动请求不能产生两个实例；重复停止成功，无权影响其他实例。
- 固定桌面端口与应用池分开管理，不把固定桌面 Render 当作任意应用的可复用实例。
- 如保留“首选端口”，它只是节点可校验的偏好，不改变节点最终分配权；未映射 / 被占用时明确报告结果。
- 池满表示这个节点 / 网络配置的资源不足，不表示全平台应用数达到固定限制。
- Console 重启后从节点回报恢复事实状态；Service 重启后核对已有受管实例，不能只按端口或文件路径接管外部进程。
- 节点离线时停止新调度、标记状态未知；不能立即把仍可能运行的进程端口当作空闲，也不能让旧授权指向复用后的新实例。
- 调整端口池 / 映射时，已有实例保持其已确认端点或受控排空后迁移；新配置不能直接重新编号正在使用的端口。
- RDP 工作区继续遵循现有独立设计：停止 Render / 断连不等于注销 Windows 会话或清理用户工作区。

## 5. 地址与公网映射按节点、按端点记录

不能只存一个 `listen_port` 同时代表绑定地址、局域网地址和公网地址。
也不能把 Service 连接 Console 时的源地址 / 源端口当成 Render 的公开端点。

每个节点至少需要报告或关联以下语义：

- 设备身份、Service 连接代次、配置版本、心跳新鲜度。
- 本机桌面端口、应用可分配资源与使用状态、Render直接端点配置；实际端口由实例就绪回执确认。
- 可供客户端使用的主机地址、协议和端口，以及适用的网络范围（例如同局域网或已配置公网映射）。
- 映射规则可以内外同号，也可以显式配置不同端口；不同协议的映射分开验证。
- 实例 ID、启动代次和端点版本相互绑定，避免重启、端口复用或地址变化时串连。

Console 可以校验已上报端点与该节点的受控映射策略是否一致，但不能根据地址上报授予其他节点的访问权。
客户端选择已经验证可用的允许端点；资源会话授权不能由客户端任意修改目标而扩大。
若公网映射未配置或客户端数据通道不可达，应明确报错；不擅自降级到桌面、无鉴权连接或未计划的 Native Relay。

### 同一公网 IP 下有多台节点

- 不同节点内部可以都使用 4613；其公网 `(IP, 协议, 端口)` 映射必须不同。
- NAT / 网关端口池属于该网关，不属于单台 Console 或单台 Render；应由受控网络配置协调分配。
- 节点只报告自己获配的映射，Console 验证重复占用；本设计不假称应用已具备路由器自动配置权限。
- 单节点的内外同号方案不能推广为所有节点必须满足的网络条件。

## 6. Direct Host WebRTC 的规模化部署

- 每个Render只公布本实例实际绑定并由Service确认的host/port；桌面默认4601，应用从4613–4998动态分配。
- 实际端口在同一端口号上承载所需TCP/WS和UDP；多Render的端口预留、绑定失败回滚和耗尽状态归所在节点Service管理。
- 公网/NAT部署由节点配置显式映射，Console不猜测源地址，不提供STUN/TURN或Relay媒体fallback。
- 浏览器Direct Host需要可信且匹配hostname的HTTPS/WSS边界；关闭证书校验不是产品部署方案。
- 大规模容量分别测量节点编码资源、Direct Host会话、Relay既有数据吞吐、Console控制连接和数据库压力。
- 局域网发现不是批量接入前提；节点通过配置的Console地址主动注册，不依赖全网广播。

## 7. 批量安装、升级与日常管理

1. 准备角色独立安装包：Console 管理端与 Windows 被控节点安装包分离，节点包包含 Service、Render 和必要运行依赖。
2. 批量安装节点，注入 Console 地址、受限接入材料及节点适用的网络模板；本机 Service 常驻，Render 按产品生命周期启动。
3. 完成节点注册与授权，回报硬件、版本、应用安装位置和网络配置状态；Console 中可区分在线、未就绪和不可达。
4. Console 向满足条件的节点调度应用。节点自身负责窗口 / 用户会话、GPU 和私有进程归属，不能由 Console 直接按 PID 操作远端进程。
5. 升级按节点 / 分组分批执行，先小批验证，再扩大；保留配置、身份和回滚产物。
   有会话的节点先停止接收新任务，按照明确策略排空，不擅自终止用户会话。
6. 控制连接重连采用退避和抖动，避免大量节点同时重连冲击 Console；命令有超时、回执和幂等状态对账。
7. 日志携带设备 / 实例 / 请求标识，但不记录 ticket、接入密钥、密码或签名私钥。

“大规模”是架构目标，目前不声明已完成千台 / 万台压测；单台 Console 的实际容量需以后用分阶段测试证明。

## 8. 初稿代码差距与实施顺序（历史快照）

以下是本设计初稿时的代码快照，不是当前剩余工作清单。
后续已接通节点配置、自动端口及 RTC 端口范围等部分工作；当前状态和剩余工作以最新实施计划及调试记录为准。

初稿时核对的现状：

- Service 已有与 Console 的控制连接、启动 / 停止回执和实例心跳机制，可以在现有链路扩展，不重写全部传输。
- Console 调度仍有 32000–32999 固定校验 / 建议逻辑，且节点记录中提前指定监听端口。
- Service 已有受保护的节点配置、当前节点端口/能力上报、实例分配、清单对账和命令/ACK 基础闭环；RDP workspace envelope、
  GPU 绑定、异号端点映射、部署身份校验及真实公网端到端仍未完成，不能把基础闭环当成完整节点交付。
- ticket / launch URL 直接使用 `instance.listen_port`；Render ICE 仍有 60430–60490 硬编码。
- 前一轮新增的机器专属配置草稿已经退役；Rust `network_ports.rs`、
  C++ `network_port_profile.h` 及模块导出，**不符合本设计，不作为后续实现基础或已交付能力**。
  它们尚未接入完整运行链路、构建验收或部署。后续代码任务需先归档 / 撤回草稿，再做角色独立配置；本轮仅更新文档。

实施顺序：

1. 明确角色配置、节点网络状态与实例实际端点的协议模型；定义节点身份、版本与回执规则。
2. 接通 Service 的节点配置 / 端口分配，Console 改为按目标节点资源调度并接受实际分配回执。
3. 接通资源会话描述符中的可达端点，分别验证LAN、公网同号映射和公网异号映射，不扩大授权边界。
4. 接通Direct Host WebRTC并对Relay既有非RTC数据能力做独立回归；删除ZLM/Coturn/中央RTC依赖。
5. 完成角色独立打包、无人值守安装、启动 / 停止 / 重启与升级回滚。
6. 先完成短期单节点功能验证，再增加独立公网被控节点验证；同机通过不能代替分机通过。

验收至少包括：两台不同节点复用相同内部端口、单节点并发分配无冲突、端口耗尽 / 释放复用、
控制连接断开/Console重启对账、迟到回执、错误端点拒绝、Direct Host首帧/音频/输入/撤销、Relay数据回归及新配置切换。
暂时只有一台节点时，可做单元 / 协议模拟验证，但需如实标记尚未完成真实多节点验收。
每轮功能测试继续限制在 5 分钟内；不因规模化目标擅自执行长时间压测。

具体公网连接及端点规则见 [节点连接配置](node_connection_configuration.md)。
