## 连接关系

```text
本机客户端 ──管理 / 调度──> 90：px_console ──授权──> CN：px_auth
                              ▲
                           控制连接
                              │
本机客户端 ──会话数据───> 90：Service / Render

上述 Console 与被控端角色在规模化部署时可位于不同机器。
```

- 90 上的 Console 接入 CN 的统一授权服务，按现有产品流程获取 / 校验授权。
- 本机通过 90 的 Console 进入实际渲染会话，不绕过授权、实例归属和连接 ticket 流程。
- Native 会话沿用 UDP / FEC 音视频与 WebSocket 文件等业务通道；Web 客户端仍使用 WebRTC。
- 本环境不增加 Native WebRTC、强制通道选择、公网 P2P 或 Relay。
- SSH 可达仅证明管理通道可用。部署前需要核对 90 的业务 TCP / UDP 端口、NAT 映射和防火墙，
  尤其是本机至 90 的 Native UDP 通路；尚未验证这些端口可从公网访问。

## 90 的公网端口映射规划

用户最新确认：90 的自有服务统一规划到 **4600–5999**，替代先前的 5400–5999 / 5400–5480。
这是 90 的同机部署示例，不是产品代码限制，也不是所有被控节点共享的端口池。
各节点 Service 独立自动分配端口、跳过占用项；Console 按设备记录配置和实际端点，不自行替节点决定端口。
采用内外同号映射，避免前一版 5410 → 32000 等端口偏移造成连接端点不一致。
以下仅记录映射规划，尚未修改远端 NAT、防火墙或程序配置。

### Console 管理服务及配套媒体服务

| 端口 | 协议 | 用途 | 对外映射 |
| --- | --- | --- | --- |
| 4600 | TCP | Console 管理页面、HTTPS API、WSS；客户端及被控端接入 | 是，同号 |
| 4604 | UDP | 局域网发现，本环境不依赖 | 否 |
| 4605 | TCP | 旧 Console Relay，本次不用 | 否，不启用 |
| 4606 | TCP | 同机媒体服务 API | 否 |
| 4607 | TCP | 接收同机 Render 的 RTMP 推流 | 90 同机时不对外；跨机器发布时按受信网络 / 来源策略开放 |

### 被控端：Service、Render 与 Native 远程连接

| 端口 | 协议 | 用途 | 对外映射 |
| --- | --- | --- | --- |
| 4603 | TCP / WS | px_service 本机管理和 Render 生命周期控制 | 否，绑定 loopback |
| 4601 | TCP + UDP | 固定桌面 Render | 是，同号 |
| 4613–4999 | TCP + UDP | 应用 Render 自动分配池，387 个端口槽 | 是，同号 |

每个 Render 复用同一端口号的 TCP / UDP：TCP 承载 HTTP/WS 接入、控制、文件等业务，
UDP 承载 Native 音视频。按实际 Render 实例分配，不是每增加一个客户端就占一个 Render 端口。

### 被控端的 WebRTC 支持

| 端口 | 协议 | 所属组件及用途 | 对外映射 |
| --- | --- | --- | --- |
| 5000–5299 | UDP | Render WebRTC 直连媒体池，300 个端口 | 是，同号 |
| 4602 | TCP + UDP | 配套 Coturn 的 STUN/TURN 入口 | 是，同号 |
| 5301–5999 | UDP | 配套 Coturn 的 TURN 分配池，699 个端口 | 是，同号 |

WebRTC 页面和信令复用 Console / Render 接口，不另设固定信令端口。
Coturn 是配套服务，不是每个 Render 各启动一套；仅 Web 使用，Native 不使用 TURN。
Coturn 可以和 Console 同机，也可以独立部署；4602 / 5301–5999 属于该 TURN 主机，
不要求每台被控节点安装 TURN。5000–5299 则属于 90 的 Render ICE 池，其他机器可有各自范围。

### 预留与管理

- **4608–4612：仅预留 5 个端口，不开放。** 替代此前大段预留方案。
- **5300/TCP：保留现有 SSH 映射**，不分配给业务或 ICE / TURN。
- 4600–5999 共 1400 个端口号：8 个固定服务端口、5 个预留、387 个应用端口、
  300 个 WebRTC 直连媒体端口、1 个 SSH 端口、699 个 TURN 分配端口。

应用示例：内部 4613 → 公网 4613，4614 → 4614，依次递增，跳过已使用端口并安全复用释放端口。
387 不是程序中的固定应用数量限制，只是 90 当前分配的应用端口资源；不承诺 387 个游戏并发。
WebRTC 分配 300 个直连媒体端口和 699 个 TURN relay 端口，替代先前的 61 / 39。
端口数量不等于会话并发数，仍受 ICE 分配、传输协议、TURN allocation 数和硬件容量影响。
超出部署端口池时应报告资源不足或调整配置，不能侵占 WebRTC / SSH 端口或生成无法访问的连接地址。
同一端口号的 TCP 和 UDP 是两种独立协议，需要分别建立映射。

### 映射与地址通告的已知缺口

- 当前 Console ticket / launch URL 直接使用 `instance.listen_port`；内外同号可避免额外端口偏移转换，
  但必须正确通告公网主机地址。
- 现有 Console / Service 仍默认限制应用范围为 32000–32999，Render ICE 仍硬编码 60430–60490。
  落地需要把应用池交给各节点 Service 配置与实际分配，Console 按设备记录上报的资源与回执，
  不再以全局固定池校验所有机器；Render 使用所在节点的 ICE 池，不把本表分段写成产品固定限制。
- Console 端口、Render 监听参数、Service 本机端口和托管 TURN 端口使用现有可配置入口。
  修改 Service 本机端口后，其本机调用方也必须同步，不得只改监听端。
- WebRTC 需要确认 ICE 实际通告公网候选地址及映射端口；静态 UDP 映射本身不能保证候选正确。
  Coturn relay 池优先使用上表的内外同号映射，避免通告错误端口。
- 上表不是已经实现的自动端口映射能力。落地前必须检查现有可配置入口；不能仅改映射表就声称跨公网验收通过。

### 不需对公网开放的端口

| 内部端口 | 协议 | 用途 |
| --- | --- | --- |
| 4603（原 20375） | TCP / WS | px_service 本机管理入口，绑定 127.0.0.1，并同步本机调用方 |
| 27017 | TCP | 同机 MongoDB |
| 6379 | TCP | 同机 Redis |
| 4604（原 30501） | UDP | Console 局域网发现广播；本环境不依赖广播发现，禁用或同步发现端配置，不做公网转发 |
| 4605（原 30502） | TCP | 旧 Console Relay；仅占位，本次不使用、不开放 |
| 4606（原 12888） | TCP / HTTP | 同机媒体服务管理 API，浏览器通过 Console 受控接口访问 |
| 4607（原 1935） | TCP / RTMP | 仅本表的 90 同机情形无需对外；分机发布需配置真实可达地址及受控入口 |
| 3389 | TCP / UDP | 若后续启用 RDP 应用模式，仅 Windows 内部会话链路，不直接暴露 |
| 动态本机端口 / IPC | 依具体模块 | Hook、用户代理及其他内部通信，不因使用动态端口而对外开放 |

媒体服务模板中的其他 RTSP / RTP / WebRTC / HTTPS 监听不自动纳入对外清单：本轮不用的协议不映射；
部署时核对真实启用项，不能把媒体模板的所有端口一并开放。
“无需公网映射”不等于实际已绑定 loopback；仍需检查防火墙和监听地址。
Console 与媒体服务若分机，媒体 API 通过受保护内部网络访问，不把“仅内部”误解为必须同机。

MongoDB、Redis、系统 RDP 属于第三方 / 系统组件，不因本次自有服务端口归类而修改默认端口。
临时出站端口和非 TCP/UDP 的命名管道不受服务监听端口段约束。
保留已有 SSH 公网 TCP 5300；SSH 实际内部目标端口沿用现有规则，不擅自改为 5300。
90 访问 CN 的 `auth.rgaa.vip:443` 是出站连接，不占 90 的入站映射端口。
本机客户端通常使用临时出站端口，不要求在本机开放同一组入站端口。
