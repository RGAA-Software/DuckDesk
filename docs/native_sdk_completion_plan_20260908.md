## 1. 本阶段的终点

Windows、Android 使用同一套可独立构建和集成的 Native SDK，公共层负责协议、会话规则和媒体任务，
平台层负责硬件资源、系统设备与应用生命周期。新增 iOS/macOS 时复用核心、补真实平台适配，不复制网络和业务规则。

本阶段完成不等于四个平台产品全部交付，也不等于全仓历史 C++ 债务清零。

- Native 固定 UDP/FEC 视频与现有 UDP 音频、WebSocket 可靠控制/文件；WS/WSS 是安全配置，不是用户可选通道。
- Web 保留既有 WebRTC，不重做浏览器 UI，不把 WebRTC 传输带回 Native。
- 不重写已完成的 UDP、FEC、文件引擎、录制引擎；不为方便抽象而改变协议、认证或文件成功语义。
- iOS/macOS 应用工程、公网 P2P/Relay、完整能力协商、发布全量构建不进入本次执行队列。
- 手机不提供新增自身屏幕的功能；选择远端已有显示器与此无关。

## 3. 目标职责与依赖

| 层 | 应负责 | 不应负责 |
|---|---|---|
| 应用/组合入口 | 页面、导航、用户授权、账号 UI、系统权限、创建和连接具体模块 | 自建传输、复制票据消费与语音协议规则 |
| SDK 会话与功能编排 | 会话尝试/取消/错误、媒体任务、输入协议、功能生命周期与状态事件 | Qt/JNI UI、设备指针、系统文件选择器 |
| 已有共享引擎 | 文件任务、编码帧录制、Opus/语音状态等已有实现 | 窗口或 Activity 生命周期 |
| SDK 网络核心 | 认证绑定、UDP 关联、分片/FEC 接收、可靠消息、背压及故障隔离 | 具体解码器、显示设备、平台权限 |
| 平台适配 | 解码/显示资源、音频设备、剪贴板、文件授权、输入映射、凭据存储 | 重新实现核心协议与连接规则 |

组合入口创建具体能力并注入。已有共享依赖不整体复制进 SDK；以明确的目标依赖复用。
不新增服务定位器、通用插件注册表、`void*` 属性袋，或为尚未实现的 Apple 后端创建空实现。
不追求单一巨型 SDK 类，也不要求 Windows UI 与 Android UI 的代码结构一致。

## 4. 执行顺序和拆分

`P1 硬件上下文 → P2 帧接口 → P3a 会话 → P3b 文件/剪贴板/录制 → P3c 语音 → P4 独立集成 → P5 验收`

按以下 10 个可独立审查的实现批次推进；是交付拆分，不是承诺 10 次对话或固定工期。

1. P1：平台参数与硬件资源。
2. P2a：CPU 帧和编码输入。
3. P2b：GPU 输出边界与显示消费者。
4. P3a：会话尝试、续票、取消和错误规则。
5. P3b-1：文件/剪贴板的共同编排。
6. P3b-2：录制生命周期与编码数据订阅。
7. P3c-1：语音共同编排与协议构造。
8. P3c-2：语音实时数据通道核对与必要迁移。
9. P4：SDK 独立配置、消费示例与接入说明。
10. P5：最终短回归、边界检查与交付文档。

如核对证明某批次已充分共享，只补边界证据/测试并关闭该批次，不为凑步骤新增抽象。
每批完成双端编译和受影响回归再进入下一批。最后一批不是此前所有测试的唯一执行时机。

## 5. P1：硬件上下文与配置隔离

### 改动

- 核对 `sdk_params.h` 所有字段消费者，将应用外观参数、平台解码偏好、硬件资源与真正会话配置分开。
  地址/认证/协议所需字段保留正确职责；不把远端采集配置误判为本地显示配置。
- Windows 工厂接收类型明确的资源持有对象；D3D11 保持 COM/现有 wrapper 所有权，Vulkan 使用 FFmpeg 引用计数的 RAII owner。
- 解决当前 Vulkan 视图晚于 SDK Init 创建的顺序：在开始视频解码前完成资源发布；必要的后续替换在指定执行线程上进行。
  不再靠可变公共参数回填借用地址，不强行在资源未创建时复制空快照。
- Windows 解码器通过平台依赖取得设备，不通过 `sdk->GetSdkParams()` 寻找硬件上下文。
- 修改 Windows Workspace、RenderView、D3D11/Vulkan 显示消费者；保留已有硬解失败后的软件回退。
- Android 继续使用已完成的 `AndroidVideoOutput`，不再引入 Surface 地址接口。

### 验收

- SDK 通用参数头不依赖 D3D11、Vulkan、Android native window 或 FFmpeg 设备结构。
- 设备引用获取失败、部分初始化失败、晚初始化、解码器先销毁/窗口先关闭均可安全清理。
- Windows 当前可用硬件路径实连出图；没有可用环境的其他后端记录为编译/单测覆盖，不声称硬件实测。
- Android 构建通过，公共配置变动不破坏启动；改动区域无新裸指针存储和异步裸捕获。

## 6. P2：帧所有权与解码输入

### P2a：CPU 帧、编码输入

- 为 CPU 帧使用确定的 owning buffer，显式描述尺寸、像素格式、各平面偏移/步长和颜色范围。
- 同步借用使用引用或 `std::span`；异步排队捕获 owner，不能把 span/string_view 当作所有者。
- 用有边界长度的输入替换项目 `Decode(const uint8_t*, int)` 交接；裸地址只在调用 FFmpeg/系统 API 的瞬间出现。
- 检查长度、平面范围、步长与大小乘法溢出，初始化失败不发布半成品帧。
- 更新 `RawImage` 工厂、Clone/CopyTo 与真实消费者；不增加无意义整帧复制。

### P2b：GPU 帧与显示

- 保留已完成的 Vulkan AVFrame 独立引用，继续用平台类型拥有 D3D11 texture/device 与 subresource 信息。
- 通用帧头不包含 Windows/Android 设备头；平台消费者通过有类型的输出边界取得对应资源。
- 明确 CPU 输出、GPU 输出与 Android 直接 Surface 输出的区别，不伪造 CPU 帧来统一外观。
- 不为每个后端重建一套媒体会话；不改 FFmpeg 第三方 ABI，不机械重写第三方代码。

### 验收

- 覆盖空/非法长度、带 padding 的图像平面、复制/共享、队列持有帧时解码器销毁、切换输出和重复关闭。
- 输出资源至少活到最后一个消费者结束，失败路径无泄漏/重复释放；GPU 路径不新增 GPU→CPU 回读。
- 公共帧 API 不再暴露项目裸指针或平台设备结构；两端显示、录制编码订阅保持原行为。

## 7. P3：共享业务规则收口

### P3a：会话与授权尝试

先追踪 Windows 的 Panel/启动授权链与 Android Kotlin/JNI 链，形成“当前持有者→规则→目标持有者”的清单。
不能只看 Workspace 就假定 Windows 拥有完整 Console 续票能力。

- 共享会话尝试的状态、attempt/generation 标识、超时、取消、错误分类及迟到结果丢弃规则。
- 将一次性票据消费、最新轮换令牌和重试需要续票的决策收敛；账号登录、HTTP 调用与安全存储仍由实际宿主能力提供。
- 用户重新启动已停止的会话时创建新的 SDK，已停止的 SDK 不复活；运行中 socket 自动重连只推进连接 generation，保留已有任务。
  UI 工作流只映射状态和用户操作，不再次实现网络状态机。
- 区分“控制连接正常”“媒体暂不可用”“文件任务状态”，不因视频失败伪造设备离线或上传成功。
- 会话对象是运行状态的权威来源；UI 有展示状态，文件和语音有各自子状态，不能互相争夺启停所有权。

验收：连续续票、过期票据、取消期间授权返回、旧连接迟到消息、占用拒绝后重试、回调内关闭、重复启停；
维持既有认证检查，不记录 ticket/nonce/renewal token，不为合并规则扩大服务端权限或改票据协议。

### P3b：文件、剪贴板与录制

- 文件继续复用 `px_ft_engine`/`FtAsyncSession`，统一真正重复的任务绑定、发送结果/背压、取消和结束映射。
  Windows 文件 UI 与 Android SAF/URI 授权分别保留；不能将 Android URI 当桌面绝对路径。
- 保持接收端完成校验/落盘后成功的语义，上传继续等待现有 Done 回执；不因抽象改回“本地 EOF 即成功”。
- 剪贴板合并共同的远端消息校验、generation/会话归属及文件任务关联；Windows OLE/虚拟文件与 Android 系统剪贴板/授权留平台。
- 录制继续复用 `px_media_record`，共同管理编码流订阅、开始/停止/失败与结束收尾；保存位置、MediaStore 和提示留宿主。
- Client clipboard/ft/record 始终是内部链接模块，不能恢复 GetInstance、DLL 加载或通用插件事件路由。

验收：文件仅可靠通道连接、传输期间离开页面、取消后迟到 Done、断线重传、剪贴板旧 generation、录制停止/断线收尾；
Windows 不同目录与 Android 实际文件校验保持一致。已有引擎不复制到新目录。

### P3c：语音单独收尾

当前拆分：消息构造已移到 `sdk_voice_protocol`，见 [协议子步骤检查点](native_sdk_voice_protocol_checkpoint_20260908.md)。
共享 `VoiceCallController` 已按每次通话创建独立 run 并接入 Windows/Android，
已有 `VoiceCallState` / `VoicePacketTransport` 已拆成不含设备后端的共享目标；未重写它们。
SDK 通过小型、有类型的音频端口拥有当前通话的设备会话；宿主适配器包装现有 `VoiceAudioEndpoint`，
Windows 设备选择和 Android 权限/路由留宿主。独立 SDK 不因此强制引入 SDL、WASAPI、AAudio 或 APM DLL。
控制消息和实时包使用两个明确的发送入口；随后 P3c-2 已接入双向 UDP Voice，控制消息保留 WS。
共享控制器结果见 [P3c-1 检查点](native_sdk_voice_controller_checkpoint_20260908.md)。
UDP、并发文件与 Web 保留验证见 [P3c-2 检查点](native_sdk_udp_voice_checkpoint_20260908.md)。
P3c-2 沿用硬件检查点 §4 的最小方案，用户此前已确认；该节的“待批准”字样是历史状态，不要求重复确认。

- 已有 `VoiceCallState`、`VoicePacketTransport`、`VoiceAudioEndpoint` 继续复用。
- 合并 Windows `ct_voice_call_protocol`/Workspace 与 Android `NativeVoiceCall` 中相同的消息构造、同意/拒绝、请求匹配、
  超时、静音状态与挂断规则；设备选择、系统录音权限、音频焦点/路由由平台端点负责。
- 先沿客户端发送、实际 connection、Render 接收/回传追踪语音帧，记录真实通道；`PostMediaMessage` 名称不等于 UDP。
- 按既定媒体边界完成必要的 Native 语音实时帧迁移：控制命令走可靠通道，实时语音帧走已认证关联的 UDP 媒体通道。
  核验 client→Render 与 Render→client 双向能力，不只改一端；沿用现有关联、序号和防重放检查，不开放未授权 UDP 注入。
- 若需要现有 UDP 结构之外的线协议或认证契约修改，先列最小变更及 Web 影响，取得方向确认再实施，不默默扩成服务端重构。
- 保留共享 APM 算法依赖；“Native 不用 WebRTC 传输”不意味着删除仍使用的回声消除算法。

验收：同意前无媒体、迟到接受不复活、拒绝/超时/重复挂断、无麦克风或权限失败、序号回绕/丢包恢复、文件并发时语音不被可靠队列拖住。
短实测链路和统计与双端人工听音分别记录；未听音不能宣称最终音质验收通过。

## 8. P4：独立构建与消费

- 提供不配置 Windows/Android 应用目标的 SDK 专用 CMake 入口，复用仓库现有依赖，不复制第三方库。
- SDK 不依赖调用者事先设置 `PX_PROJECT_PATH` 等隐式变量；根目录定位、依赖选项和工具链参数明确化。
- 区分网络核心、会话/功能、Windows 平台、Android 平台的目标依赖；SDK-only 测试不因 Qt 文件 UI harness 强制查找 Qt。
- 明确公开头与内部头，消费方通过目标传播 include/link，不手工补 SDK 内部或 build tree 路径。
- 增加 Windows 与 Android NDK 的独立配置/构建验证和最小消费示例，证明不启动 npm、Rust workspace 或客户端 UI 构建。
- 为首版提供受支持的源码集成方式与使用说明；预编译二进制分发/稳定 ABI 不作为此阶段要求，不虚称单文件零依赖 SDK。
- 说明创建、启动、回调线程、取消、关闭、输出替换和可选功能的持有顺序。
- 不支持的完整平台构建明确失败；Apple 适配未实现之前不能走 Windows 默认分支或假后端。

验收：从单独消费工程构建/链接所选 SDK 目标；仅网络核心不引入编解码/平台依赖；完整 SDK 不依赖 Qt UI；
Windows 应用、Android JNI 都使用同一套公开接入方式；最小示例能够创建和安全停止会话，而非仅编译一个头文件。

## 9. P5：短回归与交付

当前收尾状态：最新 Windows dist 20 秒出图和 WebRTC 浏览器 12 秒回归通过，Windows 产物已同步并核对哈希；
语音相关 7 组、剪贴板/录制/重连相关 8 组自动回归通过。Android 最新 Debug 构建及 18 项 JVM 测试通过，尚未安装。
剩余验收是最新手机包的页面/重试/剪贴板、Windows 系统剪贴板跨进程复制及真实设备语音听音。
手机正在供另一个项目使用，未切换应用、覆盖安装或清理数据；待确认空闲后继续，不以旧包验收替代。
详细边界和日志见 [UDP 语音检查点](native_sdk_udp_voice_checkpoint_20260908.md)。

### 自动检查

- 源码归属/依赖闭包、Native 单通道、双端设置入口、JNI 签名和 WebRTC 链接边界。
- SDK 生命周期、帧所有权、网络失败/重连，以及本轮变动涉及的文件、录制、剪贴板、语音测试。
- 销毁时有排队回调、分发中注销、回调内停止、重复启停必须有行为测试；新 C++ 必须确定初始化。
- `check_cpp_ownership`、150 列与变更块 `.clang-format` 检查；历史全文件格式差异如实记录，不机械重排无关代码。

### 运行验证

| 场景 | 验证重点 | 单场景预算 |
|---|---|---|
| Windows 本机实连 | 窗口、首帧、持续解码、输入与结束 | 20–60 秒 |
| Android USB 实连 | 首帧、页面返回/Tab、Surface detach/attach、重试与结束 | 60–120 秒 |
| 文件/剪贴板/录制 | 受影响功能、成功语义、文件哈希、取消/退出 | 各 60–180 秒 |
| 语音 | 接受/拒绝/静音/挂断、双向数据与缓冲统计 | 60–120 秒 |
| Web 保留路径 | 本机既有环境的授权、WebRTC 首帧与结束 | 60–120 秒 |

任何单场景不超过 5 分钟；不以连续重开相同场景规避限制。无关功能不在每个小批次重复全测。
没有设备、音频人工配合或可用 Web 环境时，明确未验收项，不用编译通过代替功能通过。
不安排蜂窝公网、全设备矩阵、长压测或用户此前跳过的矩阵测试。

- Windows 使用 `build_cpp_*.bat`；未获明确发布请求，不运行 `build_official.bat`。

## 10. 归档与风险控制

- 改动/退出旧实现前，完整归档当前工作区字节到新 `backup/<批次>/<原路径>`，包含未提交内容；记录基线、状态、原因与 SHA-256。
- 备份不覆盖、不参与构建/打包/运行；不保留可执行兼容分支。已有未提交变更不重置、不替换为 HEAD 版本。
- 最大技术风险是设备/帧释放顺序、Windows 授权实际归属、跨线程关闭、语音双向传输与 Web 共用服务端边界。
- 先以失败路径/最小消费者验证边界，再同时接入两个平台，避免只让一个平台变绿。
- FFmpeg、系统 C API 的瞬时借用值留在适配边界；项目 API、成员与异步捕获不用裸指针。
- 保留 InProcessLoopbackCapture 实现、Render 插件契约和 libwebrtc 借用 ABI；不改只读第三方源码。
- 若发现需新协议、服务端权限、外部平台选型或更大 UI 改造，记录影响并单独确认；普通资源迁移与已有双端接入按本计划执行。
