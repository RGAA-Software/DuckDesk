## 1. 结论与版本

该项目已具备较完整的桌面 RDP 客户端基础，应作为 GammaRay 新增 RDP 模式的优先复用实现，
不应从 FreeRDP Sample 重新实现已经存在的连接、图形、输入和剪贴板处理。
但它目前面向本地 Qt 交互，不是已经接通 GammaRay 的无窗口服务端桥接器。

## 2. 已有功能与证据边界

下表中的“已实现”指存在对应源码，不等于本次已运行验证，也不等于全部边界场景通过。

| 功能 | 已有实现 | 已知验证边界 / 新模式适配 |
|---|---|---|
| 连接生命周期 | Idle/Connecting/Connected/Disconnecting/Reconnecting/Failed 状态机；连接取消、清理 | 项目记录有首帧、取消及模拟中断验证；新模式需接实例 Ready/Failed |
| 线程与重连 | 专用协议线程、命令队列、事件泵；最多 5 次，1/2/4/8/15 秒退避 | 有模拟断线恢复及重试耗尽记录；真实断网、网关故障仍待验收 |
| 认证与证书 | 用户/域凭据；证书指纹、变更提示、拒绝/本次/永久接受；网关配置与消息交互 | GUI 弹窗需改为受管凭证和证书策略；不能无窗口时默认忽略证书 |
| 图形解码与合成 | FreeRDP GDI framebuffer、BeginPaint/EndPaint、桌面 resize | 已有真实服务器首帧记录；不是调用 GDI 抓取本机桌面 |
| 低积压帧传递 | 脏矩形合并、面积阈值切全帧、紧凑 BGRX32 数据包、消费确认 | 普通同尺寸路径限制一帧在途；resize/重连代次和并发仍需专项验证 |
| 本地显示 | OpenGL 纹理分区上传、GPU 缩放、可选 CPU 副本 | 服务端桥接无需保留 QWidget 显示路径；不能把 OpenGL 显示等同于零拷贝编码 |
| 图形质量 | 清晰、自适应、无损策略；GFX/H.264/AVC444/AVC444v2 配置 | 配置和协商能力不等于实际码流质量或性能达标 |
| 光标 | 形状、缓存 ID、热点、切换、隐藏与默认光标 | 转成 GammaRay 光标消息；防止漏光标/双光标 |
| 键鼠 | 扫描码、Unicode、扩展鼠标、滚轮、焦点/锁定键同步、组合键 | Qt/键盘 Hook 输入来源换成授权后的客户端消息 |
| 触摸与手写笔 | Qt 事件映射 RDPEI；未协商时回退鼠标 | 历史记录只证明 RDPEI 通道就绪；多点、压感和真机体验待验收 |
| 分辨率与多屏 | DisplayControl、连接时物理显示器布局、物理像素分辨率 | 多 DPI、全屏坐标真机验收待补；新模式布局不能直接取宿主物理屏幕 |
| 图形恢复 | 最小化恢复、屏幕热插拔、手动全桌面刷新 | 服务端以订阅恢复/重连驱动刷新，不依赖 Qt 窗口可见性 |
| 文本/富格式剪贴板 | 双向文本、CF_HTML、24/32 位未压缩 CF_DIB 图片 | HTML/图片真实服务器验收待补；替换宿主 QClipboard 终点 |
| 文件剪贴板 | 文件描述符与内容请求、目录递归发布/重建、原始 listIndex、进度、取消、重名隔离 | 实现较多，但文件/目录真实验收待补；不等于完整 FT 文件管理功能 |
| 磁盘重定向 | 显式选择目录/盘符，添加 RDPDR 设备，不默认发布全部磁盘 | 必须变成实例授权的目录映射；不能直接暴露宿主文件系统 |
| 打印机/智能卡 | 本机打印机多选、单个读卡器选择、对应设备注册 | 通道可用不证明设备操作可用；仍需真设备验收 |
| 音频/麦克风 | rdpsnd/audin 配置及通道集成 | 当前是本机设备后端，不是 GammaRay 音频桥；麦克风文档注明 winmm 默认设备限制 |
| USB/串并口 | USB 参数与动态通道注册、就绪诊断；串并口 UI 明确禁用 | 历史 USB 通道 10 秒未就绪；当前 Windows 构建不支持串并口，不列为已可用 |
| 通道状态 | 等待、已就绪、不可用提示及超时诊断 | 可复用为 GammaRay 能力状态；不得以勾选框代替实际协商结果 |
| 多会话 | 独立窗口各自持有 FreeRDP context 和协议线程 | 是客户端连接隔离，不代表企业身份、Windows 用户及宿主资源已经隔离 |
| 产品体验 | 最近 12 条成功会话、命名配置保存/加载/删除、截图 | 配置不持久化密码，新会话不复制密码；截图/配置 UI 不属于首版服务端核心 |
| 性能诊断 | 更新/发布/绘制计数、脏区字节、合并数、上传耗时、延迟、原始 CSV | 可复用观测结构，但需按桥接链路重定义指标 |

## 4. 接入 GammaRay 时保留什么、替换什么

建议在 GammaRay 内形成独立的 RDP runtime，参照现有 WebView runtime 的明确媒体回调接入模式，
优先迁移上述协议逻辑与已解决问题；不直接把整个 Qt 客户端窗口嵌入 Render，也不复制一个不可维护的并行协议实现。
正式引入哪些自有源码、依赖如何固定与构建，仍需实现阶段确定。本次外部仓库保持只读。

1. **保留协议基础**：连接、取消、重连、通道协商、图形解码/合成、输入、光标和剪贴板格式处理。
2. **替换视频消费者**：`frameUpdated → RdpView` 改为受控完整帧状态/缓冲池 → GammaRay 编码器。
   现有帧包可能只有脏矩形，不是每次完整桌面；必须先正确应用增量，才能取最新完整状态供编码。
3. **替换消费反馈**：目前 `paintGL` 发出 `frameConsumed` 后才放行后续帧。移除窗口却保留此依赖会卡住发布。
   新反馈对应安全的帧接收/缓冲生命周期，采用有界队列，不阻塞协议事件循环，也不丢失未合成的增量。
4. **替换本机终点**：键鼠来自 GammaRay 控制消息；rdpsnd 输出进入内存音频后端；剪贴板进入实例消息，
   不访问宿主 QClipboard；文件进入授权的实例目录。audin 另行映射现有语音输入，不能取宿主默认麦克风充数。
5. **新增企业管理层**：Service 管账号、SID、Session、秘密、配额、审计和实例生命周期；
   Qt 多窗口不是这一层的替代品。保持 game-hook/webview 不新建用户。
6. **补齐安全与生命周期**：无交互认证/证书策略、初始化失败、取消认证等待、旧代次回调、重复启停、
   回调中停止、派发中注销和异步销毁。迁入的自有 C++ 必须遵守 GammaRay 智能指针/RAII 规范，不能照搬裸指针和 `[this]` 捕获。

源码额外注意：`MainWindow.cpp` 构造函数含硬编码默认连接凭据。本文不记录其值；
“配置不保存密码”不等于没有凭据风险，产品化迁移必须去掉默认秘密，若其仍有效应更换。
文件接收已有描述符数量上限及 `.`/`..`/冒号检查，但这不是完整安全验收；
还需检查 Windows 路径归一化、重解析点、并发临时目录、ACL、容量限制、取消清理和跨实例访问。

## 5. 未完成项与性能结论

- RemoteApp/RAIL 尚未实现：当前是单一远程桌面画布，缺少远端窗口生命周期、裁剪、图标、Z 序、移动/缩放等。
  本次新增“RDP 应用模式”不要求首版实现 RAIL；可先提供独立用户的完整桌面，两者不能混为一谈。
- 录制仍在后续计划；触摸/手写笔、富格式/文件剪贴板、真实设备、多 DPI 和实际网络故障的验收尚未齐全。
- 历史 `rdp_benchmark_report_smoke.md` 只有 3.418 秒短采样：约 29.55 updates/s、实际绘制 0 fps。
  项目说明为隐藏窗口场景，只能证明采样链路，不能得出“仅支持 30fps”或“已经支持 60fps”。
- 文档称“端到端 P95”的实现时间戳始于 EndPaint 附近的脏区发布链路，止于 `paintGL` 绘制调用后，
  不含完整的远端渲染、网络和此前解码耗时，也不证明 GPU/屏幕实际呈现完成，更不是输入到屏幕发光延迟。
  桥接版本应分别记录 RDP 更新、合成、排队、编码、传输及客户端呈现指标。
- Media Foundation 后端及 AVC444 修复有复用价值；GPU 解码命中率、CPU 合成/复制成本、色彩转换、
  重编码损失和双用户 1080p60 仍需测量，不将“有硬件后端”写成零拷贝或 60fps 保证。

后续实现以 [RDP 应用模式设计](rdp_application_mode_design.md) 为准：R0 优先从本项目抽取非 GUI 帧源，
再接模式与多用户管理；每次实际验证不超过 10 分钟，按已具备能力分批测试，未测项目明确保留。
