### 0.2 最终产品行为

- Windows 普通桌面、GameHook、WebView 和支持范围内的 Android 共用 iroh 传输内核；RDP 通过同内核可靠流透传。
- 默认自动选择直连/中继；提供明确的“强制中继”诊断策略，界面和日志显示实际路径与恢复状态。
- 视频和音频走数据报；控制、输入、剪贴板、文件和 RDP 走各自可靠流。录制继续保留。
- Relay 仍叫 Relay；先交付可安装、可托管的单 Relay，再做到可登记多台、扩容、维护和故障恢复。
- 复用现有登录及资源会话授权，不引入短期 transport token、额外 ticket、第二套认证或相关附加验收。
- Web/Direct Host WebRTC 保持现有边界，不将其改为 iroh，也不恢复中央 SDP/ICE、TURN 等退休组件。
- 当前“强制 TCP”是旧显式直连 WebSocket/TCP，对照期保留。最终旧栈退出时一并移除该旧路径开关，使用明确的统一策略；
  不把“强制中继（TCP/TLS）”静默伪装成“TCP 直连”，不让两个矛盾开关长期并存。

### 0.6 UDP 稳定性验证贯穿主线

不将当前 UDP 标成“完全稳定”，也不要求所有网络条件下零抖动才开始正式 Relay 开发。
每次影响传输或媒体的实际修改保留针对性回归；未影响的检查复用已有结果。

- 正常网络：固定动态源、分辨率/帧率/码率和动作，direct 与正式 Relay 各连续 10 分钟、重复 3 次，
  作为 M3/M5 稳定性验收，不变成每次小改动的必跑全套。输入必须有转发日志和视角变化，不能只统计投递了鼠标消息。
- 分开记录启动、稳定运行、故障和恢复；保留全部失败窗口。先补齐显示呈现和逐帧间隔计量，再宣称显示 FPS/P95/P99；
  第 12 节的显示目标没有自动通过，也不以解码前计数代替。
- 再遇正常网络下重复 150–220ms 或秒级停顿，先关联源端输出、收包等待、组帧、参考恢复与解码，
  必要时双端有限抓包，再比对 Sunshine/Moonlight；不盲调 IDR 超时、缓冲大小或拥塞算法。
- 低于实际码率的链路允许降画质/降帧；只要求队列有界、无恢复请求风暴、网络恢复后可恢复。
  2Mbps 不能维持原画质 60fps 不单独阻断正式 Relay 工作。无画面且无法恢复、持续秒级停顿或新增回归则先修复再扩大交付。
- 现有 TCP 仅作定位对照，不用“TCP 也卡”证明 UDP 已通过，不用单轮较好最大值证明网络丢包根因已解决。

## 7. P3：冻结传输、媒体与授权契约

- [ ] 至少两台物理宿主/独立网络路径：验证一台断开、维护排空、延迟差异和双端恢复；不能把 10 个本地进程称作 10 台性能验收。
- [ ] 负载递增报告：以实际码率与链路上限给出容量曲线；均衡目标按权重/容量，不要求不同硬件上连接数绝对相等。
- [ ] 单端点高并发热点与大规模 P2P→Relay 回退测试，明确容量边界和失败提示。
- [ ] 切换期间不重复启动应用、不增加许可路数、不让第二个控制者越权进入。

## 10. P6：RDP 与 Android

- [ ] 普通断线或 Render 停止不注销、不删账户/配置、不终止工作区应用；重连验证已有会话身份。

- [ ] 核对 `core-native`、JNI、Native SDK 和 ABI/构建目标；接入同版本传输与媒体契约，不增加旧协议适配 facade。

- [ ] 云应用仍使用独立业务入口和 `client_type=android`；不恢复设备内旧应用库或冒充 Panel。

## 12. 测试与交付记录

### 固定场景

清洁网络性能目标先采用：稳定 1080p60 动态源，每路目标总线速预算明确，实际可用带宽留出余量，连续 10 分钟，至少重复 3 次。
记录每路采集/编码/发送/组帧/解码/显示 FPS 和帧间隔、输入响应、队列年龄、CPU/GPU、wire bitrate。
建议初始门槛为显示平均 ≥58 FPS、P99 帧间隔 ≤50 ms；P0/P1 固定测量方法，P2 前冻结条件，不在失败后悄悄更改门槛。

direct 与强制 relay 分开测。弱网矩阵包含随机丢包 1/3/5%、突发丢包、乱序、带宽骤降、受限 MTU、文件并发和多路媒体。
弱网门槛以恢复有界、无无限排队、无请求风暴、无业务错误为主，不保证低带宽仍保持原画质/60 FPS。
失效期间和恢复后的数据要分别统计，不能删除停顿窗口后报告平均值。

### 验证入口

P1 优先复用 `scripts_build/build_cpp_media_transport_tests.bat`、相关 SDK/Client focused 测试入口，按实际修改扩展贯穿恢复链的测试。
当前 media transport 脚本只运行 `upstream_media_reference`，不能假定它覆盖 SDK 解码生命周期。
P2/P3 增加独立 Rust transport Release 构建/测试入口；不将 `build_official.bat` 用于日常验证。

本机 changed runtime artifacts 必须同步到对应 `build_official/<product>/dist` 并匹配 SHA-256，才可报告交付。
文件占用时仅在测试发布步骤停止对应进程后发布；不影响无关用户会话。
真实安装验收另按完整包执行，不能用同步开发 dist 代替安装。

每个阶段记录：任务 ID、代码 revision/工作区状态、构建命令与配置、产品/依赖版本、测试拓扑、参数、结果、证据路径、未解决项。
