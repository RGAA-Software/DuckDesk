# 90 / BJ 跨宿主容量与新端点分配

2026-10-10，网络主线 M2 接续。本批未修改产品网络行为或安装产品包；复用已安装 Windows/Linux 正式 Relay，新增可复用的新端点分配探针。

## 代码核对

Console `available_iroh_relays` 排除离线、过期、禁用、维护和不足两个连接余量的节点，并按连接占用率排序。iroh 决定实际 home/path；候选列表的顺序不构成均匀分配承诺。Relay 在锁内计算真实活动连接并拒绝超额，断开按 ConnectionId 精确释放。端点在被拒绝后暂时抑制候选，容量恢复后重试。

没有发现需要用猜测性参数调整解决的新缺陷。这里验证的是硬连接容量、候选重选与容量溢出后的新端点接入，不是 Console 预约分配或带宽均衡已经实现。Relay 连接数不是应用路数；跨 home 通信还可能需要额外连接，不能把连接上限直接等同于端到端并发路数。

## 拓扑与隔离

- 本机 Windows 运行真实 transport probe，使用生产 transport crate、强制 Relay、两台私有 CA 校验。
- Relay 为 90 Windows `39.71.45.66:4605` 和 BJ Linux `49.232.233.61:4605`，保持 Console 管理身份。
- 预检遍历 201 个资源会话，无活动会话。测试临时停止 90 空闲节点服务，避免桌面 Endpoint 占用测试容量；未注销 Windows 用户或终止 RDP 工作区应用。
- 两台 Relay 临时设为两个连接上限，脚本 finally 和 240 秒截止负责恢复原配置；没有全局网卡或防火墙变更。
- 完成后两台配置原字节/哈希恢复，上限 4096、ready/fresh、未维护；90 节点服务 Running。

## 结果

| 场景 | 实测结果 |
|---|---|
| 两台满额，释放备用 BJ | 515 ms 后接入 BJ；可靠回显 6,291,520 bytes 一致；数据报 118/120，最大往返 485.276 ms |
| 两台满额，释放原拒绝节点 90 | 4364 ms 后重新接入 90；可靠回显一致；数据报 111/120，最大往返 302.423 ms |
| 四个新 Endpoint 均获得双候选、不固定 home | BJ、90、90、BJ；接入 425/473/362/1161 ms；最终每台两连接，已有健康 home 保持 |
| 分配后的已准入同 home 端点通信 | 可靠回显一致；数据报 115/120，最大往返 455.388 ms |

容量/分配功能通过。探针并发突发三个 2 MiB 可靠流、一个 64-byte 流和 120 个数据报；丢报与延迟保留，不把该结果称为实时媒体/长期性能通过。两个探针端均在本机，Relay 分处独立 Windows/Linux 主机；这不是两端跨 NAT 或十机器负载均衡验收。

证据：`20261010_cross_relay_before.json`、`20261010_cross_relay_capacity.json`、三份 `20261010_cross_relay_*.log` 和恢复日志。新增探针命令为 `px_transport_probe allocation-self-test --endpoint-config <配置>`；本地可通过 `scripts/tests/run_iroh_relay_capacity.py --allocation` 运行相同分配场景。
