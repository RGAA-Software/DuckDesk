## 新日志口径

旧完整帧日志中的 frame 是编码帧号；队列缺包中的 frame 是传输帧号。两者原本不连续对应，缺失明确映射会导致关联错误。
新增记录同时保留两套帧号。一次捕获仅一个自有游戏实例/连接，使用 stream、wire_frame、timestamp 与本地 trace 区分。

| 事件 | 内容 |
|---|---|
| `diag_offer` | 进入发送层的编码帧号、传输帧号、类型、大小、队列长度、本机单调时间 |
| `diag_tx_frame` | 每帧排队/总耗时、路径/RTT/cwnd/QUIC 丢包计数、每个分片写入结果 |
| `diag_rx_packets` | 解密后到达的分片顺序、块号、分片号、预期数据/冗余数量及相对到达时间，包括重复/迟到分片 |
| `diag_rx_result` | 当前分片、完整帧编码号、是否交付、缺失参考、恢复片数、迟到/乱序/重复计数、推测或最终缺帧 |
| `diag_capture_resume` | 编码准入等待超过 2ms 后恢复的实际等待与在途状态 |
| `feedback_trace` | 诊断窗口内每次反馈到达和释放情况；原 RFI 发起/发送/参考恢复日志继续保留 |

`writes` 每项为 `sequence:block:last_block:shard:data_count:parity_count:start_offset_us:write_us:error`；
`arrivals` 每项为 `sequence:block:last_block:shard:data_count:parity_count:arrival_offset_us`。
TX 偏移相对于 `origin_us`，RX 偏移相对于 `first_us`。两机单调时钟不能直接相减，墙钟也不作为单程时延依据。
写入成功只表示本地 QUIC 接受，不表示网卡已发或对端已收。对端没有记录的分片只能先标为 unobserved，不能直接归因为物理丢包。

临时详细日志限制为每个媒体对象最初 90 秒；收包按帧汇总，500ms 窗口刷出，最多保留 64 帧、每帧 2048 条分片观测，
截断会明确标记。跨刷出窗口的同帧记录需合并。无包内容、登录凭据或授权票据。既有日志轮转限制继续有效。
连接结束后也可能有发送失败，分析时必须区分活跃窗口和清理窗口，不能把清理阶段 250ms 超时当作正常画面停顿。
