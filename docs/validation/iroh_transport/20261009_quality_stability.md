# 2026-10-09 码率恢复与 WebView 停顿定位

本轮已交付码率策略和分阶段诊断。短时压力不再直接连续减半码率，健康反馈下能恢复画质。**尚未通过高画质持续 60 FPS 的验收**：游戏直连仍有 305.1ms 短停顿，WebView 加载后有 226.7ms 间隔。保留这些结果，不把“没有秒级长停顿”解释为所有卡顿已解决。

## 实现

- `VideoRateControl` 区分瞬时压力和持续拥塞：普通压力持续 1 秒后每秒减 20%；持续大队列和确实未收到完整帧时快速降码率；非零 RTT 建立基线，切换路径重新采样。健康反馈持续 2 秒后每 2 秒逐步恢复，仍受用户请求上限约束。
- 接收字节率用 500ms 累计窗口计算，完整帧额度仍每 50ms 确认，避免单个空反馈把短窗口估计拉到零。
- WebView 增加导航、首绘与超过 100ms 的绘制间隔；发送端记录编码帧间隔，SDK 记录同一帧号的接收间隔。跨机器比较间隔和帧号，不直接相减未同步的时间戳。
- 共享纹理使用 NT 句柄成功打开时，不再因前一项接口尝试失败而逐帧输出警告。真正打开失败仍记录；没有更改纹理缓存、互斥或所有权语义。
- 未新增认证系统、短期 token 或 ticket；QUIC 仍负责线速 pacing。本轮完整原文件归档在 `backup/iroh_quality_stability_20261009/`。

## WebView 原因定位

- 第一次失败：第 3 帧绘制间隔 957ms、编码间隔 957ms、接收间隔 953ms。随后页面报 `A valid external Instance reference no longer exists` 和 `Instance dropped in popErrorScope`，场景停止，绘制/编码/接收均约 450ms 一帧。这是源页面/WebGPU 初始化失败，不能解释为 UDP 丢包；WebGPU 失败的底层原因仍未确认。
- 重启成功：第 145 帧绘制间隔 968ms、编码间隔 977ms、接收间隔 989.5ms。导航 HTTP 完成不代表三维场景已经持续绘制；本轮约一秒的启动间隔主要来自页面绘制。
- 成功加载后不再出现相应的长绘制间隔，但编码前准入和接收仍有短间隔，码率日志伴随 RTT/在途压力。这部分属于后续传输/反馈/编码准入优化范围，不能与启动绘制停顿混为一谈。
- 没有自动强制 WebGL、修改第三方页面或添加静默浏览器重试策略。
