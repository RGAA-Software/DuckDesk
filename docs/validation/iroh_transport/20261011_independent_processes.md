## 排除测试入口干扰

1. 首次尝试把两个 controller 会话都指向同一游戏类别。当前 Console 是 starter 配置，每类别一路，第二次资源会话创建返回 `409 connection_busy`；文件进程未启动，不能算混传失败。保留 `20261011_independent_processes_admission_attempt.json`。随后使用正常独立文件服务入口：桌面文件会话 + 游戏视频会话，没有更改许可证或绕过配额。
2. 自动文件验收原先无条件等待首帧。纯文件进程没有首帧，现按启动模式决定是否等待，正常视频混传仍保持等首帧行为。
3. 独立文件窗口会先消费远端删除结果，自动验收随后一直等待并误报超时。此次明确由验收器消费自己的结果，普通文件窗口行为保持原样，并增加上传/下载完成日志。旧失败轮的上传/下载文件 SHA 均为 `bc11ccf975a9d76a408b39e80d91c7b72265e7b0706f9c2447661bcbee3babc1`、远端测试文件已删除；这次 FILE_TRANSFER_TIMEOUT 是测试结果消费问题，不是网络断开。原始证据 `20261011_independent_processes_harness_attempt*` 保留，不计有效通过。
4. 上述旧轮恢复授权后的只读查询遇到 403：授权恢复操作使旧登录失效；后续重新登录确认 ACL 已为空。正式两轮均重新登录核对恢复成功，不遗留授权。

只修改本机 Client 的自动验收入口及结果归属，未改变实际传输实现；两产品增量 Release 编译、入口附带测试通过，build/dist SHA 一致，身份 `20261011_independent_processes_build.json`。
