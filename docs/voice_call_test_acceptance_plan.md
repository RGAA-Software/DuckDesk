## 1. 验收原则

本计划验证的不只是“能听见”，而是授权可信、双向媒体真实、异常可恢复、音质达标、资源释放、版本兼容和既有远控功能不回归。

测试结论分为：

- `PASS`：按指定构建、步骤和判定标准得到完整证据。
- `FAIL`：实际结果不符合标准，必须记录缺陷和可复现信息。
- `BLOCKED`：环境或依赖缺失，不能记为通过。
- `N/A`：经评审确认不适用，并写明原因。

严禁用以下结果替代正式验收：

- 仅看到协议回包，却没有确认真实采集、编码、传输、解码和播放。
- 使用自动接受、测试后门或直接调用内部函数，替代正式 Panel UI 的用户接受/拒绝。
- 只看累计包数，不验证包属于当前 `call_id` 且挂断后停止。
- 只在 dummy 声卡通过，便声称真实麦克风、扬声器、AEC 或热插拔通过。
- 只在90号机通过，便声称 Win10、Win11、不同声卡和浏览器矩阵通过。
- 测试失败后无修复记录直接重跑，或只保留最终一次成功结果。

### 1.1 2026-08-24 增量执行记录

本机 Chrome 与90号机正式 Render/Panel 路径已新增一条可量化的 Web 语音闭环：浏览器 outbound RTP 从95字节增长到7506字节；90端确认首个48kHz/mono/16-bit/480-frame PCM，RTC累计153包/7506字节/0丢包，通话端点累计 `rx_pcm_samples=207840`。挂断后远控画面和输入继续运行120秒并保持 connected。该结果记为 WebClient Chrome 核心传输 PASS，不替代真实物理麦克风、生产 HTTPS、Edge或双物理机 AEC 门禁。完整证据见 [标准 RTC / TURN 双机验收报告](webrtc_rtc_acceptance_report_20260824.md)。

## 2. 优先级与发布门禁

| 级别 | 定义 | 发布要求 |
| --- | --- | --- |
| P0 | 安全、授权、基本呼叫、媒体、清理、安装和核心回归 | 必须 100% PASS，0 个 Blocked/N/A，0 个阻断/严重缺陷 |
| P1 | 主要平台、弱网、设备变化、AEC、Web兼容、长稳 | 计划矩阵全部执行；失败须修复或有明确风险签字，不得隐瞒 |
| P2 | 极端设备、辅助体验、扩展组合 | 可安排后续，但必须记录覆盖率和已知限制 |

正式发布还必须满足：

1. 候选版本来源唯一，commit、产品版本、安装包和关键二进制哈希已冻结。
2. 生产构建不含自动接受、伪造设备、固定凭据、跳过鉴权或测试证书逻辑。
3. P0 自动化连续两次干净通过；90号机完整 E2E 在候选安装包上通过。
4. 正式来电 UI 由真实用户执行接受、拒绝和不操作超时各一次。
5. 双物理终端完成外放 AEC/双讲以及2小时耐久，不能用同机软件回环完全替代。
6. 修复任何语音缺陷后，重跑缺陷用例、所属分组及 P0 回归。

## 4. 测试数据、工具与观测

### 4.1 可重复音频输入

- 1 kHz 正弦波：验证通道、采样率、增益和无明显重采样错误。
- 20 Hz–20 kHz sweep：发现截断、严重失真和格式错误；语音链重点观察 100 Hz–8 kHz。
- 短 chirp/脉冲：计算采集到播放的单向时延和抖动。
- 标准男女声语料及静音段：验证 VAD/DTX（启用时）、NS、AGC和可懂度。
- 远近端同时讲话样本：验证 AEC 双讲不吞音。
- 确定性 PCM 向量必须可校验哈希；真实用户语音不得作为仓库测试资产保存。

### 4.2 必采指标

每端至少采集：状态转换、结束原因、发送/接收/解码/播放包数、重复/乱序/迟到、PLC/FEC、队列当前值/峰值、capture/playout drop、underrun、设备重建、CPU、工作集、句柄、线程和网络字节。

正常网络建议发布阈值：

| 指标 | P0判定 |
| --- | --- |
| 单向端到端时延 | P95 不高于 150 ms；测量方法和设备缓冲需记录 |
| 接收音频队列 | 稳态目标 60–100 ms，峰值不超过 200 ms，拥塞后能回落 |
| 音频帧节拍 | 20 ms；持续时间与包数误差不超过 2%（排除明确静音/DTX） |
| 进程存活 | 通话、拒绝、断线、设备变化均无崩溃/死锁 |
| 2小时资源 | 工作集无持续单调增长；结束后线程、句柄和声卡占用回到基线容差 |
| AEC | 实验室单讲 median ERLE >= 15 dB；双讲近端语音无持续吞音；人工10分钟无明显回声 |
| CPU | 记录目标机规格和基线；语音增量不得导致视频帧率或输入响应明显退化 |

如当前实现达不到阈值，应记录 FAIL 并进入优化，不得修改阈值以迁就结果。阈值变更必须有设计评审和测试数据。

## 5. 自动化测试层次和命令

现有最低命令：

```powershell
cmake --build build_official --config RelWithDebInfo --target test_voice_call test_client_voice_call_protocol test_client_virtual_display
./build_official/src/px_deps/px_voice_call/test_voice_call.exe
./build_official/src/px_client/test_client_voice_call_protocol.exe
./build_official/src/px_client/test_client_virtual_display.exe
cd web/px_web_client
npm run test:voice
npm run build
```

截至2026-08-23当前开发构建：`test_voice_call` 共33项（31通过，2项真实设备/长稳条件测试按设计跳过）；CTest登记的语音核心、客户端协议、虚拟显示器回归为3/3；Web关联状态、每次通话前提示和安全上下文测试19项通过且生产构建通过。条件测试必须在指定环境单独执行并保存结果，不能把跳过计为通过。

实现阶段应把这些测试注册到 CTest，并新增独立目标：

- `test_voice_call_state`：纯状态机和模糊输入，可并行、无设备依赖。
- `test_voice_audio_pipeline`：确定性 PCM、APM、Opus、jitter/PLC、有界队列。
- `test_voice_call_plugin`：伪造 plugin host，覆盖鉴权、并发、消息路由和清理。
- `test_voice_panel_ipc`：Panel IPC 关联、超时、重复响应、进程重启。
- `test_client_voice_call_ui`：Qt 状态、按钮、快捷键、可访问性和跨线程投递。
- Web 单元/组件/E2E：状态 reducer、permission/mock track、真实浏览器授权和 track 生命周期。

所有自动化测试必须支持非交互运行并返回非零失败码。真实设备测试必须与 dummy 设备测试分组，禁止因 CI 无声卡而静默跳过后仍显示全绿。

Web真实浏览器脚本为 `scripts/cdp_voice_call_e2e.mjs`。它只从运行时 `WEB_URL` 取连接信息，证据会脱敏包括 `c` 在内的敏感查询参数，并在截图前遮盖受控桌面；`EXPECTED_DECISION=accept/reject/timeout` 分别覆盖正式Panel决定。accept路径还会验证两条audio m-line、接受前sender无track、双向RTP增长、双向独立静音和挂断后track ended。调用方必须用真实Panel操作或UI Automation执行决定，脚本自身不绕过授权。`ALLOW_INSECURE_MEDIA_TEST=1` 仅允许在自动化中把指定 HTTP 源临时视作安全源，结果必须标记该开关且不能替代生产 HTTPS 验收；正常 HTTP 必须另以 `EXPECT_INSECURE_BLOCK=1` 验证明确禁用和不采集麦克风。

候选安装包部署后运行 `scripts/validate_voice_install.ps1`，验证 Service/Panel、语音 APM 与插件、WebClient、两端安全提示、卸载登记及 USBMMIDD 健康状态，并把文件哈希、驱动签名信息、进程和监听端口写入 JSON。该脚本只做安装健康检查，不替代真实呼叫媒体 E2E。

## 16. 90号机最终验收流程

以下顺序必须使用同一个冻结候选安装包，过程中不得替换单个 DLL：

1. 记录90号机系统、活动会话、显示器、音频设备、服务/进程/端口和现有安装版本；备份需恢复的用户配置。
2. `/S` 静默覆盖安装，核对返回码、服务状态、模块数量、监听端口、插件加载日志、版本和SHA-256。
3. 原生客户端连接，确认物理屏首帧和 capability；执行呼叫→真实Panel接受→双向语音→双方静音→挂断。
4. 执行拒绝、30秒超时、等待中取消、错误call重放和第二客户端busy。
5. 添加一块USBMMIDD屏，采集新增屏，切回物理屏；通话中切屏；移除测试屏并确认画面恢复。
6. WebClient先在正常 `http://IP` 验证安全上下文禁用提示，再在生产 HTTPS 入口用Chrome通过真实鼠标操作悬浮按钮，完成浏览器授权、Panel接受、双向语音、静音、挂断、刷新清理；仅测试安全源开关的结果不得冒充生产 HTTPS。
7. 分别验证当前默认直连与Relay；记录实际选中传输，禁止根据配置推测。
8. 重启Panel、Render和Service，执行断网/恢复、锁屏/解锁；确认状态和设备释放。
9. 执行30分钟并发冒烟；2小时和外放AEC可在双物理终端完成，但结果须关联同一候选版本。
10. 重复静默安装验证幂等；按发布要求决定是否执行卸载。恢复用户原有显示拓扑和配置，清除临时任务、测试文件、凭据及进程。

90号机通过标准：所有指定 P0 通过，结束后产品按用户要求保持安装或恢复；Service/Panel/Render模块正常；显示拓扑精确恢复；无测试任务、凭据、临时端口、孤儿进程和声卡占用。测试报告必须明确列出未在90号机覆盖而由其他环境承担的用例。

## 17. 缺陷严重度与重测

| 严重度 | 示例 | 发布处理 |
| --- | --- | --- |
| Blocker | 未授权开麦、跨会话串音、安装后服务不可用、稳定崩溃 | 必须修复并重跑全部P0 |
| Critical | 挂断后仍采集、错误用户接受、持续明显回声、资源永久占用 | 必须修复，重跑所属组+P0 E2E |
| Major | 热插拔无法恢复、弱网无限延迟、Web假Connected | 默认必须修复；风险接受需书面记录 |
| Minor | 文案、偶发非阻断UI布局问题 | 可评审延期，但纳入已知问题 |

每个缺陷记录：首次失败证据、根因、修复提交、影响面、重测用例、回归组和最终证据。重试通过不能删除首次失败记录。
