## 区分业务对象

- resource_sessions 是明确主体/目标的逻辑前端；首次 connected 事件才代表一次被节点确认的访问，创建预约不是访问成功。
- client connection observations 是该逻辑前端下的实际承载/通道观察，具有独立 UUID、节点连接代际、序号、收发计数和终态。
  多通道不增加用户人数，持久快照不代表当前在线，也不能作为 RDP 第二前端准入依据。
- 旧 c_stream 还保存具名连接设置，不只是媒体在线流。新连接设置需要明确 owner、目标和有界媒体/界面选项，
  不搬迁旧设备密码、任意 host/port 或自动推断目标字段。其产品调用覆盖尚待盘点，不能以观察表替代后宣称完整。
- file_transfers 是连接内业务记录，必须引用 resource_session 和该会话的精确 node；
  不接受仅凭 visitor_device/target_device、IP、文件名或无认证头推导上报权限。
- 会话录制事件与节点本地录像库/Console 缓存是不同对象。自主录制文件允许没有 resource_session，
  仍保留按节点列表、已完成文件过滤、按需回传、播放下载、保留副本和缓存清理能力。

## 连接观察与访问历史的接续实现边界

访问历史从 resource_sessions 及其追加事件投影：created 只表示请求已接纳，首次 connected 才是节点确认接入时间；
这里的接入确认不证明已经产生首帧、音频或 Windows 桌面就绪；媒体质量/实际可用性另由客户端和节点运行状态验证。
closed_at 只在精确 retirement 完成后产生。Unknown/closing 不补造结束时间或成功时长，不根据本机时间倒算不存在的回执。
浏览历史允许同主体的新有效登录读取本人同 client_type 的历史，但不能借此续签原登录的描述符。

连接观察使用独立 channel UUID，并固定 session、node、node generation、control epoch 和通道类型；
一次逻辑前端可以有多条实际传输通道，观察者/控制者和 RDP 单前端人数仍只由 resource_sessions 管理。
当前已准入节点上报连接/进度，采用单调序号和累计字节；重复同序号必须同正文，终态不能重新 Active。
节点换代或 frontend retirement 时，尚未确认结束的通道同事务进入 Unknown；拒绝新节点接管旧 channel ID。
通道断开记录本身不释放实例/RDP 占用，不注销 Windows 会话，不触发按进程名清理。

这些字段不存 appkey、token、任意用户路径或旧 device/account 推导标识；状态查询使用明确主体/目标 FK 与有界游标。
会话录制开始/停止事件与完成文件目录分开，不能将“开始录制”转换成可以回传的 finalized 文件。
连接观察已实现为 connection_observations / connection_observation_events，十二条显式 SQL；
访问历史直接投影资源会话及首次 connected 事件，不再建立第二套占用权威。
每个逻辑前端最多 16 条 Active 通道；控制/媒体/音频/文件/RDP 类型明确。RDP 仅记录其协议载体/控制通道，
拒绝用独立视频/音频采集通道替代；observer 不得建立文件通道。
pg-20260917-081101-91e119d2 的 Windows 八组专项通过，含二十路创建/同序号/最后通道名额竞争、
RDP 人数不变、原登录撤销、同主体新登录读历史、Guest/Android 隔离、节点换代与审计失败回滚。
源码 hash 已核对；新十二领域共享池和完整跨平台恢复仍以接下来的完整报告为准。

后续节点协议已经加入 `open_channel` / `report_channel`，并复用受认证 NodeConnection、严格递增 request_id、session/node/generation
和 frontend lease 门禁；Console 端可持久化并回传精确 channel 状态。当前缺口在生产侧：Service/Render 尚未从真实控制、媒体、音频、
文件或 RDP carrier 生命周期生成这些消息，因此现有 wire/handler 测试不能代替 DB5 的真实通道行为。

## 文件传输记录实现

创建从当前已确认的 controller 会话发起，节点身份由已认证长连接上下文提供；
事务内重新检查节点代际、会话授权、目标和租约。节点 request_id 幂等，不同正文不得覆盖。
记录使用新 UUID，方向、文件 basename、总字节、声明 SHA-256、owner/target 引用保持不可变；
不保存源/目的绝对路径、凭据或任意错误正文。

进度使用单调序号、累计字节和正文摘要：同序号相同正文幂等，不同正文或倒序拒绝，已确认字节不回退。
所有 u64 必须在写入前通过 i64 上界检查；成功要求字节数完整且接收侧 SHA-256 与声明值一致。
这个条件仅检查上报契约；DB5 仍须对真实两端文件独立计算 hash，不能用上报字段替代文件验收。

终态不可复活。权限撤销后拒绝开始新传输，但允许原生产者提交其已开始记录的最终失败结果；
结果记录不授予额外文件访问能力，实际传输必须遵守资源会话租约。
节点失联/换代后未完成记录标记 Unknown，不伪造 Completed；新连接不能借相同 ID 接管旧生产者。
前端关闭确认也把没有终态回执的传输标为 Unknown（frontend_closed），与关闭及审计同事务；
明确的 Completed/Failed/Cancelled 不变。节点必须先送达并确认传输结果，再确认前端 retirement。
关闭后遗漏的终态不靠晚到 Progress/Completed 覆盖 Unknown；保守保留缺证据状态，不伪造成功。
变更记录和追加事件同事务；事件写入失败必须回滚字节、序号和状态。

管理查询仅 admin/viewer 管理终端可访问，owner 查询从凭据派生，不接受正文 owner；
UUID 游标稳定分页，单页 1–100，索引覆盖节点/会话/主体反向查询。

已实现表为 file_transfers、file_transfer_events，9 条显式 SQL；事件只追加，运行角色不可删除记录或修改声明文件/大小/目标。
首批六组 Windows PG 专项 pg-20260917-055514-9ac7878f 通过，含 20 路重复创建和同序号冲突、错节点/观察者/过期租约拒绝、
进度/hash/终态、撤权后失败记账、重连 Unknown、审计失败回滚、分页/去密/重启。
之后新增前端关闭联动；七组 Windows 专项 pg-20260917-055745-8faf6db0 全部通过，
包含关闭/传输事件失败时整体回滚和重复关闭不重复改历史。
完整报告 pg-20260917-055925-f437e6a6 的 Windows/Linux 各七组、前序回归及三库恢复通过，源码/工具 hash 已核对。

产品接入缺口；不得把 Console 接收协议存在写成文件传输已经端到端完成。

## 录像库与缓存

录像身份为独立 UUID + node，而不是拼接 device:filename；文件名、大小、修改时间仅为文件版本识别信息。
节点为每个已结束的不可变 MP4 文件版本持久化独立 source UUID 和 SHA-256；完成标记与内容 hash 都确定后才能上报。
hash 在节点受限的后台任务中计算/保存，不在 Console 的目录查询事务内读取整段媒体。
同 source UUID 的内容 hash、文件名/大小/mtime/codec/会话归属
不可改写。修改文件生成新 source UUID，即使文件名相同也不会覆盖旧记录。节点上报按当前连接代际及每源单调序号去重。
目录保留 reported_present 与 observed_at 作为历史观察，不能把它们解释为当前节点健康或文件一定可获取；
节点重新鉴权后需明确重新观察，实际回传还要再次查验文件版本、完成标记和当前准入。
自主录像 session_id 可空；若关联会话，则必须是本节点的精确 resource_session。云应用权限不授予浏览整个执行节点的录像库，
节点库读取遵守明确设备 ACL，管理员/只读管理员使用独立管理入口。
录制中不作为可播放文件；文件版本变化使旧回传任务失效，不能让晚到进度覆盖新文件。
缓存任务、临时文件提交和数据库 Ready 必须有明确顺序与可恢复状态；不能在文件写完/核对之前返回 Ready。
保留副本不被普通 TTL/磁盘压力清理，清理使用租约和精确缓存对象身份，禁止未验证路径递归删除。
媒体访问仍需当前节点/设备权限和短效访问凭据，不暴露无鉴权 uploads 静态目录。
旧录像设计里的明文/固定端口及静态 uploads 只作历史功能盘点，不作为新实现的通信和鉴权方案。
仅恢复 PostgreSQL 不能恢复外部录像文件：恢复/重启后必须核对实际缓存对象和 hash，再开放 Ready；
缺文件保持不可用并报告风险，不能仅凭旧库 Ready 标记提供播放地址。

缓存实施采用逻辑 recording 与物理 blob 分离：每次回传尝试登记新的 blob UUID，临时/完成路径都由受保护根目录和
受控 UUID 生成，不从用户文件名拼接。晚到旧任务不能覆盖或复活新任务引用的 blob；只有当前租约且完整大小/SHA-256
核对通过后，才提交 Ready 的 blob 引用。文件 IO 不占用长数据库事务。
发布与清理还需每 blob 跨进程锁及锁内再次检查任务/引用状态；不能仅在 IO 前检查一次数据库就认为没有竞争。
清理不能只按后缀扫删：仅处理持久账本登记、没有 Ready 引用/有效读取租约且不受保留保护的对象。
恢复后未知文件先隔离核对，不因“像缓存文件”而删除。缓存状态机与数据库协调器已进入实现和专项验证；
独立私有文件/锁/路径/内容校验层已实现；完整报告 pg-20260917-070338-cbe8cd86 的 Windows/Linux 各八组实际 IO、
前序服务与三库恢复均通过，源码/工具 hash 已核对。
文件/数据库协调细节及实际文件测试要求见[缓存文件边界](postgresql_cache_file_contract.md)。

录像目录 repository 已实现 recordings/recording_events，六条查询及六组 Windows 专项
pg-20260917-061459-ea532091 通过。覆盖无会话自主录像、文件版本/内容 hash 不变性、并发/序号、节点重连、
精确会话归属、设备 ACL、只读管理、去密分页及审计回滚。完整报告 pg-20260917-061716-591ca543
的两平台测试、三库恢复及源码/工具 hash 核对通过；

## 具名连接设置实施边界

具名设置是用户的偏好，不是连接描述符或访问凭据。owner 由当前登录推导，并按 client_type 隔离；
Android 使用 android，不能借 panel 或 admin_web 获取他人的设置。保存的目标仅为 Desktop(device_id)
或 CloudApplication(application_id)，不保存旧实例、运行端口、密码、host 或连接 token。
每次实际启动/访问仍重新授权、调度并取得新的资源会话；设置不能授权 observer、接管或直接指定 Render。

创建时检查当前目标访问权限，用户可以查看/删除自己已失去目标权限的设置，以免产生无法清理的孤儿条目；
更新设置需再次检查目标权限。目标和 owner 不可借更新转移；换目标新建条目。
重试身份由 owner/client/request UUID 与初始正文 hash 共同确定，拒绝同请求不同正文；更新/删除使用 revision CAS。
活跃条目每用户每终端最多 128 个，列表使用 UUID 游标、每页 1–100；删除保留幂等墓碑和追加事件，不从历史数据重建旧目标。
原始创建请求精确重试返回当前设置（不撤销后续修改），已删除条目不复活；删除原 revision 的精确重试返回墓碑。

媒体/界面选项必须有类型和范围。它们只是期望值，实际能力协商可拒绝；不能使 RDP 走视频二次编码，
也不能使只读偏好成为服务器允许第二前端的依据。
当前实现包含名称、256 Kbps–200 Mbps 期望码率、1–240 期望 FPS、音频/剪贴板/只看、最大化/分屏、
P2P 偏好、系统混音/目标应用音频偏好、24 位 RGB 背景。没有旧字段自动填充或旧客户端配置导入。
保存偏好不等于对应模式/平台已实现所有选项；产品适配层必须明确接受/拒绝不支持的选项，不能静默改用其他传输或捕获方式。
saved_connections/saved_connection_events 与八条显式 SQL 已实现；专项 pg-20260917-064532-cfcc06fc 及完整
pg-20260917-064614-34466d46 的两平台七组、单元、十一领域共享池和三库恢复通过，源码/工具 hash 已核对。
此实现不代表原 c_stream 的 HTTP/WS 或客户端调用已经切换。
