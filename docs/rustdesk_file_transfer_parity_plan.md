# RustDesk 文件传输独立进程与界面对齐计划

## 1. 目标

将 Pixels Windows 文件传输改造成与 RustDesk 桌面端一致的独立会话：用户从远程设备卡片或设备详情点击“文件传输”后，直接启动独立的文件传输进程，不要求远程控制已经连接，也不复用远控窗口、媒体通道或远控进程生命周期。

文件传输窗口在布局、信息层级、交互和操作覆盖上对齐 RustDesk 桌面文件管理器；传输协议继续使用项目已经从 RustDesk 迁移并强化过的 `px_ft_engine`，不重新引入 RustDesk 的 Flutter/Rust 运行时。

## 3. 实施前基线与差距

Pixels 已具备：

- RustDesk 语义的目录读取、递归发送、接收、覆盖确认、续传临时文件、取消、创建目录、删除、重命名和进度回调。
- `/file/transfer` 独立 WebSocket 路由以及 Relay 文件通道。
- `mode=file-transfer` 启动信封、`file_transfer_only_` SDK 参数和禁用视频的连接分支。
- `FtAsyncSession` 的独立工作线程与背压处理。

仍缺少：

- Panel 当前只会通知用户先连接远控，没有直接创建文件传输进程。
- 文件传输仍作为远控窗口里的附属浮动面板，独立模式不会自动呈现专用窗口。
- 本地侧没有完整目录控制器；当前 UI 仅能输入一个本地路径并查看远端目录。
- 缺少 RustDesk 的双栏文件浏览、路径导航、排序、多选、创建/删除/重命名、隐藏文件、传输队列、拖放以及完整确认弹窗。

## 4. 目标架构

```text
Panel 设备操作
  -> 解析设备 ID / Console 原生地址 / 已保存密码
  -> 生成一次性 file-transfer 启动信封（密码摘要不进入命令行）
  -> 启动独立 px_client.exe --native-launch-stdin 进程
      -> ClientLaunchConfig.fileTransferOnly = true
      -> 仅建立 /file/transfer 或对应 Relay 文件通道
      -> 不创建视频、音频、控制输入或远控工具栏
      -> FileTransferWindow
          -> LocalFileController
          -> RemoteFileController -> FtAsyncSession -> px_ft_engine
          -> TransferQueueModel
```

生命周期约束：

- 文件传输进程和远控进程可分别启动、分别关闭、并行存在。
- 关闭远控不得中断文件传输；关闭文件传输不得停止远控。
- Panel 退出时只回收由本次 Panel 实例创建且仍存活的子进程。
- 每个连接使用独立 stream ID、connection nonce 和文件路由绑定；迟到的断线回调不得清理替代会话。
- 启动失败、密码错误、设备离线和通道关闭必须在文件传输窗口内给出可本地化错误。

## 5. RustDesk 桌面界面一比一清单

### 5.1 窗口与主布局

- 顶部设备标签栏：文件图标、设备 ID/名称、关闭标签；结构预留同窗口多设备标签，但第一阶段每次启动仍是独立进程。
- 主体按 RustDesk 的 `3:3:2` 比例排列：本地文件区、远端文件区、传输状态区。
- 三列使用相同的 16 px 外边距和 8 px 内边距；本地与远端结构完全镜像。
- 低宽度时设置合理最小宽度并允许窗口缩放，不隐藏操作或字段。

### 5.2 本地/远端文件区

- 50×50 平台图标与“本地计算机 / 远程计算机”标题。
- 第一工具行：后退、上级目录、面包屑路径/可编辑路径、搜索/清除、刷新。
- 第二工具行：主页、新建文件夹、删除、更多，以及向对端发送/接收按钮。
- 更多菜单：显示隐藏文件、全选、取消全选。
- 文件表头：名称、修改时间、大小；支持点击排序及升降序指示。
- 文件行：驱动器/文件夹/文件图标、单击选择、Ctrl 多选、Shift 连选、双击打开目录、右键重命名、键盘首字母定位。
- 本地和远端都支持路径直接输入；Windows 根路径显示驱动器。
- 支持从资源管理器拖入远端区域上传，以及在双栏之间发送所选项。

### 5.3 传输状态区

- 空状态使用传输图标和“当前没有传输任务”。
- 每项显示方向图标、任务名、状态、百分比、速度和进度条。
- 进行中任务可取消；暂停/失败且可续传的任务可恢复；完成任务可从列表移除。
- 文件夹递归传输显示文件序号/总数及总体字节进度。

### 5.4 弹窗

- 创建文件夹、重命名、删除确认。
- 目标已存在：覆盖、跳过、覆盖全部/跳过全部；续传条件满足时提供继续传输。
- 关闭窗口且仍有任务时确认。
- 所有弹窗使用 Pixels 共享语义主题、深色蒙版和中英文键，不使用散落字符串。

## 6. 模块拆分

为避免继续扩大 `ClientSession` 和单一 UI 文件，新增模块按责任拆分：

- `client_file_transfer_window.*`：窗口级组合、三栏布局、弹窗协调。
- `client_file_browser.*`：可复用的本地/远端浏览器视图，不持有网络实现。
- `client_file_transfer_model.*`：目录、选择、排序、导航历史和传输队列状态。
- `client_local_file_system.*`：本地文件系统 RAII 适配、Windows 驱动器和已知目录。
- `ClientSession` 文件能力：远端请求、目录操作和作业命令的窄接口；网络与 UI 状态不混合。
- `PanelClientLauncher`：区分远控子进程和文件传输子进程，但共用安全标准输入信封。

## 7. 实施阶段

1. 删除 Panel 对“现有远控会话”的依赖。

3. 启动独立 `px_client` 文件模式，并用独立 session ID 管理。
4. 文件模式只建立文件通道，自动显示专用窗口；关闭不影响远控。
5. 增加启动信封和 Panel 启动行为测试。

## 8. 完成标准

- 未启动任何远控进程时，点击设备“文件传输”即可打开并完成传输。
- 任务运行期间关闭远控窗口，文件传输不掉线；反向关闭也不影响远控。
- RustDesk 桌面文件管理器当前可见的布局和操作在 Pixels 中都有对应实现。
- 本地/远端文件操作、覆盖、取消、失败、续传和审计均有自动化或节点联调证据。
- 中英文、明暗主题、普通/高端视觉效果均可用。
- `build_official/<product>/dist` 与构建产物哈希一致后才标记可验收。
