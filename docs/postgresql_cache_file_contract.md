# PostgreSQL 录像缓存：文件与数据库的一致性边界

2026-09-19，DB2-D 实施契约。录像目录、文件层、缓存协调器、节点回传和授权 HTTP Range 下载已实现并通过聚焦验证；
真实公网录制/浏览器验收及保留/驱逐管理入口尚未完成，不能据此宣称 DB2 或 DB5 完成。

## 文件层

缓存根目录独立于网页静态目录，只允许服务身份、SYSTEM/root 和受信管理员访问。显式初始化已有空目录，
写入 deployment/root UUID；启动只打开并核对已有身份，不能自动修补损坏标记或接管未知目录。
首版只验收 Windows 本地固定 NTFS 卷和 Linux 本地 ext4；不使用共享盘、FUSE、Overlay 或内存文件系统承诺相同的锁与持久性。
Linux 文件系统类型检查只能识别 ext 家族；实际发行测试记录具体挂载类型，不能把相同 magic 当作所有 ext 版本的验收证据。

每个根目录只允许一个活跃 Console 所有者。每个 blob 有共享读取锁、独占写入/清理锁；子对象持有根目录所有权，
父对象先关闭不能使仍在写入/读取的子对象失去保护。正常析构显式解锁，进程被杀后验证操作系统释放锁。
锁文件不在在线清理中删除，避免同名不同 inode/handle 导致两把独立锁。每次写入使用全新 blob UUID，
锁文件留下单次尝试标记；失败、取消、清理完成后均不复用这个 ID。

文件名只由 blob UUID 和固定后缀生成。Linux 逐级禁止符号链接，以目录 FD 定位子文件；Windows 拒绝重解析点，
持有不共享删除权限的祖先/根目录句柄。最终文件须为私有普通文件且硬链接数为 1；不能只验证字符串前缀或 basename。

数据分块有大小上限，累计长度和 SHA-256 必须与不可变源版本一致；失败后不再允许该 writer 继续提交。
文件同步完成后才发布，已存在目标绝不覆盖。Linux 使用 `renameat2(RENAME_NOREPLACE)`；不支持的文件系统报错，
不退回检查后覆盖式 rename。[Linux rename 手册](https://man7.org/linux/man-pages/man2/rename.2.html)

Windows 同目录发布不设置替换/跨卷复制标志，使用文件同步和 `MOVEFILE_WRITE_THROUGH`。
这些调用不能替代实际断电恢复验证；进程终止测试不是硬件断电保证。
[MoveFileExW](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-movefileexw)、
[FlushFileBuffers](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-flushfilebuffers)。

读取持有共享文件锁，并检查实际长度/hash；PG Ready、文件存在或大小相同都不能代替内容验证。
精确删除只处理已授权 blob 的数据/临时文件；不扫描后缀删除未知文件，不删除节点原录像。
受信管理员/服务身份能够直接修改文件，属于运维信任边界；本地锁不是对恶意管理员的防御。

## 数据库协调器

先登记每次回传尝试的 blob UUID、不可变录制版本、root UUID 和租约，再产生文件。
获取物理锁后重新检查数据库状态；统一顺序为文件锁 → 短数据库事务，不在数据库事务中做网络/整段文件 IO。
只有实际发布证明与当前任务/代际/租约、源大小/hash、root 身份均一致时，才提交 Ready 引用及事件。
文件发布后数据库提交失败，留下可对账的孤儿对象，不伪造 Ready；旧租约晚到不能替换新任务引用。

媒体访问需要当前身份以及“精确 resource-session owner”或“当前设备 ACL”之一，并使用短效读取租约；不能把拥有 blob UUID 当作授权。读租约过期或权限撤销后，
传输按既定收敛期限停止；大文件/Range 续传不绕过重新授权。读取时同时持有物理共享锁，避免数据库租约过期与正在读文件之间的清理竞争。

保留副本管理属于写管理权限；只读管理员不能触发保留/删除。已保留副本不因节点离线或源文件滚动清理自动删除。
普通 TTL/磁盘压力清理不得突破保留规则；容量被保留副本占满时拒绝新的缓存，而不是暗中解除保留。
GC 必须同时证明对象已登记、无 Ready 引用/有效读取租约且不受保留保护；实际删除完成才记账为已清理。

根目录和物理文件不在 PG 备份中。恢复/重启先核对 root 身份、当前控制代际和实际文件，再开放读取；
缺失、损坏或未知对象进入不可用/隔离状态，不能自动作为任意路径删除。
锁文件/尝试墓碑的长期离线压缩需要独立维护流程，不能在线突破单次 ID 或文件锁不删除的规则。

### 已实现的事务对象

0016/0017 全新 schema、协调器、节点工作流和产品媒体接口现已包含下列对象；不提供旧 schema 或旧 ticket 兼容：

- cache runtime 绑定物理 root UUID、当前 Console control epoch 和每次启动的新 activation UUID。
  旧 epoch/activation 不能提交任务或复活媒体租约；更换根目录不会把旧目录的 Ready 投影成新目录可用。
- recording cache entry 是 recording 的逻辑缓存/保留策略，带 revision、当前 blob 引用、最近访问和验证 activation。
  Ready 是已验证观察，播放前仍验证实际文件；重启前的验证 activation 不能直接沿用。
- blob attempt 账本保存全新 UUID、root、不可变源版本/size/hash、原始申请主体/登录、节点代际、限期 worker 租约和状态。
  活跃、已废弃但未物理清理的对象均占用预留容量；超时不直接释放磁盘预算。保留原始身份，不能用新登录替换旧任务授权。
- read lease 绑定主体/登录、blob/root、当前 activation 和短时效；事件只追加，与引用/保留/租约变更同事务。

回传申请、独占任务、续约/过期、真实发布证明、Ready 提交，以及读取/Range 所需的短租约均已实现；保留/驱逐管理 API/UI 尚待完成。
任务执行器在有界阻塞队列做文件 IO，不在 SQL gate 内等待整段 hash 或网络。每次有效续约/发布重新核对申请者权限、
节点和源版本，不能把回传能力变成长期访问令牌。目录查询与媒体数据返回分别验权。

GC 在物理独占锁内先提交不可逆的 deleting 状态及 Ready 引用解除，随后做精确文件删除，最后提交 deleted/容量释放。
不能先删文件再决定数据库对象是否仍被使用。deleting/deleted 的 blob 永不重新引用；新请求使用新 blob。
清理从未写入文件的尝试时，也持久写入单次尝试墓碑，避免迟到 worker 在清理完成后创建该 UUID 的文件。
最终容量释放必须持有删除证明及其独占锁；删除完成但事务失败时仍保留 reservation，允许对同一对象重试确认。
保留设置和清理竞争使用 entry revision CAS：清理已先提交时，旧页面的保留请求失败并刷新，不能谎称旧副本已被保留。
清理完成回执丢失可在同一登记对象上再次确认文件不存在后收敛；未知文件不参与这个幂等规则。

恢复验证使用实际打开并校验的 reader，其共享锁保持到短事务完成；新写发布证明的独占锁保持到 Ready 提交完成。
只传递脱离锁生命周期的 UUID/hash 元组，不能作为物理发布/恢复验证的证明。
