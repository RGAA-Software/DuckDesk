## 本批代码

1. Windows 发送适配新增 `WSASendMsg + UDP_SEND_MSG_SIZE`，对齐固定 Sunshine 基线的每消息 UDP 分段机制。
   同批分片等长、总量不超过 64 KiB；不支持或调用失败走现有逐包发送，成功但字节数不符时不重发该批，避免重复。
   沿用当前 pacing 的批量上限、Socket 执行线程、取消和背压；不扩大瞬时发送预算。
   音频仍走原独立批次。无全局 Socket 选项修改，无异步 Win32 借用指针。
2. `VideoReceiveQueue` 新增按流累计统计：实收数据/校验、块内重复、迟到、乱序、恢复分片、完整帧、
   预测丢失、纠正预测、最终丢失事件、不可恢复帧、格式错误；Client 每 5 秒输出各流累计值。
   重连清零，恢复分片不冒充实收；“完整帧”表示组帧完成，不等于解码或显示成功。
3. Render 记录批量实际接受包数与批量回退次数；批量/逐包成功路径共用分片间隔诊断。
4. 回归新增真实 Socket 分段/回退后的包长、内容、去重检查，以及无效输入、关闭 Socket、
   统计重置、跳帧、预测纠正检查；原上游差分、生命周期测试继续运行。

## 保留差异，不是遗漏开发

| 部分 | 冻结的 Pixels 适配 |
| --- | --- |
| 控制与鉴权 | 保留现有 WS/媒体恢复入口，不移植 RTSP、ENet、配对等产品层 |
| 音频 | 保留 20 ms Opus 与受保护长度/填充，不改成上游默认 5 ms；4＋2 矩阵与接收算法按基线 |
| 封装 | 保留 8 字节媒体外层和受保护 Pixels 视频描述符，不承诺原版产品互连 |
| pacing | 现有总码率预算、FEC/音频开销预留、最多 1 ms 迟到补偿；不照搬固定高速率常量 |
| 背压 | 4 帧/4 MiB/100 ms 有界保护及恢复规则，不允许无限排队 |
| Windows 批量适配 | 使用相同 UDP 分段消息；本批将已有等长 Packet 复制到最多 64 KiB 连续缓冲，而非上游分散缓冲组织 |

8 Mbps 总预算、1400 B 包的当前视频节奏通常每批只有一包，新增分段入口不会强行凑批或增加等待。
不能把“批量路径已实现”描述为当前 90 网络环境已提速，更不能把降码率/改 MTU 当成算法对齐。

统计约定：data/parity 计数为头字段通过初检的真实输入，包含后续判定的重复/迟到；不是恢复生成的包。
迟到含已完成块后的校验包，不等于网络丢包。重复计数仅能识别当前块内重复，不为统计另建无限历史。
不可恢复帧在已开始观察后的跳帧/块跳过时确认，不把加入前的历史编号计作丢帧；最后尚未结束的帧不能提前判丢。
最终丢失事件数与丢帧数分开，预测纠正按该块最终恢复/收齐确认。
