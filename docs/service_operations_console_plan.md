# Pixels 服务管理与运维后台计划

> 日期：2026-09-16；状态：待实施。本文规定管理职责、页面信息、状态与操作契约，不代表现有后台已经具备这些能力。
>
> 关联：[部署与升级计划](server_deployment_and_upgrade_plan.md)、[服务架构](server_refactoring_plan.md)、[交互页面原型](server_topology.html)。

## 0. 管理原则

每套官方/私有平台有一个统一的 Console 管理后台。Console、Auth、Desk（按部署范围）、Broker、Relay、节点 Service 和 Render 都有自己的列表与详情页，
共用登录、权限、状态模型、任务中心和审计。各服务不再额外开放一套面向公网的独立管理网站。
普通用户访问入口与管理员入口分开；Official/Customer 不是管理员角色，私有平台只能管理自己的服务。
管理界面不转发视频，也不提供通用远程 shell。业务准入、进程管理和操作系统权限是不同层次。

`px_auth_server` 是官方许可证签发基础设施，只在官方授权运维域登记和管理；Customer 后台仅能查看本部署许可证验证/导入状态，
不得管理官方 Auth 进程、签发任务或私钥。`px_desk_server` 按实际部署登记，提供咨询/问题/版本等现有业务，
不是私有登录或会话建立的强制依赖。未部署显示“不适用”而不是故障；同一套代码不等于每套部署必须安装全部服务。

云应用属于 Console 内的 Cloud Runtime 业务层，不属于 Broker/Relay 运维层。新增独立“云应用管理”导航：
应用目录、部署与规格、调度预览、运行实例/RDP 工作区、调度记录与队列。
详见 [云应用与多 GPU 调度设计](cloud_application_scheduling_plan.md)，网页第五页可演示负载选机和逐卡准入。
机器详情必须逐 GPU 展开，区分当前占用、未启动预约、保底预算和 requested/actual GPU，不能仅展示整机平均负载。

## 1. 谁实际管理服务

| 层次 | 负责内容 | 不承担的职责 |
|---|---|---|
| Console 管理 API / Web | 展示、权限校验、维护计划、操作预检、持久任务与审计 | 不直接执行网页传入的命令或访问 Docker socket |
| 服务自身管理接口 | 就绪、排空、配置校验/热加载、版本、会话摘要、指标 | 不把上报状态当作可任意提升权限的证明 |
| 服务端部署执行器 | 通过 SCM、systemd 或容器运行时安装、启动、停止、升级注册的 Console/Auth/Desk/Broker/Relay，限制到本运维域 | 不调度游戏，不创建另一套 Session 权威，不向私有平台开放官方签发管理 |
| 节点 px_service | 管理受其监督的 Render、代理与节点资源；执行节点排空 | 不代替 Linux 服务端部署工具，不接管未知进程 |
| OS/容器管理器 | 进程托管、限定频率的崩溃重启、资源限制与退出结果 | 不决定用户是否有权访问业务 |

部署执行器是安装套件内的窄权限模块：单机可以本机 CLI/服务，多机时采用每主机认证执行端。
执行端只接受有签名/认证的类型化任务（service_id、目标版本、任务 ID、预期代际），绑定安装时登记的服务和受保护目录。
首版无通用任意命令、任意路径、任意 PID 参数；日志和诊断包不包含登录密钥。自动重启要有退避、上限及告警，不能制造无限重启风暴。
人工设为 Stopped、维护中或 RecoveryRequired 的对象不能被业务看门狗自动启动。每个组件只能有明确的进程监督责任方，避免多套 guardian 互相拉起。
不改现有 Game Hook 的私有 Job AND 完整规范路径约束；安装进程升级与业务实例清理使用不同类型的任务。

Prometheus/Alertmanager 负责监控告警，不执行部署或业务调度；Kubernetes 是后续可选的容器部署适配，不是多机管理前提。
自营公网商业版必须有独立监控，小型私有部署可使用内置基础状态。交付边界以
[部署计划第 1.1–1.2 节](server_deployment_and_upgrade_plan.md#11-监控部署编排与业务调度分工) 为准；本节执行器不扩展成自研通用编排器。

### 1.1 Console 挂了怎么办

- 服务端套件包含本地状态/诊断/启动/回滚/恢复工具，使用 OS 管理员权限或私有管理通道，不依赖 Console 登录接口正常工作。
- 保存受保护的安装清单、签名版本、任务日志和恢复点；先检查运行状态及任务代际，不能以 Console 无响应直接重装数据库。
- 本地应急操作记录审计，Console 恢复后补报；不携带用户凭据，不开通用公网恢复端口。
- 独立监控可以报告 Console 不可达。已经打开的管理页面断流后显示数据过期，不能持续展示旧绿色状态。
- Console/Broker 恢复不代表 Relay/Render 原会话已经健康，需要分别核验控制链路、数据链路和授权。

## 2. 统一状态模型

一个绿色“在线”不足以说明服务可用。列表与详情都区分以下维度：

| 维度 | 示例 | 来源与解释 |
|---|---|---|
| 安装/进程 | 未安装、启动中、运行、停止、崩溃循环 | 部署执行器或节点监督者观察到的状态 |
| 健康 | Healthy、Degraded、Unhealthy、Unknown | 自检、依赖检查和独立探测，注明观察来源 |
| 准入 | Ready、NotReady、Draining、Maintenance | 能否接收新业务；排空中的进程可以健康但不接新业务 |
| 数据新鲜度 | Fresh、Stale、NeverSeen | 本机采样时间、平台接收时间和最后序列；超阈值显示 Unknown/Stale |
| 期望配置 | Running、Stopped、Draining、目标版本 | 管理任务记录；和实际状态差异可见，不掩盖未完成变更 |
| 业务生命周期 | Session Active/Detached、Instance Ready/Stopped 等 | 由对应业务 owner 提供，不能从进程状态猜测 |

每个记录至少包含 deployment_id、稳定 service/node/instance ID、主机标识、服务类型、OS/架构、product/distribution、
版本/build ID、进程 incarnation/owner epoch、协议范围、配置 revision、起始时间、退出原因、采样时间、接收时间与状态原因码。
状态数据携带来源与权限范围。PID 只作诊断，不能作远程操作的唯一身份。

- 可选初始采集节奏为 5 秒轻量心跳、15 秒资源汇总；具体阈值在容量测试后配置，页面显示实际值，不写死业务超时。
- 连续心跳缺失先标记 Suspect/Stale，不得把活动用户数清零或自动判定节点可升级；Confirmed Stopped 需要监督者或可靠对账证据。
- 服务器健康、管理网络可达、客户端数据路径成功分别展示；一台机器能 ping 通不代表能转发媒体。
- 依赖失败影响 readiness，但不是所有依赖失败都触发重启；避免数据库短暂不可用引发所有服务循环重启。
- 不支持的指标显示“不支持/未采集”，未知值显示“未知”，不使用 0 代替。指标窗口、单位、来源、样本数和刷新时间可见。

## 3. 后台信息架构

```text
平台总览
服务管理
  Console / Auth（仅官方运维域）/ Desk（部署启用时）/ Broker / Relay / Direct Host WebRTC端点
节点与运行实例
  机器池与接入 / 节点 Service / GPU 与容量 / Render / RDP 工作区 / 安全退役
会话与连接
  逻辑会话 / 参与者与通道 / 路径 / 失败事件
业务管理
  用户与权限 / 设备
云应用管理
  应用目录 / 部署与规格 / 调度预览 / 实例与工作区 / 调度记录与队列
维护与升级
  版本仓库与应用分发 / 小批验证与升级批次 / 排空 / 维护公告
告警与诊断
  活动告警 / 容量趋势与监控健康 / 日志与事件 / 诊断包 / 审计
平台设置
  平台身份与入口 / 证书 / 许可证 / 备份恢复 / 通知
```

首版不需要每个条目都独立页面。统一列表、详情页及任务组件可复用，但服务特有指标和保护条件不能混成无类型参数表。
所有页面中英文与主题共用状态；权限限制由后端执行，不靠隐藏按钮。示例原型与真实平台明显区分，原型不发运维请求。

### 3.1 列表与详情的公共结构

列表支持类型、主机、版本、状态、新鲜度、准入和升级批次过滤，按原因聚合故障；大列表分页，不一次拉取全部会话。
每一行可以进入详情；总览异常卡直接定位相关对象，而不是让管理员重新搜索 ID。
详情布局为：摘要与最后更新时间 → 指标趋势 → 依赖/关联对象 → 当前用户与任务 → 配置差异 → 日志/事件 → 操作历史。
带可复制 ID 和受权限保护的端点信息；密钥只显示指纹/有效期/轮换状态，禁止展示完整 secret、账号密码或 RDP 凭据。
操作区显示影响的实例、用户、剩余容量、版本窗口及阻塞原因，不只有一个无解释的“重启”按钮。

### 3.2 数据库与备份页面（DB4 前置交付）

数据库已确定为 PostgreSQL，具体备份档位与数量以 [数据库方案第 6 节](postgresql_database_migration_plan.md#6-自动备份与保留策略) 为准。
页面展示主版本/schema、可写角色、连接池、主备与归档延迟、备份计划/时区/保留、仓库容量、最后可恢复时间和恢复验证结果。
基础档默认小时 24/日 7/周 4/月 6；生产档展示全量/差异/增量依赖和连续 WAL 窗口，不能把恢复点数当裸文件删除数。
操作包含立即备份、保留锁定、受限下载、恢复预检和维护恢复任务；独立执行器提供 Console 不可用时的恢复路径。
运行账号、迁移账号、备份/恢复权限分离，页面不展示 DSN 密码、RDP 解密密钥或数据库超级用户凭据。
先完成 DB4 的最小可用页面/工具，再接入统一运维导航；不能因完整后台尚未开发而推迟数据库备份。

### 3.3 多机资源池与批量任务页面（首版）

- 机器池：展示 deployment/pool、用途、故障域/区域标签、硬件等级、总/可用/预约/未知容量及维护状态；
  节点归属变更需权限和对账，跨 deployment 不是普通移组。Relay 池展示带宽/allocation，Render 池逐 GPU 展示，不能混成通用“空闲数”。
- 接入与应用分发：认证登记、能力发现、驱动/版本核验、应用 revision/资源准备、绑定验证、Ready 各阶段独立显示；
  支持单机和有界批次任务、失败重试/取消及校验结果，不能把“已下载”显示成“可运行”。
- 批量升级：展示目标快照、先行验证批次、并发上限、最低剩余容量、失败暂停条件、待用户退出和每机回执；
  新加入池的机器不自动加入已确认批次，恢复任务不能重复执行已完成项。
- 容量趋势：展示排队/拒绝、资源瓶颈、可用应用部署、备用容量和机器准备耗时；注明监控采样窗口和预测依据，
  首版给出人工扩容建议，不提供未实现的自动采购按钮。
- 安全退役：区分关新准入、排空、停止运行时、撤销登记/凭据，以及云主机销毁；有保留工作区/本机数据/未知占用时显示阻塞。
  “退役节点”不隐含删除云主机或用户数据；已确认移除的节点禁止持旧身份重新入池。

Console 管理一个部署的多台机器，所有操作复用持久任务/权限/审计；不为每台机器创建另一套账号系统。
首版小型私有安装不必显示复杂趋势图，但机器状态和安全门禁不能省略。现有离线网页不是上述新增页面已实现的证明。

## 4. 每个服务页面的内容

服务导航补充“Auth 签发服务（仅官方授权运维域）”“Desk 业务服务（按部署启用）”；
两者接入同一库存、任务、告警和审计模型，不能只在数据库页出现。

| 页面 | 关键指标/信息 | 列表下钻与关联 | 允许的管理操作及约束 |
|---|---|---|---|
| 平台总览 | 用户可用性、服务健康/未知数、节点可调度容量、Direct/Relay 会话、告警、维护时间、证书与备份风险 | 点击异常到服务/节点/会话/任务；官方或私有平台身份固定显示 | 不提供“无条件重启全部”；创建有范围的维护计划 |
| Console | API 请求率、延迟分位、错误率、DB 延迟/连接、调度队列、Grant/outbox 积压、当前调度 owner、schema 版本 | API 错误→request/session；DB 依赖；版本副本和选主状态 | 安全配置热加载、单副本排空/升级；自我停止由独立执行器完成 |
| Auth（官方运维域） | 签发/验证成功率、拒绝原因、授权与撤销 revision、签发队列、DB/schema、证书期限、签名器可用性 | 许可证→签发任务→审计/恢复集；只显示 key ID，不展示私钥 | 关闭新签发、排空在途签发、维护升级；密钥轮换另需专属权限/复核，不随普通升级自动更换 |
| Desk（部署时启用） | API 延迟/错误、咨询/问题处理积压、版本元数据 revision、制品可达性/摘要校验、DB/schema | 发布记录→签名制品→更新任务，咨询内容按权限脱敏 | 暂停写入/发布、排空任务、配置与升级；不通过恢复旧版本记录绕过签名和安全防回滚 |
| Broker | 认证连接、端点数、建连成功/失败、连接耗时、待处理信令、Grant 同步延迟、重连率、owner epoch | Endpoint→Session→path/Relay；拒绝原因；跨 Broker 路由 | 关闭新准入、排空、证书轮换、滚动任务；旧代际不能改新状态 |
| Relay | 独立 Session 数、连接/子通道数、allocation、上下行吞吐、已用/剩余带宽预算、配对失败、限流、排空进度 | 受影响会话和 Broker；过去窗口趋势；升级替代容量 | 设置新准入/权重/限额；排空；预告维护；有会话时重启须显式中断审批/确认 |
| 节点 Service | CPU/内存/磁盘、GPU/显存/编码器占用、可调度槽位、版本、心跳、桌面/应用端口占用、运行模式 | GPU→实例→Render→用户；配置期望与实际；注册身份 | 禁止新调度、诊断、空闲升级、重新注册计划；不因报表用户数为零直接升级 |
| Render 实例 | 工作负载类型、所属节点/GPU、启动/Ready 时长、PID/创建身份、实际端点、版本、控制/观看者、采集/编码 FPS、码率和错误 | Session/路径、Game Job 归属、CEF 或 RDP 状态、最后断线宽限 | 精确停止实例需权限与影响预览；有用户不后台更新；Stopped 重复停止幂等 |
| RDP 工作区 | Workspace ID、映射用户的脱敏标识、Windows Session 身份、busy 状态、代理与传输状态、最后连接、保留策略 | 活动前端、Proxy/Render、授权与失败原因；不展示 Windows 密码 | 断开传输与销毁工作区完全分开；首版不提供普通运维一键注销/删除账号 |
| Direct Host WebRTC | 按Render实际端点展示直接协商成功/失败、首帧、音频/输入状态、候选类型、证书与可达性；不展示不存在的TURN allocation | 关联Windows/Web/适用Android消费者、资源Session、节点、Render与host/port；与Relay数据路径分开 | 诊断端点、防火墙和证书；撤销资源会话；不提供ZLM/Coturn启停或WebRTC经Relay fallback |
| 会话与路径 | 主体、目标、角色、授权版本、Session 状态、Direct/Relay/RDP、路径代际、重连轨迹、错误 | 用户→Session→Broker→Relay→节点→实例全链路 | 撤销访问/终止会话需要权限、原因与审计；断路径不默认销毁业务资源 |
| 数据/证书/许可证 | DB 状态与迁移版本、备份时间/恢复验证、剩余空间、部署证书/许可证有效期、更新信任根 | 关联受影响服务、维护/迁移任务 | 轮换/导入/验证备份；恢复属于独立维护，不向页面暴露数据库超级用户凭据 |

Relay 是透明加密转发者，不能声称知道端到端画面 FPS、用户输入或所有媒体丢包。RTT/丢包必须注明是链路观测还是端点上报；
未采集或协议不支持时留空/标记未知。Render 编码 FPS 和客户端呈现 FPS 分开，不以一端成功代替全链路成功。

### 4.1 示例告警与关联

- Relay 带宽余量不足：显示容量分母、持续时间、受影响会话数，建议扩容/限制新分配；不能建议停止整个节点。
- Broker 连接激增但会话数不变：关联重连事件和认证拒绝，区分重连风暴与新增用户。
- 节点失联：显示最后已知用户数而非 0，禁止自动判空；关联主机/管理网络故障。
- Render Ready 超时：关联启动 task、进程日志、GPU/端口和节点状态，不无限重复 Start。
- 证书即将过期、授权同步延迟、升级阻塞、备份过旧或恢复未验证：各有 owner、严重性、首次/最近发生时间和处理建议。

## 5. 操作、任务、权限和审计

### 5.1 标准操作流程

选择对象 → 获取当前权威快照 → 权限/新鲜度/版本/容量预检 → 展示影响与维护策略 → 确认 → 创建持久任务 → 执行端确认 → 状态对账。
任务状态至少包括 Queued、Preflight、WaitingForUsers、Executing、Verifying、Succeeded、Failed、Canceled、RecoveryRequired。
请求带 idempotency key、目标稳定 ID、预期 incarnation/配置 revision、操作类型、维护窗口和原因；提交时再次校验，防预检后状态变化。
API 返回 task_id，不能把 HTTP 200 当作执行成功；后端不会因浏览器关闭重复执行，也不会因为前端超时就默认取消。
取消只在仍可安全取消的阶段生效；回滚限制沿用升级计划，schema 不可回退时禁止“强制回滚”绕过数据保护。
跨服务批量任务限定并发、故障域和剩余容量，不能选择“全部”后同时排空全部 Broker/Relay/节点。

### 5.2 权限

首版预置只读观察员、运维人员、平台管理员三个角色，具体权限按能力分配，审计员可独立授予只读审计权限。
读取敏感诊断、轮换证书、恢复数据、强制中断会话与用户管理分别授权；重要操作使用重新认证/MFA和二次确认，不默认所有重启都走审批。
强制维护必须填写原因、范围和通知安排；可按客户策略增加审批，但不是所有部署的前置依赖。
操作发起人/执行身份、前后版本/配置摘要、预检结果、通知范围、失败原因、任务代际与时间写入耐久审计。
服务端执行权限、deployment 与目标归属校验，网页禁用按钮只改善体验，不构成安全边界。

### 5.3 配置管理

配置区分只读身份、可热加载、新会话生效、需要重启四类；展示当前值、期望值、revision 和未生效原因。
先校验后应用，热加载原子切换；端口冲突、证书错误或描述未签名时保留旧配置。
Relay 节点地址/证书等改动同步到发现与分配描述；不能在 UI 改一个地址就遗留旧连接描述。
凭据字段只支持替换/轮换，不从后端读回完整值；导出诊断和配置模板默认脱敏。

## 6. 状态、指标和事件如何进入后台

1. 云节点 `px_service` 主动直连所属 Console 的认证管理长连接，持续报告节点身份、资源、实例与配置；这条连接不迁往 Broker。
2. Render 通过受认证本机 IPC 报告运行事实，Service 结合本机采集和进程监督汇总；Console 按来源去重并拒绝旧 incarnation/序列覆盖新状态。
3. 后台使用分页快照 + 增量 SSE/WS；断流重连带游标，游标失效重新取快照。保留轮询作为传输选择，而非旧业务协议 fallback。
4. 心跳/图表允许采样和聚合，任务结果、撤销、维护状态与审计通过持久事件可靠同步；背压时不能丢关键操作结果。
5. 自营公网商业版交付独立 Prometheus/Alertmanager；小型私有版提供内置基础状态和有限趋势，监控套件可选，
   私有监控不上传官方。Grafana 可补充图表，Kubernetes 不作为客户首装或多机管理必需。

指标标签只使用受控维度（服务类型、实例、区域、结果类别等），不把 user_id、session_id、完整 URL 或 token 放入高基数时序标签。
会话级查询走受权限控制的明细/事件存储；记录保留时间、聚合周期和容量上限由管理员配置并在发布基线中给默认值。
趋势注明采样时间和缺口，计数器遇进程重启正确处理 reset；升级/停机窗口标注在图上。
告警支持去重、恢复、确认与限时静默，计划维护抑制预期告警但不隐藏真实状态、容量耗尽、任务失败或安全异常。
通知渠道可用平台内通知和客户配置的邮件/Webhook；私有部署默认不发送到官方，Webhook 需校验目标与权限，防内部地址滥用和秘密外泄。

### 6.1 状态生产者和接收者

| 状态 | 采集/确认者 | 接收与使用 |
|---|---|---|
| CPU、内存、磁盘、网络与每张 GPU 的能力/压力/故障 | 节点 Service 的本机采集模块 | 经管理长连接到 Console 节点库存及 Cloud Runtime 调度投影 |
| 进程启动、退出、崩溃、本地资源占用及预约执行结果 | Service 的精确进程监督与本地准入模块 | Console 实例/预约/任务台账 |
| Ready、实际图形/采集/编码 GPU、FPS、参与者、断线宽限和运行错误 | Render 经认证本机 IPC 交给 Service | Service 汇总到 Console，保留原始采样时间、来源和实例代际 |
| RDP 工作区与 Windows Session 身份、busy、代理状态 | Service 会同 RDP 运行模块核验 | Console Workspace 投影；断开代理不推断工作区销毁 |
| Endpoint 在线、Attach、路径与 allocation 状态 | Broker；Relay 提供自身 allocation/通道事实 | Broker 维护连接权威并向 Console 同步；不是机器资源调度依据的替代品 |
| Broker/Relay 自身版本、健康、负载和维护执行结果 | 各服务管理模块，进程退出由独立部署执行器确认 | 通过认证管理 API/事件上报 Console；不要求经过云节点 Service |
| Console 自身及完全停机状态 | 自检加外部监督/部署执行器 | 后台可用时展示；完全停机由独立监控和本地恢复工具报告 |
| Auth 签发/撤销、DB、签名器与维护状态 | Auth 管理模块；进程退出由官方域独立执行器确认 | 经认证 API/持久事件到官方运维 Console；不得上报密钥材料到私有后台 |
| Desk API/发布、制品验证、DB 与维护状态 | Desk 管理模块；进程退出由其所属部署执行器确认 | 到本部署 Console 的库存/任务/告警；未部署为不适用，不伪造健康 |

Service 在没有 Render、没有用户、Panel 未打开时也要连接和上报。只部署节点安装包即可形成管理链路，不能让 UI 进程承担常驻采集。
管理入口来自已认证的平台配置/发现描述，节点身份绑定 deployment/node；运行实例使用限定到本次启动身份的 IPC 权限。
本机 IPC 丢失时，即使 Service 心跳正常，也必须把对应 Render 指标/Ready 事实标记过期或未知，禁止把旧值重新打上新时间。
Service 自身也可能故障，Console 接收时间与独立监督用于识别失联；自报健康不是唯一证据。

### 6.2 上报时效、可靠性和命令结果

- 心跳与资源汇总使用第 2 节的可配置采样节奏；预约接受/拒绝、Ready、退出、GPU 故障、维护门禁和任务结果立即推送。
- 每条报告携带 node_id、Service incarnation、连接 generation、序列、采样/接收时间及相关 instance/reservation/task ID；
  GPU 数据包含 inventory revision。旧报告不能覆盖新代际，时钟偏差不能把旧采样变为新鲜数据。
- Console 的资源预约在下发 Start 前已经记账，不等待下一次负载上报；Service 仍以本地资源和维护互锁做最后准入。
- 关键结果先耐久记录、待 Console 确认后回收，断线重传采用至少一次投递与幂等去重；连接写入成功不等于命令执行成功。
- 普通指标可聚合，关键事件/回执不可静默丢弃。积压、磁盘满或无法保证关键结果记录时告警并停止新的有副作用准入，
  不靠无界内存缓存，也不为清空队列擅自终止已有用户；安全停止仍须保留可对账结果。
- 浏览器仅从 Console 读取经过权限过滤的状态；前端 SSE/WS 或轮询既不是节点心跳，也不承担资源预约权威。

### 6.3 管理断线与重连对账

管理状态依次区分 Connecting、Syncing、Ready、Disconnected/Stale；这里 Ready 只表示管理同步完成，
实际新业务准入还要通过资源、应用部署、授权和维护门禁。建立 Socket 或收到一次心跳不能直接把节点恢复为可调度。

1. Console 确认管理断线后立即暂停该节点的新调度；静默网络故障按新鲜度阈值处理。Service 检测断线也关闭新业务准入。
   在失联检测窗口内仍依赖带代际的持久预约、本地互锁和到期检查，不承诺瞬时察觉断网。
2. 保留活动实例、启动中和未决预约的最后已知占用并标记未知，不清零、不触发空闲升级，也不自动在另一台机器重复启动。
   断线前已接受的任务按原授权/任务契约执行并记录结果，不能将“收不到回执”视为失败后另起一份。
3. Service 带退避和抖动重新认证；Console 校验 deployment、node、incarnation 和当前控制 owner，拒绝旧代际命令。
   DB0–DB5 至 P4 为单活动 Console，P5 升级双实例也只有一个有效的节点命令 owner；新 owner 接管必须 fencing，
   不能让两条旧/新连接同时发有效 Start。单实例重启仍检查旧代际，PG 事务不能代替节点侧 fencing。
4. 在 Syncing 阶段同步完整机器/GPU/实例/工作区、预约和未决任务快照；快照携带序列水位并接续其后的增量，
   防止同步期间发生的启动或退出丢失。序列缺口或日志截断重新取快照，不能仅凭最后一条心跳重建状态。
5. Console 期望/预约与 Service 实际结果逐项对账；超时、租约到期、未知进程或实际 GPU 不符进入待核查/隔离，
   未证明安全回收的占用继续保留。Service 重启后的进程核验仍遵守既有所有权约束，不按名称、PID 或端口收养替代实例。
6. 对账完成、关键指标新鲜且其他门禁通过后才恢复新调度；仍在维护的节点不得被重连逻辑自动开放。

管理链路中断本身不要求终止已有媒体连接；继续服务仍受原有授权、撤销有效边界、故障与 Render 断线宽限约束。
授权失联按部署计划第 5.3 节的服务端租约收敛；页面显示到期时间/同步水位，不能将失联授权显示为永久有效。
不能把这条管理链路断线当作“最后一个用户退出”。RDP Windows 会话、账号、Profile 和工作区应用不因它被注销或删除。

### 6.4 独立监控、发现与容量边界

监控与业务状态走两条用途不同的链路：Service → Console 的认证管理报告支撑调度/对账，
Prometheus 采集服务/exporter 的指标支撑历史趋势与告警。PG 中的业务事务/预约、节点最终准入和授权租约仍是各自权威。
不能通过一条监控查询取得“空闲”后直接发 Start，也不把全部高频指标写入永久业务审计表。

1. 自营部署提供版本固定的采集配置、告警规则和 Alertmanager 通知配置，覆盖 Console/Auth/Desk（按运维域）、
   Broker/Relay、Service/Render、PG/备份和采集链路本身；Grafana 为可选图表层，不提供绕过 Console 的运维写操作。
2. Prometheus/告警进程与 Console 独立托管，自营公网至少将监控放在不同于主 Console 的主机故障域，
   通过受限服务指标和独立端到端探测发现故障，不能只采集 Console 转发的“自己健康”。
   监控失效也要有独立心跳/外部通知检查，通知路径不能唯一依赖已经故障的 Console。
3. 采集目标从已认证服务库存生成有版本的发现清单，监控保留最后有效配置；新节点入池/退役同步增加/撤销，
   Console 不可用不应清空目标。指标端点仅走私有管理网络或受认证加密通道，不为抓取 GPU 数据开放无认证公网管理端口。
4. 不能被直接抓取的节点可经受控采集出口上送，或导出 Service 管理报告的指标投影；这种投影仍依赖上报链路，
   必须保留原采样时间、报告年龄和失联标识，禁止每次抓取把旧值变成新鲜值；另行监控采集出口本身。
5. 采样频率、标签基数、磁盘/保留窗口、查询并发在 P0 给出配置基线，P7 按实际规模压测；规模增长时先限制标签和聚合，
   必要时按池/区域分片采集，长期存储与监控 HA 另行验证，不承诺单 Prometheus 无限容量。用户/会话明细仍走受限业务查询。
6. 监控故障只使历史/告警能力降级，不主动终止业务；管理报告过期或授权失效仍执行既有门禁。
   反过来，Prometheus 显示健康不能覆盖 Service 管理失联、预约未知或 Render IPC 失效。

管理面扩容验收还要覆盖连接数、背压、分页/游标、按池批量聚合、关键结果优先、有界任务队列、重连退避和恢复对账耗时。
公布经验证的节点/指标/任务容量；超过基线先限流并告警，不能靠增加无 owner 协调的 Console 进程处理。

## 7. 故障处理体验

页面明确区分无权限、从未采集、当前查询失败、历史数据过期、真实服务故障和计划维护。
后台断流时保留最后快照并显示采集时间，关键实时数值改为未知/最后已知；新鲜度不足的排空完成/升级激活操作被阻止。
任务后端在真正执行前重新取权威状态，UI 恢复不绕过维护门禁。其他服务故障仍允许读取已有任务和审计记录。
诊断入口打包版本/配置摘要、脱敏日志和相关事件，展示包大小、范围与有效期；不抓取用户屏幕或导出 Windows 凭据作为默认诊断。
单 Relay 维护公告由 Console/Broker 保持可查询；Console 故障时使用已下发通知和有界重连，本地恢复工具仍可用。

## 8. 与现有项目的衔接及交付顺序

当前仓库已有 `web/px_console/src/views/ResourcesView.vue`、`ConnectionMonitor.vue`、`AppsView.vue`、`EventView.vue`、
`SecurityInternal.vue` 和用户/设备管理页面；路由已区分管理端与 `/user` 用户端，适合作为统一入口。
现有连接监控有 Service/Panel 列表和 Session 事件，也有周期轮询；这些不等于完整 Broker/Relay 服务库存或升级任务中心。
重构应复用当前业务 API 和可维护组件，在新协议基线内迁移；不重复建一套后台，也不借本任务改造无关页面。

| 阶段 | 本专项交付 |
|---|---|
| P0 | 服务/资源池 ID、状态来源/新鲜度、指标/发现 schema、操作与批次协议、角色页面；冻结采样/保留/标签预算及告警基线 |
| DB0–DB5 | PostgreSQL 基线和故障语义、DB4 最小数据库/备份页面及独立恢复工具；先于新服务管理能力 |
| DB-HA | 主备/协调多数、入口、复制/归档状态与切换审计；公网/私有 HA 商业发布门槛 |
| P1/P2 | Console 统一导航、多机/资源池库存、状态投影、角色、任务审计基础、只读列表/详情 |
| P3 | Auth/Desk（所属运维域）、Broker/Relay/节点/Render 心跳与指标，服务发现、多机容量状态、Session 关联，接入独立监控 |
| P4 | 将 DB4 独立备份/恢复执行能力纳入本地部署执行器体系，补 Console/Auth/Desk 应急恢复、基础告警、私有离线后台和诊断 |
| P5/P6 | 应用分发、按池小批/分批升级、排空、安全退役、公告/回滚与最低剩余容量门禁 |
| P7 | 多 Render/多 Relay、权限/竞态/规模验收；独立监控与告警送达、容量上限、手册和恢复演练 |
| P8 | 云厂商自动扩缩容、Console 多活、跨地区调度和可选 Kubernetes 部署适配；不推迟首版资源池管理 |

新增网页原型的“服务管理后台”仅用于审阅页面结构和字段，所有状态/指标是示例；任何按钮均不得连到真实启停或升级接口。

## 9. 验收清单

- Console/Auth/Desk/Broker/Relay/Service/Render 列表能按部署范围下钻，Session、节点、告警和任务可以相互定位。
- Auth/Desk 的健康、未知/失联、DB 故障、在途任务排空、升级失败和恢复均验收；停 Auth 不伪称现有私有登录必须失败。
- Customer 直接调用 API 也不能操作官方 Auth/读取签发私钥；Desk 未部署为不适用，恢复版本数据不绕过制品签名/安全序列。
- 健康但 Draining、不健康但进程运行、无指标、心跳过期分别展示，不能一律写在线/离线。
- 心跳晚到/乱序/进程重启/时间偏差不会覆盖新的状态；节点失联不会把用户数变 0 或触发空闲升级。
- Panel 关闭、零 Render 时 Service 仍直接向 Console 上报机器/逐 GPU 状态；Broker 信令在线不能掩盖管理连接失联。
- Service 在线但 Render IPC 断开时实例状态过期；Console 断线、Service 重启、快照与增量并发及控制 owner 切换均能安全对账。
- 回执丢失、日志截断、租约过期与采集背压不会造成双实例或未知占用被释放；Syncing 或维护中禁止恢复新调度。
- 只读用户通过直接 API 调用也无法执行操作；跨 deployment、旧 incarnation、无权限及重复操作均正确处理。
- 预检后用户重新进入、容量变化、任务冲突时执行端拒绝或重新预检，不按旧快照继续停止服务。
- 浏览器关闭或 WS 断开不丢任务，刷新可恢复进度；不把客户端取消请求等同取消已执行任务。
- Console 完全停止时可以通过本地工具诊断/安全恢复，不依赖数据库超级用户密码暴露给浏览器。
- 单 Relay 维护公告、无备用容量、长期用户、升级失败与回滚受限有完整界面和原因提示。
- 缺少 GPU 指标、RDP 只保留工作区或 Native/WebRTC 协议不同，页面不伪造 FPS/丢包或把工作区当已销毁。
- 大列表、指标突增、背压、日志脱敏、明暗主题、中英文、窄屏、键盘导航及错误/空状态通过验收。
- Console 进程/主机故障仍收到独立告警；监控停止不误停业务，监控链路自身失联可被发现，私有数据不发官方。
- 发现清单重复/乱序、Console 不可用、旧指标投影、退役节点重连均正确处理；监控健康不能绕过业务新鲜度门禁。
- 多机同时接入/重连、应用下载或验证失败、升级批次失败、备用容量不足均有界处理；不出现无限任务或全池同时下线。
- 有持久工作区/本机存档/未知占用时缩容阻塞；维护/退役 API 不隐含云主机销毁或数据删除权限。
