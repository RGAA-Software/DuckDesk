# 服务商业化改造：逐步开发与测试门禁

> 2026-09-16 · 待实施的验收规范。本文不表示数据库迁移、服务改造或以下测试已经通过。
> 实施顺序来自[部署与升级计划](server_deployment_and_upgrade_plan.md)，数据库规则来自[PostgreSQL 计划](postgresql_database_migration_plan.md)。
> 本文负责把每个阶段转换为可执行、可判定、有证据的开发步骤；需求冲突先修订契约，再修改实现和测试。

2026-09-16 最新决定：旧环境没有有效数据，直接新建 PostgreSQL。取消旧源库盘点、TTL 快照、数据转换/导入及旧库回退测试；SQL migrations 仅用于新库建表和未来正式 schema 升级。

同日补充：按全新系统开发，不做旧协议、配置、ID、接口、字段或旧客户端兼容。预期来自新产品契约；旧测试只复用业务场景，过期预期必须重写。代码检查与拒绝测试同时确认无旧格式适配、默认猜测、双轨和 fallback。

## 1. 每一步如何判定正确

“合理合法”在本计划中指符合已确定的产品规则、授权边界、数据约束、协议和生命周期约定。自动化通过不是法律合规证明。

每项改变必须建立 `需求/决策 → 不变量 → 用例 ID → 测试入口 → 结果/证据 → 阶段门禁` 的对应关系。
预期结果先来自产品契约和独立测试数据，再验证实现；不能直接把实现当前返回的内容录成“正确答案”。
基线发现的既有缺陷登记为缺陷，不能为了保持旧行为而把越权、静默写失败或旧目标兜底固化为正确行为。

| 检查维度 | 具体判定 |
|---|---|
| 行为 | 正常操作有明确结果，拒绝和超时也有明确结果；界面、接口、数据库和真实进程相互一致 |
| 权限 | 按部署、用户、角色和资源校验；被拒绝请求不产生持久写入、命令或可用访问通道 |
| 数据 | 唯一、引用、字段范围、过期和事务正确；成功响应对应已提交结果，未知结果可按幂等键查询 |
| 生命周期 | 重复、乱序、并发、断线和重启不产生第二实例、旧命令执行、错误清理或工作区丢失 |
| 可恢复 | 备份实际恢复、恢复后业务核对通过；切回有明确数据边界，不把旧二进制能启动视为安全回滚 |

## 2. 测试环境与证据边界

| 环境 | 建设内容 | 可以证明 | 不能据此宣称 |
|---|---|---|---|
| E0 纯逻辑 | Rust/前端单元与契约测试、可控时钟 | 策略、边界、序列化、状态转换 | 真数据库事务、真实网络、GPU 行为 |
| E1 本机数据库 | Docker PostgreSQL 18，固定补丁/digest；隔离测试库、账号、卷；实际 migrations | SQL、约束、锁、建表/升级和隔离恢复 | 独立主机容灾、Windows SCM 备份服务 |
| E2 本机集成 | 真实 Console/Auth/Desk、E1 数据库、模拟节点；另接 Windows 原生 Service/Render/Client | HTTP/WS、outbox 和真实 Windows 运行链路 | 公网 NAT、异机故障域、Android 真机 |
| E3 部署隔离 | 官方测试域 O、独立私有 A/B；不同部署身份、凭据、数据库和端口 | 同名账号/ID 的平台隔离、离线私有部署 | 同宿主机容器的物理容灾 |
| E4 公网与硬件 | 当前配置的公网测试节点、真实多 Render/多 Relay、单机多 GPU；随后 Android 真机 | 跨机路径、容量、实际 GPU 落点、客户端行为 | 未实际测过的 GPU 型号、规模或客户端 |
| E5 独立故障域 | 数据库 HA 计划要求的独立主机、独立备份仓库 | 故障切换、旧主隔离、异机恢复及 RPO/RTO | 同地域方案的跨地域容灾 |

E1 的 PostgreSQL 数据使用独立 named volume；业务库与破坏性测试库分离。磁盘满测试使用受限测试卷，不能填满宿主系统盘。
E2 按模块可先用模拟节点稳定触发乱序和崩溃点，但阶段出口必须补真实 Service/Render，模拟成功不替代原生验证。
Windows 图形、驱动、Job 和 RDP Session 验证在原生环境执行。Android 在 Windows 对应链路通过后执行。
O/A/B 在发行隔离实现前可预置独立测试环境，但不能提前标记 P1 全链路通过。

所有有副作用入口使用显式测试配置：目标地址、deployment、制品清单和允许操作的资源。不给公网目标设脚本默认值。
本机 PG 端口只绑定 loopback；公网端点消费当前节点配置与连接描述，不探测旧局域网地址或退役端口。
每次运行生成 run_id，登记库、卷、服务/进程身份和实体 ID。清理仅限登记资源，失败证据先保留；禁止全局 prune、泛化 kill 或默认清空数据库。
故障注入只针对隔离测试资源。已有授权覆盖的测试按登记范围执行，无需每一步重复人工确认；新的真实数据销毁或业务中断不由测试脚本推定授权。

## 3. 每个开发小步的固定流程

1. 写清本步改变、前置门禁、必须保持的不变量及失败恢复方式，选定用例 ID 和测试环境。
2. 先准备输入与预期：合法、非法、边界、重复；涉及共享状态再加并发和中断。用例以业务行为断言，不绑定内部函数形状。
3. 对新增行为确认测试能在缺少实现时失败；对既有行为记录实际基线。至少给关键拒绝断言一个反例，防止请求未送达或断言未执行造成假通过。
4. 做一个可独立验证的实现增量，执行受影响模块检查、真实 PG 集成测试及相关契约回归。
5. 对副作用注入精确故障点，检查接口结果、持久状态、节点执行次数和恢复结果；修复后重跑失败用例及关联回归。
6. 生成报告，评估本步门禁；通过后再接依赖它的下一步。可独立的设计工作可继续，不能借此跳过失败的集成前置门禁。

通过状态仅用 `PASS / FAIL / BLOCKED / NOT_RUN / N/A`。缺数据库、设备、凭据或目标资源是 BLOCKED；未运行是 NOT_RUN。
N/A 必须说明产品/部署范围及依据，例如私有部署不包含官方签发库；不能用 N/A 隐藏首版必需能力。
必测缺项、零用例、被 ignore/skip、超时、清理越界或结果采集失败均不能通过阶段门禁。
允许自动重试的业务场景本身需要断言；不能反复重跑整套测试直到绿色并丢弃失败记录。偶现竞态未定位前仍阻塞相关门禁。

合入增量要求本步相关测试通过，并显式记录尚未交付的集成能力；阶段交付要求该阶段全部必测通过。
不要求每次小修改跑整套硬件验收，也不能用小步通过冒充阶段完成。文档变更仅检查内容与链接。

## 4. 第一轮开工的八个小步（必要 P0、DB0、DB1）

| 顺序/用例组 | 实现或准备 | 具体测试与预期 | 出口证据 |
|---|---|---|---|
| 01 / BASE | 新模型与合成功能基线 | 对照 Console/Auth/Desk 领域设计新字段/约束/索引；定义登录注册、ACL、应用三模式、签名及版本接口的合成输入和预期 | 新模型、需求用例矩阵和已知缺陷；不访问旧数据，也不以旧源库缺失阻塞 |
| 02 / ENV | Compose、版本锁定和测试运行器 | 干净环境启动；重启后合成数据保留；两次独立运行无串库/端口/卷冲突；错误 DSN 和目标身份拒绝；缺 DB 不跳过测试 | image digest、版本、资源清单、非零失败退出码和结果报告 |
| 03 / PRIV | 三库和最小权限角色 | 每个运行账号只访问本服务允许表；跨库/跨服务、DDL、提权拒绝；独立 migration owner 可执行限定迁移；凭据不出现在日志报告 | 三服务角色权限矩阵及实际允许/拒绝查询结果 |
| 04 / SCHEMA | 第一版 migrations 与独立迁移入口 | 空库升级；重复执行无额外变化；两迁移者竞争仅一执行；中途杀进程恢复；checksum 被修改拒绝；锁超时可解释；不支持 schema 的服务 NotReady | schema 版本/摘要、迁移锁与失败恢复记录；运行进程不会偷偷建表 |
| 05 / POOL | SQLx/PgPool、配置和错误传播 | 错凭据、断库、池耗尽、超时均有界失败；就绪检查区分进程存活与业务可用；恢复后新请求成功；未知提交结果不谎报成功或直接重放 | 错误契约、最长超时配置、断库前后状态和持久结果 |
| 06 / QUERY | 最小纵向查询/事务及测试数据 | 先选择一个当前业务实体，走真实 repository 的写/读/更新/回滚；SQL 查询检查对应实际 schema；独立读连接验证提交结果；唯一冲突必须真失败 | 可重复测试、SQLx 查询检查、runtime 与 migration 权限分离证据 |
| 07 / RESTORE-SMOKE | 仅合成数据的手动备份恢复 | 将样本备份恢复到另一个新库；核对字段、约束、关系和查询结果；损坏备份拒绝；原库不被覆盖 | 可恢复样本与清单；只算恢复冒烟，不计作 DB4 自动备份完成 |
| 08 / DB1-EXIT | 串联以上入口 | 在全新隔离环境重建；执行 02–07；Windows 原生服务和计划支持的 Linux 服务入口分别连接 PG 验证；复核与 DB0 契约一致 | DB1 报告，缺失运行平台或必测仍标 BLOCKED |

DB0 为新 PostgreSQL 三库未来整体恢复给出清单、写入屏障和对账样例；Windows 备份执行器给出服务身份/ACL/目录/任务契约。
这些是新系统的恢复设计，DB4 再验实际执行器，不需要旧 Mongo 环境或历史数据。

第一轮新入口建议统一置于 `scripts/server_validation/`，Compose/fixture 位于独立测试目录；具体文件名在实现时冻结。
目前已新增 `scripts/server_validation/postgres.ps1`，提供 Up/Test/TestSuite/PrepareQueries/Down/Status，使用方法见[本机环境说明](../deploy/development/postgres/README.md)。
日常增量先执行 `TestSuite -Suite <领域>`，通过后执行 `Test -Linux` 回归；专项报告明确 FOCUSED-ONLY，不包含浏览器/恢复或全平台验收。
运行器已覆盖多领域 SQL/事务故障注入，但尚未覆盖本表全部产品门禁；真实节点、客户端及备份执行器仍须分别接通。
Console 已有身份/用户组 repository 小步及[字段、事务与验收映射](postgresql_identity_contract.md)，包括真实 PG 事务故障、SQLx 在线/离线查询检查和 `-Linux` 原生 WSL 测试。它们不是 Console 产品 API/完整资源 ACL 验收。
SQL 集成测试使用真实 PostgreSQL，不用 SQLite 或 mock 代替 PG 约束/锁；纯业务策略可继续使用轻量单元测试。

## 5. 数据库替换阶段门禁

| 门禁 | 开发顺序 | 必测输入、动作与预期 |
|---|---|---|
| DB2-A 身份 | users → login_sessions → group/ACL | 并发注册同规范化用户名只有一条记录；空值、大小写、Unicode 按冻结规则判定；过期/撤销立即在授权查询生效，不能等定时物理删除；跨用户 ID/伪造 owner 拒绝；DB 故障无假登录成功 |
| DB2-B 目录与设备 | devices → applications → deployments | 按 BASE 冻结的策略测试角色×资源×动作；目录不可见、直接猜 ID、启动和恢复入口一致；时间/时区、u64 边界、唯一冲突、外键、分页跨页重复遗漏均验证；重启后配置保留 |
| DB2-C 实例与命令 | instance/task → idempotency → outbox | 最后一个槽的竞争只有一个合法占用；相同 request_id/正文返回同结果，不同正文拒绝；不同主体同 request_id 不共享结果；提交前故障无命令，提交后回执丢失可对账，重复投递仅一次实际启动；旧代际回执不覆盖新状态 |
| DB2-D 工作区与记录 | workspace/secrets → session/events/records | 新 ID/AAD 持久化及恢复后可解密；另一前端 busy；断线/停止/恢复不注销会话或删应用；查询数据持久且权限正确；PG 备份中的在线快照恢复为待确认，未知占用不被释放 |
| DB2-EXIT Console | 接通全部 repository 后整体切换 | 无 Mongo 运行 fallback；登录注册、ACL、Game Hook/WebView/RDP、会话和记录全链路；真实 Service 的次数/进程身份与数据库一致；相关回归全通过 |
| DB3 Auth/Desk | 分别实现新存储，再检查共享依赖 | 固定合成签名向量验证；许可证撤销不复活；Desk 咨询/问题/版本接口正确；各自 DB 故障、重启、未决任务恢复；产品依赖树与部署配置无 Mongo |
| DB4 备份/恢复 | 基础执行器 → 保留 → 恢复 → 生产 WAL | 见第 7 节；Windows SCM 与 Linux 执行器分别真实运行；Console 停机仍能备份、告警、离线恢复；基础和生产档分别出报告 |
| DB5 全新部署 | 空库初始化 → 正常 API 创建业务 → 完整验收 | 缺字段/重复/孤儿被拒绝；初始化中断安全；新用户登录、ACL、RDP 新工作区解密与签名验证；新节点登记/对账；Windows 后 Android 回归 |

DB2-A 至 DB2-D 每步均运行前面受影响用例，不能只测新增表。阶段内可开发尚未接入产品的 PG repository，最终统一接入；不建设双写或运行时双后端。
DB5 使用新建用户、部署凭据和合成应用数据，不承接旧开发库的登录状态或工作区记录。
后续正式 PostgreSQL 升级才测试“开放写入前切回”和“开放写入后恢复/前向修复”，不建设回到 Mongo 的流程。

## 6. 并发与崩溃测试如何落地

DB1 先建立测试时钟和故障注入边界；DB2 再接入业务注入点。测试入口受测试构建/隔离运行配置约束，不暴露生产远程故障控制接口。
测试用 barrier/明确事件等待制造竞争，不用固定 sleep 猜测执行顺序；每次记录随机种子、超时和实际触发位置。

| 用例 | 执行方式 | 独立断言 |
|---|---|---|
| RACE-01 最后一槽 | 两个独立测试进程，各建 PG 连接，同时提交；再以 20 个请求重复争用 | 每轮至多一个占用；允许有界冲突/无容量，禁止两份实际启动；连接数和失败数可核对 |
| CRASH-01 提交前 | 数据写入尚未 commit 时终止测试服务 | 重启后无半事务、无已发送 Start；请求可按契约重试 |
| CRASH-02 提交后发送前 | commit 已确认、outbox 未发送时终止 | 重启可取回同一命令；不创建第二实例 |
| CRASH-03 执行后确认前 | 节点已启动，丢弃回执，再重启/重投 | 节点事实、实例代际和幂等结果对账；物理运行实例总数为一，不误停止原实例 |
| ORDER-01 乱序 | 新 revision/停止已生效后投递旧 Ready/Start/Stop | 旧回执拒绝；Stopped 再 Stop 成功；复用 PID/端口的新资源不受影响 |
| AUTH-01 拒绝无副作用 | 未授权主体直接调用隐藏接口、篡改目标或重放另一主体请求 | 明确拒绝，持久授权/实例/outbox 数量不增加，真实访问失败 |
| LIFE-01 C++ 回调 | 对变更模块测试排队回调后析构、派发中注销、回调内关闭、反复 start/stop | 无悬空访问、死锁、循环持有和残留订阅；使用可用的内存/句柄诊断留证 |

每个确定性竞态至少跑一次精确排序，并执行固定种子 100 轮扰动（作为初始开发门槛，不作为容量承诺）。任一违反不变量即失败。
并发测试中的两个进程不代表支持两个活动 Console；DB0–DB5 至 P4 的部署约束仍为单活动实例。

## 7. 备份恢复必须怎样验

基础档先用可控时钟模拟至少 7 个月调度，验证小时 24、日 7、周 4、月 6、升级前 5 和手动 30 天策略。
同一备份被多档引用时只有最后引用过期才清理；锁定、正在恢复和最后有效恢复集均受保护。失败备份不占成功名额。
再执行真实定时任务、重叠任务、跨周期重启和实际恢复；模拟时间通过不替代 SCM/执行器实测。

| 用例组 | 必测内容 | 完成判定 |
|---|---|---|
| BK-SCHED | Console 停机、执行器被杀、错过周期、时区切换、任务超过周期 | 独立执行，互斥且不重复堆积；补一次漏跑，半成品不成功；任务与告警可离线查询 |
| BK-FAIL | 上传中断、凭据失效、备份目录 ACL 拒绝、受限卷满、hash 损坏 | 明确失败，不删最后有效恢复点；告警实际送达且脱敏 |
| BK-RESTORE | 全新隔离机器/库，合成数据备份期间持续写入，随后实际 pg_restore | 恢复点边界内数据/约束/业务一致；记录备份耗时、实际恢复耗时和丢失窗口；无向原节点发命令 |
| BK-SET | 三库缺一、不同水位、Auth 签发后未同步、Desk 元数据缺制品 | 对账阻止开放；私有未部署成员有可核对的 N/A；齐备后才可声明完整恢复集 |
| BK-AUTH | 撤销后恢复旧备份、缺密钥/外部水位、旧控制端回归 | 旧凭据/Grant/命令不得重新获得访问；证据不足保持 RecoveryRequired；RDP Session 保留 |
| BK-PITR | 生产档持续写入，模拟误删，按明确时间点恢复；故意移除测试副本的一段 WAL | 恢复到目标点并核对业务；缺 WAL 不冒称成功；测量最后可恢复点滞后，目标按数据库计划为不超过 5 分钟 |
| BK-UPGRADE | schema 中断、锁超时、非事务步骤失败、引擎补丁及声明支持的大版本演练 | 版本/数据一致；支持窗口内可切回，否则明确前向恢复；不能破坏性 down migration |

自动备份状态 Created、Verified、OffsiteVerified、RestoreTested 分开断言。只有 hash 一致不得计为 RestoreTested。
公开生产档的异机/PITR 验收和私有基础档的逻辑恢复分别出结论，不能相互替代。

## 8. 数据库之后的逐阶段门禁

| 阶段 | 接入顺序及必测 | 通过条件 |
|---|---|---|
| P0 协议剩余项 | 参考代码可复现性、部署信任根、发现/认证/Grant/维护/升级状态机、错误样例、时序边界 | DB 前先冻结必要数据安全契约；进入 P1/P2/P3 前补齐其协议前置，缺参考须明确替代设计 |
| P1 发行隔离 | 四产品×Official/Customer；O/A/B 使用相同账号名与资源 ID；换平台时延迟旧响应；用 URL/IP/别名指向 O；跨发行更新 | Customer 在发凭据前拒绝官方身份；证书/签名真实验证；缓存和身份不串；构建框架完成与在线全链路完成分开，后者等待 P2/P3 |
| P2 授权 | 重复/冲突 request_id、撤销/续期竞态、Console 失联、时钟回拨、旧备份恢复 | 持久授权与 outbox 正确；普通/严格策略从最后权威续期起最晚 310/40 秒停止访问；重连/重启/重放不续命；先测模拟接收端，P3 再验实际 Direct/Relay |
| P3 连接与调度 | 先 Broker/Relay 身份和路径，再节点管理/资源池/逐 GPU 准入；健康过期、维护、未就绪应用、GPU 显存不足、CPU/内存/带宽不足、最后一槽竞争 | 先硬过滤再评分；超限或 Unknown 拒绝，实际 GPU 与预约一致；管理失联后完成对账才恢复准入；RDP owner 固定；Direct/Relay 权限端到端执行 |
| P3 多机 | 两个以上 Render/Relay 真实节点，新节点登记/资源就绪、池迁移、单节点掉线 | 只将符合条件的新请求放到新容量；不自动热迁移活动游戏或已有工作区；报告明确节点、GPU 和网络规模 |
| P4 私有交付 | 干净 Windows/Linux 安装、同发行覆盖/升级/卸载、拒绝冲突产品服务及手动安装服务；断开所有公网出站；失败安装恢复 | 完整产品制品验证；私有注册/登录/许可/会话/备份可运行；按明确数据保留策略卸载；不依赖官方在线签发；单机预览可交付 |
| P5 控制面升级 | Windows A/B 精确服务名/端口/目录；迁移锁、单 owner 交接、旧命令晚到、每个切流点崩溃、失败切回 | schema 窗口与权限正确；旧 owner 被隔离；量测信令中断、媒体停顿、重复输入、文件 hash；分别声明恢复能力 |
| P5 Relay 维护 | 冗余时关闭新 allocation 并排空，已有重连/文件子通道继续；单 Relay 预告维护、公告遗漏、维护超时 | 不承诺现存 Socket 迁移；维护跨过 Render 断线宽限时 Game Hook/WebView 原实例可结束且明确告知；RDP 工作区保留；Direct 不被主动断开 |
| P6 节点/客户端升级 | 预下载、users>0、未决预约/启动/重连宽限/受保护实例逐一阻塞；Start 与 Draining 竞争；小批失败/剩余容量不足；Windows 覆盖、Android 同签名覆盖 | 不提前停进程；失败暂停后续批次；Job 外进程安全；用户数据和 RDP 会话保留；错误签名/发行拒绝；Android 安装/重启按系统流程 |
| P7 运维/商业验收 | Console/Auth/Desk/Broker/Relay/Service/备份执行器逐一停机、失联、DB 故障与升级失败；权限、维护和清理门禁；Console 停机时独立告警 | 状态来源/新鲜度可信；未知不显示健康；告警真实送达；后台中英文/主题、错误态通过；全部前置报告与真实容量/故障演练齐备 |
| DB-HA | 按 E5 拓扑测主机断电、分区、同步副本丢失、协调少数派、入口故障和旧主回归 | 单写权威、已确认提交与业务结果核对；写入恢复目标 120 秒实测；公网商业/私有 HA 发布前必过 |

每个阶段先明确会受影响的旧用例并重跑；P7 还需运行完整发行/模式/连接矩阵。P8 的多活、Kubernetes、活动 Relay 迁移不计入首版已实现能力。
多 GPU 调度同时验证“请求的 GPU”和应用/采集/编码实际落点；仅编码器选卡成功不算绑定通过。无法验证的模式按调度计划限制可用池。
运维后台及拓扑模型必须覆盖只读角色、状态过期、目标 Unknown 三个操作门禁，以及升级 users>0 阻塞。
调度模型分别测试 CPU、内存、网络及 GPU 压力、显存、编码槽、实例槽七个容量边界：恰好可容纳时允许，单项超限时拒绝；未知值另测拒绝。
页面中的预算数字仅为模型 fixture，不能变成生产硬编码；真实服务使用版本化规格与可分配预算执行相同边界测试。
模型通过仅代表页面模型，不替代以上后端和真实节点用例。

## 9. 客户端真实功能验收

每个声明支持的组合登记 `产品/发行 × 部署 × 运行模式 × 连接路径 × 操作`，不支持的组合说明理由，不能静默省略。
RDP 按当前专项仅验证 Windows 客户端与其专用承载，不因矩阵要求引入未授权的 RDP Android/Relay 路径。

Windows 先验证登录注册、应用列表、启动、实际画面/音频/输入、停止与恢复、权限收缩；文件传输以两端 SHA-256 验证，不仅看进度到 100%。
Game Hook 同名/同路径但不在本次 Job 的进程必须存活；WebView 的窗口/输入/音频验证与实际功能声明对应；RDP 对比断线前后 Session/用户/Profile/应用身份。
Windows 制品运行路径来自当前交付清单，验证构建产物与实际运行副本的 SHA-256；不能硬编码过期 output 路径或用开发 EXE 替代产品验收。

随后 Android 真机检查注册/登录、独立顶层云应用、android 身份、CloudApplication 目标 app/instance/descriptor/owner、后台恢复和覆盖安装。
缺字段、跨用户/部署和旧描述必须拒绝，禁止 device/account 兜底。仅 HTTP 脚本发出 android 字段不能证明 APK 页面或实际目标类型正确。
UI/媒体验收报告须附制品 hash、设备信息和实际交互证据；截图只证明可见画面，音频/输入/恢复另有结果断言。

## 11. 报告、运行频率与停止条件

每次报告至少包含：run_id、时间、Git revision 和未提交补丁摘要、构建/包 SHA-256、数据库/schema/工具版本、脱敏环境身份、
用例 ID 与需求引用、命令/配置摘要、预期/实际结果、断言数、故障点/种子、耗时、脱敏日志与状态快照、清理结果、缺陷和后续阻塞项。
报告不得包含 token、密码、签发私钥、RDP 密文解密材料或未脱敏用户数据。测试数据用合成 fixture；必要的真实数据副本受原数据权限保护。
二进制 hash、测试配置或关键依赖改变后，受影响的旧报告不能直接沿用；报告保留旧结果，新增复测证据。

| 时机 | 必须运行 |
|---|---|
| 每个实现增量 | 相关格式/编译检查、策略/契约测试；涉及 SQL 跑 PG；涉及副作用跑对应故障/并发组 |
| 合入集成分支 | 受影响服务及共享消费者检查、PG 干净库迁移、关键回归；缺环境阻塞必需检查 |
| 阶段出口 | 本阶段全部必测＋受影响前序回归＋必要真实环境验证，提交报告索引和未完成项 |
| schema/引擎重大升级及发布 | 恢复演练、版本窗和回退边界、发布矩阵、制品核验；完整发布构建按已授权交付执行 |
| 集成基线建立后每日自动任务 | 固定规模并发/故障组、备份恢复冒烟；失败关联责任变更，不以无人查看日志代替告警 |
| 商业发布 P7 | 先冻结节点/用户/请求率/数据量与 p95/p99、错误率、队列、资源预算；阶梯压测到声明容量，至少 24 小时稳定性并注入计划故障 |

性能门槛必须在正式测量前版本化，报告展示基线/目标/实际；没有目标只记测量，不能写“性能达标”。
24 小时是初始稳定性门槛，不证明长期无泄漏；检查内存、句柄、连接池、队列与 WAL/磁盘增长趋势，按异常延长定位。
备份月度异机恢复按数据库计划执行。测试基础设施不可用、性能目标未冻结或硬件不足，阻塞对应门禁，不影响独立小步继续开发。

阶段门禁由用例结果和证据决定，不要求用户逐个手动批准测试。每轮交付汇报：本次通过哪些门禁、哪些未执行/失败、下一步具体入口。
用户得到的“完成”必须对应声明范围内全部必测通过；测试计划、代码写完、构建成功和 Docker 可用分别是不同状态。
