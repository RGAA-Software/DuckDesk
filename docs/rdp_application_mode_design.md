## 0. 最新决策：RDP 原生代理与会话保留

用户后续明确：GammaRay 负责前期用户创建、授权、连接链路、代理转发、辅助操作和 RDP 会话管理；
保留 Windows RDP 原生编码，客户端复用自有 Qt demo 的 RDP 图形解码、合成和显示，不走二次视频编码。
同一个 GammaRay 客户端程序内部增加 RDP 处理路径；game-hook/webview 的现有视频路径及不新建用户的行为保持不变。
RDP 数据包含压缩图形、surface/增量状态与反馈，不能当作单一普通 H.264 视频轨直接交给旧播放器。
Native 的承载适配、可靠性/顺序/背压与通道隔离须验证；Web 端 RDP 解码/显示需要单独方案，不能宣称自动兼容原 WebRTC 播放器。

### 0.0 已冻结的账号、自动准入和传输边界

- 持久工作区唯一键为 `(rdp_app_id, node_id)`，一个 RDP 应用在一个节点对应一个 Windows 账号。
  不加入访问者 user_id，也不因匿名访问、访问者变化或客户端重连创建新账号。
  不同访问者先后进入同一个应用/节点时，会使用同一个持久桌面及文件；隔离边界在工作区之间，不是访问者之间。
- 用户允许未登录访问。px_console 根据应用发布/访问策略自动准入并下发短期连接票据，不增加登录或授权确认弹窗。
  票据绑定工作区、节点、实例代次和连接占用；匿名访问也有独立连接标识及恢复凭据，不能把所有游客当作同一个连接者。
  是否登录不改变单工作区单连接规则；第二个访问者收到忙状态，不抢占或旁观已有会话。
- 私有部署的 px_console 负责生成、加密保存 Windows 账号密码，维护账号版本、工作区映射和备份恢复。
  节点 Service 负责幂等创建标准用户、核对 SID/权限、应用凭证版本和执行 Render 生命周期，不另建独立密码权威来源。
  首次创建失败、密码轮换失败、数据库与密钥恢复不一致均返回明确状态，不能为重试删除已有账号/profile。
- 首版采用已验证的 Windows 原生 SSPI 认证路径。console 自动向经准入的客户端及远端提供所需凭证，客户端连接期间仅在内存持有。
  无账号输入、无再次授权确认；不承诺持有本机进程控制权的访问者无法提取该凭证。Windows 账号权限和入口访问控制必须限制在目标工作区。
  不落盘、不记日志、不放生产命令行；测试 demo 的进程环境注入不作为产品长期秘密传递接口。
- 复用现有 WebSocket 连接和消息封装，新增类型明确的 RDP 二进制负载；不再评估其他传输协议，也不要求另开一条 WS。
  路径为 `Client FreeRDP ↔ 现有 WebSocket ↔ Render 受控 proxy ↔ 节点本机 Windows RDP`。
  TCP 提供存活连接内可靠、有序的字节传递；新增适配只需正确处理消息分片、部分读写、流量控制、队列上限和关闭。
  不给 RDP 增加重复的网络重传协议，不丢弃任意 RDP 字节，也不把断线后的旧缓冲灌入新协议连接。
  控制消息与 RDP 数据共用连接时，采用有界分块和调度限制积压；不能承诺消除 TCP 本身的队头阻塞。
- 证书信任由部署和后台流程预配置，正式连接不弹确认框；测试的 `--cert-ignore` 不转为默认关闭校验。
  proxy 由 Render 作为受控子进程管理，端点仅允许受控桥接访问；不把测试用的裸 `13389` 入口直接作为产品入口。
- 测试仍用现有 `10.0.0.90`，RDP 登录使用已有非 Administrator 测试账号（当前为 `usbtest2`），不接管管理员桌面。
  创建账号等管理动作由既有受权服务执行，不等同于用管理员账号登录 RDP；不顺带重启系统或注销无关会话。
- 实测证据见 [2026-09-08 proxy 验证记录](rdp_proxy_validation_20260908.md)。TCP 直连 proxy 已通过；
  接下来的验证对象是新增 WebSocket/RDP 适配及产品生命周期，不是重新论证 TCP 可靠性。

### 0.1 连接可以关闭，账号与 Windows 会话不主动注销

2026-09-08 用户进一步澄清：“我们的render等可以关闭，但是windows账号，会话不做主动注销就行，下次快速就连上了。”
这取代此前对“连接一直开着”的误解：不要求 Render、FreeRDP 协议端点或后端 RDP 连接常驻。
用户随后明确：Render 仍沿用现有客户端离开后的超时退出逻辑，不为 RDP 新增常驻或立即退出策略。
RDP 工作区按单个活跃客户端设计；该客户端离开后等待既有宽限期，期间经授权重新连接则取消本次退出，超时仍无人连接才退出。
具体超时与接入点以现有适用路径为准，不新增 RDP 专用时间参数，也不改变其他模式行为。
源码参考：`src/px_render/rd_app.cpp` 的 game-hook 断连分支已有 5 秒宽限、连接检查及 generation 校验；
同处 webview 分支仅延迟停用画面，不能据此声称所有现有模式都已使用同一退出路径，RDP 接入仍待实现。

| 事件 | 默认行为 |
|---|---|
| 工作区首次显式启动 | 创建/复用授权账号与会话，按需启动 Render/代理并建立 RDP 连接 |
| GammaRay 客户端关闭、离开工作区或网络断开 | 唯一活跃客户端离开后沿用既有超时退出流程，超时仍无人则停止 Render/代理并关闭其 RDP 连接；不注销 Windows 会话、不删除账号/profile、不清理会话内应用 |
| 宽限期内客户端重新连接 | 取消旧退出任务，继续使用仍存活的 Render；防止过期回调关闭已恢复的连接 |
| 长时间无人连接 | Render 按既有超时退出；仅无键鼠输入不等于客户端离开，不另设空闲注销或账号/profile 删除策略 |
| 用户重新进入 | 重新授权，按需启动 Render/代理并建立新的 RDP 连接，优先接回该账号原有会话；不盲目新建用户或重复启动应用 |
| 访问票据过期或权限撤销 | 阻止失效访问者继续收发数据和输入，不因此注销工作区；匿名访问同样经过自动准入，不能靠换成游客绕过撤销 |
| 后端 RDP 连接异常 | 活跃访问期间可按重连策略恢复；主动关闭后不后台无限重连，失败不触发 logoff、删账号或盲目创建替代会话 |
| 宿主服务/系统重启 | 不承诺原会话及应用状态永不丢失；下次访问核对账号、Session 与实例身份，不强制无人使用时自动建立连接 |
| 明确请求结束/销毁工作区 | 作为独立、受权且需明确操作的管理流程；不能由关闭窗口、普通断连或默认清理隐式触发 |

这里要求保留的是账号、profile 及未被注销的 Windows 登录会话，不是保留旧 socket 或旧 RDP 图形解码状态。
普通停止只清理 GammaRay 所属的连接/代理资源，不能调用会话 logoff 或按用户/EXE 扫杀会话内应用。
新连接须通过 RDS 重新协商和同步图形状态；原会话仍存在且重连策略允许时恢复原桌面。
若原会话已因系统重启、管理员或用户主动注销等原因不存在，应明确回报并按启动策略处理，不能宣称原应用已恢复。
快速重连是验收目标，不承诺固定延迟；账号映射、RDS 会话复用策略及真实重连耗时需要验证。

用户指出 RDP 的单连接差异：新模式按“一个工作区/目标会话，同一时刻一个活跃客户端”设计，
不套用多观看者广播。一个客户端可使用多个协议/辅助通道，不能把底层 socket 数量当作使用者数量。
这是工作区级连接约束，不是整台 Windows Server 只能一个用户；也不能把“同一账号”与“同一会话”无条件等同。
RDS 提供限制每用户单一会话的策略，启用时该用户的断开会话可在下次登录时重新接入；禁用时可允许同账号多个会话。
来源：[微软单会话策略](https://learn.microsoft.com/en-us/windows/client-management/mdm/policy-csp-admx-terminalserver#ts_singlesession)。
该策略不替代 GammaRay 的准入控制。用户已确认：第二个客户端进入已占用工作区时返回“正在使用”，不要依赖 RDP 登录抢占；
首版不提供自动抢占；以后若提供显式接管须单独决定。不同工作区不受同一个全局连接锁限制。
Windows 的 shadow 另有查看/控制他人会话能力，不属于本模式首版多客户端能力：
[微软 shadow 文档](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/shadow)。

### 0.2 代理边界与会话保留

撤销此前“必须服务端常驻协议运行时”的推导。客户端复用 demo 的完整 FreeRDP 协议与显示，
Render 管理已验证的 FreeRDP proxy，外层使用第 0.0 节确定的现有 WebSocket。结束访问时两段 RDP 连接均可关闭。
认证与秘密分工按第 0.0 节执行，不再把服务端独占 Windows 凭证作为首版门槛，也不承诺客户端完全接触不到密码。
保留 RDP 原生编码，不恢复 Render 解码后重编码方案，不维持无人使用的 RDP 活跃连接。

部署时须核查 Windows/RDS 的空闲、活动连接、断开会话时限及达到时限后的处理，避免系统策略自动结束会话；
这里只记录部署要求，没有修改本机或远端策略。微软列出了相关会话时限策略：
[ADMX_TerminalServer](https://learn.microsoft.com/en-us/windows/client-management/mdm/policy-csp-admx-terminalserver)。
不绕过组织强制策略或许可限制；存在冲突时明确报告，不能承诺绝对永不掉线。

### 0.3 下一步与验收边界

独立代理已验证 AVC444v2 桌面及断开后回到原会话；下一步实现现有 WebSocket 的 RDP 字节流适配和产品闭环。
自有 demo 已增加自动凭证启动支持，具体迁入代码仍需满足项目所有权/异步安全规范；不能把 demo 实测当作 GammaRay 已集成。
每次验证不超过 10 分钟：覆盖首次启动、前端与 Render 退出、再次进入、权限撤销、短时故障恢复与 A/B 实例隔离。
检查停止后 Render/代理无残留，同时 Windows 账号、会话及测试应用仍在；重连核对原会话与应用状态，避免创建第二个会话。
补测宽限期内重连取消退出、超时后重启 Render 接回原会话、同工作区并发准入只成功一个、重复连接不抢占，
以及旧连接退出/超时回调不释放新连接占用、不影响新连接；不同账号工作区可独立访问，既有模式多客户端行为不变。
不得把测试结束的默认清理实现为注销用户或删除持久工作区；需销毁的临时测试实例须单独明确范围。
短时验证只证明对应路径，不作为长期会话保留稳定性证据；不擅自增加超长测试。

## 1. 模式定义（早期记录，以第 0 节为准）

内部暂定名称 `app_mode=rdp`，最终标识、UI 名称和协议字段尚未实现。三种应用模式平行调度，
共用实例管理、访问授权和对外媒体服务；媒体来源及输入终点按模式明确区分。

| 模式 | 内容来源 | 输入终点 | Windows 用户 |
|---|---|---|---|
| game-hook | 游戏 Hook 画面 | 目标游戏的既有输入通道 | 现有用户环境，不新建用户 |
| webview | CEF 离屏渲染 | CEF 页面输入 | 现有用户环境，不新建用户 |
| rdp（新增） | FreeRDP 接收、解码和合成的会话画面 | FreeRDP → 目标 Windows RDP Session | 按隔离策略创建/复用专属标准用户 |

现有 desktop 保持主机桌面采集。新增 RDP 模式不加载 DDA/GDI/Hook 作为画面来源，
也不在断开后回退成主机桌面采集或主机 SendInput。“不做 GDI 桌面采集”不意味着不能使用
FreeRDP 自身的 GDI 图形合成器；后者处理协议画面，与调用 Windows 桌面抓屏不同。

本轮目标是本机 Windows Server 的独立用户桌面，不自动扩展为普通用户可任意指定地址、凭证的通用 RDP 跳板。
企业员工/不可信外部租户的信任模型仍待确定；标准用户 Session 隔离不等同于虚拟机隔离。

## 2. 协议终止与处理链路

```text
Console 调度与授权
       ↓
Service：账号 / SID / Windows Session / RDP 实例生命周期
       ↓
RDP 模式 Render + FreeRDP 运行时（宿主侧受管进程）
       ↕ 本机 RDP 连接
Windows RDS：专属用户桌面与应用

视频：RDS 图形更新 → FreeRDP 解码/合成 → 项目帧接口 → 编码 → 现有 Native/Web 通道
输入：现有客户端 → 实例授权 → FreeRDP 输入接口 → 目标 RDP Session
音频：目标 RDP 音频通道 → 受控内存后端 → 项目音频编码/传输
```

FreeRDP 在宿主侧终止 RDP；现有客户端继续使用项目协议。Native 使用既定 UDP+FEC 媒体和 WS/WSS 控制/文件，
Web 使用现有 WebRTC。完整的 RDP 客户端能力不代表能原样把 RDP 字节流交给现有媒体解码器。
若以后让终端直接说 RDP，将涉及不同的客户端、能力路由和授权设计，不作为本次改造的隐含范围。

目标用户 Session 不需要另起 Render 做视频采集。RDP 运行时所在进程的用户身份、Session 0 或专用宿主 Session 的可行性，
以及硬件编解码能力必须实测后决定；没有 Qt 窗口不等于已证明可在服务环境运行。
文件等辅助能力可以评估受限用户代理，但不能由此重新引入重复桌面采集。

## 3. FreeRDP 接入点与修改范围

已核实的依据：

- [FreeRDP 3.26.0 客户端示例](https://github.com/FreeRDP/FreeRDP/blob/3.26.0/client/Sample/tf_freerdp.c)
  展示连接生命周期、画面更新及 resize 回调。
- `D:/dolit/rdp/src/RdpSession.cpp:1734` 的 `onEndPaint` 从 FreeRDP framebuffer 与脏矩形发布画面；
  `onDesktopResize` 处理缓冲尺寸变化，`sendMouseEvent` 等负责输入。
- `src/px_render/webview/webview_runtime.h` 和 `rd_app.cpp::StartWebView` 已有视频、音频、光标、首帧与失败回调接入。
  借鉴这些明确能力，但新增独立 RDP runtime，不把 CEF 类型或 QWidget 混入 RDP 核心。
- FreeRDP 输入入口见 [input.h](https://github.com/FreeRDP/FreeRDP/blob/3.26.0/include/freerdp/input.h)，
  图形回调见 [update.h](https://github.com/FreeRDP/FreeRDP/blob/3.26.0/include/freerdp/update.h)。

第一阶段使用公开 API 验证正确性，CPU framebuffer 是可验证基线，不预先承诺性能。
实现优先复用自有 Qt 客户端已有的协议线程、重连、图形/光标、输入和剪贴板处理，不从上游样例重复起步。
必须解耦 Qt 窗口消费确认、交互式认证和宿主设备后端；已有实现与尚待验收项见上述功能盘点。
只有确认公共接口无法输出所需 GPU 资源或存在具体缺陷时，才评估维护最小 FreeRDP 补丁。
补丁应有固定上游版本、单独测试、维护说明与升级策略；本轮没有修改只读参考源码或加入第三方生产依赖。

收到图形数据需要持续处理协议、状态和确认，但处理不等于一定显示本地窗口。
官方示例演示了 `FreeRDP_DeactivateClientDecoding`，它不能直接用在需要输出解码画面的首版中；
必须保留必要解码与合成。原来的 Suppress Output 保活优化不适用于活跃的画面来源。

## 4. 视频正确性与性能

### 4.1 首版按解码、合成、重编码设计

RDP 图形可能包含绘制命令、位图、多个 surface、区域更新和 AVC420/AVC444。H.264 能力协商不代表输出就是
完整桌面、单视频轨、可直接交给现有客户端的码流。FreeRDP 的 `libfreerdp/gdi/gfx.c` 可见 AVC 解码、surface 映射与拷贝实现。

首版采用：RDP 更新 → FreeRDP 正确解码/合成 → 完整桌面状态 → GammaRay 视频帧 → 编码。
减少 GPU/CPU 拷贝是后续优化；压缩码流直通是另一项需证明可行的能力，不宣称已经免转码。
与早期方案相比，取消目标会话的屏幕采集，但承担 RDP 图形解码与再编码；性能和质量需对比。

### 4.2 帧与队列约束

- 完整维护画面状态，应用所有必要的有序图形增量；不能在解码合成前任意丢弃脏矩形或依赖前序状态的更新。
- 合成后向编码器使用有界、优先最新状态的帧队列；编码拥塞不无限积帧，也不阻塞 FreeRDP 协议事件泵。
- EndPaint/GFX 更新次数不是完整桌面视频 fps。使用帧时间戳、动态内容序号和合成完成状态计量有效帧。
- 异步编码不得借用会被下一轮 FreeRDP 写入的 framebuffer；采用受控拷贝/缓冲池或有同步与所有权的 GPU 纹理。
- resize、多屏和重连推进图形代次，旧缓冲、旧光标与旧输入坐标作废；编码器重新配置后再发布新画面。
- 光标可能独立于 framebuffer，需接入现有光标消息或明确合成策略，避免漏光标或双光标。
- 静态桌面不要求不断产生新图形更新；可保留最新帧供新连接首帧使用，但不将重复发送计入有效 60fps。

### 4.3 60fps 的新验收链路

`DWMFRAMEINTERVAL=15` 是 RDP 60fps 上限依据，不保证实际 fps：
[微软 KB 2885213](https://learn.microsoft.com/en-us/troubleshoot/windows-server/remote/frame-rate-limited-to-30-fps)。
新路线要测量 RDS 有效更新、FreeRDP 解码/合成、色彩转换/纹理传递、项目编码和终端呈现全过程。
RDP 上游有损编码再转码可能影响文字和图像质量；AVC444、码率、色彩与多次编码损耗需要内容对照。
良好的 GPU 不自动解决 CPU 图形合成、内存复制、驱动后端或多用户编码容量问题。

活跃时不使用 Suppress Output，避免关闭唯一画面来源。无人连接时是否暂停 RDP 显示更新属于后续空闲策略，
恢复时必须有完整可用画面并验证延迟。RDP 断开后不能继续显示旧图并宣称会话实时正常。

## 5. 输入与虚拟通道

| 能力 | 新模式设计 | 第一版状态 |
|---|---|---|
| 键鼠、文本 | 控制租约验证后，通过 FreeRDP 发往目标 Session | 核心必做，覆盖扫描码、布局、Unicode、坐标和按键释放 |
| 光标 | 处理 RDP pointer 形状、缓存、热点和位置语义 | 核心必做 |
| 系统音频 | 接收 RDP 音频，在内存后端送入项目音频链路 | 核心验证；不先播放到宿主再做 loopback 采集 |
| 文本剪贴板 | 经实例策略桥接 cliprdr 与项目剪贴板消息 | 需适配；不得自动绑定宿主全局剪贴板 |
| 文件与文件剪贴板 | 评估 RDP 通道或受限目标用户代理，映射现有操作语义 | 待选型；磁盘重定向不等于现有 FT 已接通 |
| 麦克风/语音 | 定义 audin 与既有双向语音的映射、权限和终点 | 待验证，不能等同于已完成既有语音功能 |
| 多屏/分辨率 | RDP 显示协商/控制与项目显示模型转换 | 分阶段支持；不得直接改变宿主显示器作为替代 |
| USB/打印机/手柄等 | 显式能力和通道适配 | 默认不启用未验证功能 |

每个通道都绑定实例及授权主体；RDP 功能完整不等于自动继承项目全部能力。
不能直接注册会访问宿主剪贴板、扬声器、磁盘或设备的默认后端。
失败、切换控制者、重连和停止必须正确释放该实例的输入状态，拒绝旧 generation 的排队输入。

## 6. 账号、实例与授权

- Service 负责专属标准用户、SID、profile、RDS 登录策略及清理；不能复制参考项目创建管理员用户的做法。
- `RdpInstance` 关联企业主体、实例 ID、账号/工作区引用、Windows SID/Session/登录标识、运行时代次及独立端点。
  用户不能凭自行提交的 Session ID、主机地址或用户名获得访问权。
- 账号与实例分别管理：断开客户端、关闭 RDP 连接、注销 Windows Session、删除用户/profile 是不同操作。
- 建议同一工作区只允许一个主动 RDP 桥接实例；多观看者由实例内授权能力处理，不能用重复 RDP 登录争夺同一会话。
- 输入和图形目标通过同一受管 RDP 连接绑定；票据校验、撤销和审计仍在 GammaRay 边界执行。
- 密码不放命令行或日志；不向客户端暴露 Windows 登录凭证。证书身份、认证方式和秘密传递机制需部署验证。
- RDP 运行时无需 SYSTEM 权限的部分使用低权限进程；Service 特权接口保持小型、类型明确、按实例校验。
- 同机用户、应用及 loopback 请求不自动可信。RDS 部署与 CAL 条件仍按组织实际环境核对。
- game-hook/webview 不新建用户，不接入 RDP 登录/注销；现有 Stop 和按 EXE 路径清理不得误伤新模式。

## 7. 实现阶段与短时测试

| 阶段 | 交付重点 | 验收 |
|---|---|---|
| R0 协议原型 | 从自有 Qt 客户端复用协议处理，画面/resize/光标/输入接入非 GUI 输出 | 不依赖 paintGL 消费确认，不启动桌面采集，正确显示、交互、断开和停止 |
| R1 模式接入 | app mode、实例调度、Ready、媒体与输入适配 | game-hook/webview 行为不变，Native/Web 使用现有通道 |
| R2 多用户管理 | 标准用户、Session、凭证与每实例进程所有权 | A/B 双实例画面、输入、恢复与停止互不干扰 |
| R3 数据能力 | 音频、剪贴板和文件策略桥接 | 能力逐项映射，未支持项明确不可用，无宿主数据串入 |
| R4 性能与交付 | 1080p60、双用户容量、必要时最小 FreeRDP 补丁 | 报告有效帧率、延迟、画质和资源；未测项不作承诺 |

每次实际测试最长 10 分钟，清理计入。建议 1 分钟连接/首帧、2 分钟单用户动态内容、2 分钟输入/音频/resize、
2 分钟双用户、2 分钟故障恢复/清理，余下 1 分钟为硬超时余量；能力不齐则明确缩小覆盖，不模拟通过。
核查没有调用桌面采集路径、没有宿主 SendInput/剪贴板回退、没有影响其他用户进程。
覆盖进程退出、队列未排空时销毁、派发中注销、回调触发停止、重复启停、图形缓冲被重用及各初始化失败点。

项目自有 C++ 按智能指针/RAII、确定性初始化和弱引用回调规范实现；第三方 ABI 边界适配必须审查，
不能照搬参考客户端裸指针或 `[this]` 异步捕获。遵守聚焦构建、dist 同步和 SHA-256 交付要求。
